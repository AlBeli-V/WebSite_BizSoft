# competitive-data — хранилище контура конкурентной разведки

Orphan-ветка: общего предка с `main` нет, случайное слияние невозможно.
Код контура живёт в `main` (`competitive-intelligence/`), сюда пишутся только
машинные данные. Обмен — через `competitive-intelligence/storage/data_sync_ci.sh`
(`pull` / `push "<сообщение>"`), напрямую коммитить сюда не нужно.

Заведена 31.08.2026 по образцу ветки `seo-data` базового SEO-контура.

## Структура

| Путь | Что лежит |
|---|---|
| `data/competitive/raw/` | сырые ответы источников как есть, по дате |
| `data/competitive/processed/` | нормализованные срезы выдачи (одна строка — запрос × регион × ПС) |
| `data/competitive/history/` | дневные ряды показателей, append-only |
| `data/competitive/snapshots/` | канонические снимки дня — единственный источник цифр для письма и отчёта |
| `data/competitive/competitors/` | реестр конкурентов: категория, B2B Confidence, evidence-URL, история переоценок |
| `data/competitive/decisions/` | Decision Memory: статусы рекомендаций, append-only |
| `data/competitive/ledger/` | журналы расхода API по месяцам, append-only (hard cap) |
| `reports/competitive/` | сгенерированные письма и deep report |
| `reports/competitive/archive/` | неизменяемые снимки отчёта по датам |

## Правила

1. **История не перезаписывается.** Файлы истории и журналы — только дозапись.
2. **Все timestamp — с таймзоной**, время контура московское (UTC+3).
3. **NO DATA никогда не превращается в ноль.** Недоступный источник пишется
   как ошибка в поле `error`, а не как нулевое значение: иначе сбой доступа
   читается как обвал видимости (выученный урок базового контура).
4. **Журнал расхода пишется до результата вызова**, а не после: повторный
   запуск в тот же день не должен удваивать закупку.
5. Маркеры отправки писем (`reports/competitive/last-mailed.txt`) правит
   только почтовый workflow — `data_sync_ci.sh push` их не трогает.
