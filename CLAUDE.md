# Правила проекта biz-soft.pro

## Регулярное правило: новые страницы → sitemap → индексация

После добавления новых страниц сайта (лендинги в разделе «Производители»
`/vendors/*` и продуктовые страницы `/product/*`) обязательно:

1. **Sitemap.** Проверить, что новые URL попали в `/sitemap.xml`.
   Sitemap динамический (SSR из Directus, `src/pages/sitemap.xml.ts`):
   товары и вендоры из БД подхватываются автоматически, но новые
   **статические/bespoke-страницы** нужно вручную добавить в `STATIC_ROUTES`.
   Товары с `noindex` и sku из `productNoindex()` (плагины JB-PLG-*, личные
   лицензии *-IND) в sitemap не попадают — их не индексируем.
2. **Принудительная индексация.** Запросить переобход новых URL в
   Яндекс.Вебмастере через workflow `ops-yandex-recrawl` (вход `urls` —
   список URL через запятую; квота 150 URL/сутки). Результат — комментарий
   в журнал-issue #22.

## Каталог и привязки

- Directus — единственный источник товаров; вендор товара — точное значение
  поля `vendor` (сверять с `src/data/vendors.ts`, поле `vendor` записи).
- На bespoke-страницах (`vendors/openai|figma|zoom|jetbrains.astro`) НЕ
  фильтровать товары по префиксу sku: часть товаров живёт под
  «интеграционными» sku (INT-AI-CHATGPT, INT-DESIGN-FIGMA). Ключи меты и
  порядка карточек — slug ИЛИ sku.
- Живую выгрузку каталога (vendor/name/slug/sku/price) даёт workflow
  `ops-export-products` (комментарий в issue #22). Он же коммитит
  машиночитаемый снимок `data/catalog-snapshot.json` в ветку запуска.
- Прайс-лист для Яндекс Бизнеса — SSR-маршрут `/yandex-business.xml`
  (правила отбора и полей: `src/lib/yml-feed.ts`, см. `docs/yandex-business-feed.md`).
  Ссылку в Яндекс Бизнес даём на этот URL — файл не перезаливаем.

## Доступ к прод-серверу

Прямой сетевой доступ сессии к сайту закрыт. Все проверки и операции — через
ops-* workflows (GitHub Actions → SSH), результаты — в issue #22. Деплой —
только через deploy.yml при пуше в main.

## Часовой пояс: письма и расписания — по Москве

Установлено руководителем 21.08.2026. Действует во всех ветках и сессиях.

Любое время, названное в задаче без указания пояса («в 10:00», «утром»,
«к вечеру»), означает **московское время (UTC+3, без перехода на летнее)**.
Это касается писем на почту, отчётов, напоминаний и расписаний.

- Планируя запуск, переводить в UTC вычитанием трёх часов: 10:00 МСК = 07:00 UTC.
- В cron GitHub Actions и в Routines время задаётся в UTC — писать уже
  пересчитанное значение и оставлять рядом комментарий с московским.
- Бишкек (UTC+6) по умолчанию НЕ использовать, даже если так было заведено
  в ранее созданных расписаниях: новые и изменяемые — по Москве.

## Язык общения: только русский

Установлено руководителем 21.08.2026. Действует во всех ветках и сессиях.

Весь текст, который видит руководитель, — на русском языке: ответы в чате,
**рассуждения по ходу исполнения**, сообщения коммитов, заголовки и описания
PR, комментарии в коде, тексты писем и отчётов.

Английский допустим только там, где он является частью технической записи и
переводу не подлежит: имена файлов, идентификаторы, ключи API, команды,
названия полей и коллекций, цитаты из ответов внешних сервисов.
