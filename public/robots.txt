# Агенты перечислены одной группой намеренно. По стандарту robots.txt робот
# выбирает ОДНУ подходящую группу и применяет её целиком, а не складывает со
# группой «*». Пока у Googlebot, YandexBot и ИИ-краулеров стояли собственные
# группы с единственной строкой «Allow: /», запреты ниже на них не
# распространялись вовсе: служебные разделы были открыты ровно тем роботам,
# ради которых файл и писался (разбор индексации 18.09.2026).

User-agent: Amazonbot
Allow: /
Disallow: /admin
Disallow: /api
Disallow: /cart
Disallow: /checkout
Disallow: /search
# /consent из запретов снят 16.09.2026: страница отдаёт 301 на постоянный
# адрес /legal/personal-data-consent, а закрытый в robots адрес краулер не
# запрашивает вовсе — переадресация не обрабатывается, и старый URL остаётся
# в индексе. Правовые документы (/legal/*) открыты: они должны находиться.
# Страница отписки закрыта: она открывается по одноразовой ссылке из письма.
Disallow: /unsubscribe
# Типовые документы: открываются только по прямой ссылке из письма, в
# индексе им делать нечего (решение 15.09.2026).
Disallow: /documents/

# Метки переходов и рекламные идентификаторы не меняют содержимое страницы.
# Без этой директивы Яндекс заводит на каждую метку отдельный адрес: к
# 15.09.2026 в индексе оказались пять копий страниц вендоров с «?etext=»,
# четыре из них кабинет пометил NOT_CANONICAL, пятая осталась в выдаче
# дублем, а 22.09.2026 письмо Вебмастера принесло те же дубли по блогу и
# вендорам. Canonical на странице уже без параметров (src/lib/seo.ts), но
# Clean-param снимает дубль до обхода, а не после. Директива межсекционная:
# её читает Яндекс, остальные роботы игнорируют.
#
# Перечень ведётся в data/seo/url-params.json (там же примечание к каждой
# метке и список значащих параметров, которым сюда нельзя). Блок ниже
# собирает «pnpm robots:sync», сторожит tests/robots.test.ts.
# clean-param:begin — собирает scripts/seo/robots-sync.mjs, руками не править
