# BIZSoft Marketing Data Dictionary

**Назначение.** Единственное определение каждого маркетингового показателя:
что он значит, откуда берётся, по какой формуле считается, в каких границах
применим и какие выводы по нему делать нельзя.

**Правило.** Показатель с одним названием имеет одну формулу во всей системе.
Если формул две — это дефект (см. MKT-011), а не два показателя.

**Дата:** 21.08.2026. Пометка ⚠ означает, что показатель сегодня вычисляется,
но его значение искажено — ссылка на находку приведена.

## Поисковая видимость

### `yandex.impressions` — показы в Яндексе

| | |
|---|---|
| **Бизнес-смысл** | Сколько раз страницы сайта показаны в выдаче Яндекса **по отобранной выборке запросов** |
| **Источник** | Webmaster API v4, `search-queries/popular/`, `TOTAL_SHOWS` |
| **Формула** | `Σ TOTAL_SHOWS` по возвращённым запросам |
| **Охват** | ⚠ выборка топ-100 запросов из 506 существующих, отбор по `TOTAL_SHOWS` (MKT-009) |
| **Период** | Скользящее окно ~14 дней; фактическая длина плавает 12–14 дней из-за задержки источника |
| **Регион** | Не задан в запросе — все регионы вместе |
| **Ограничения** | Выборка смещена в сторону высокочастотных запросов; длинный хвост систематически теряется |
| **Какие решения можно принимать** | Сравнивать позиции и показы **внутри одного запроса** между датами |
| **Какие выводы делать нельзя** | ❌ Называть это видимостью сайта. ❌ Сравнивать суммы двух дат как рост (MKT-005): окна разной длины и сменный состав выборки. ❌ Складывать с показами Google |

### `google.impressions_window` / `impressions_last7`

| | |
|---|---|
| **Бизнес-смысл** | Показы страниц сайта в выдаче Google |
| **Источник** | GSC Search Analytics API v3, разрез `date` |
| **Формула** | `Σ impressions` по строкам разреза `date` |
| **Охват** | Весь ресурс `sc-domain:biz-soft.pro`, web-поиск |
| **Период** | 28 дней, конец — последняя доступная дата (задержка GSC 2–3 дня) |
| **Ограничения** | ⚠ Разрезы `date`, `query` и `page` дают разные суммы за один период (114 / 47 / 138 на 21.08) — GSC анонимизирует часть запросов. ⚠ `last7`/`prev7` берутся срезом по индексу строк (MKT-014) |
| **Какие решения можно принимать** | Оценивать динамику индексации и появления новых страниц в выдаче |
| **Какие выводы делать нельзя** | ❌ Считать CTR из показов разреза `query` и кликов разреза `date`. ❌ Публиковать проценты при базе < 50 показов: «+100 %» при 19 → 38 показов — шум |

### `queries_position_le_10` — запросов на первой странице

| | |
|---|---|
| **Формула** | `count(entities where average_position ≤ 10.0)` |
| **Ограничения** | ⚠ Считается по той же выборке 100 запросов; при смене состава выборки меняется без единого изменения позиций |
| **Нельзя** | ❌ Трактовать снижение как потерю позиций, пока не проверен состав выборки |

### `average_position` — средняя позиция

| | |
|---|---|
| **Источник** | `AVG_SHOW_POSITION` (Вебмастер) / `position` (GSC) |
| **Формула** | Считается источником; в снимок берётся как есть, **без повторного усреднения** |
| **Ограничения** | Средняя позиция запроса и средняя позиция страницы — **разные сущности** (`quality.py` `SCOPE_QUERY_VS_PAGE`) |
| **Нельзя** | ❌ Усреднять средние позиции по запросам без взвешивания на показы: невзвешенное среднее по дням даёт 41,88, взвешенное — 42,63 на тех же данных. ❌ Смешивать среднюю позицию запросов и страниц в одном показателе |

## CTR

### `sample_ctr` — CTR выборки

| | |
|---|---|
| **Бизнес-смысл** | Доля показов выборки, превратившихся в переходы |
| **Формула** | `clicks / impressions` — **обе величины из одной выборки запросов** |
| **Реализация** | `scripts/seo/measurement.py::sample_ctr` |
| **Ограничения** | Только выборка топ-100; на 21.08 = 5 / 967 = 0,52 % |
| **Можно** | Сравнивать CTR выборки между датами при неизменном составе выборки |
| **Нельзя** | ❌ Называть CTR сайта (`quality.py` запрещает через `allow_sitewide_ctr_claims`). ❌ Делить клики Вебмастера на визиты Метрики — это часть и целое |

### `expected_ctr`, «потерянные клики»

**Не рассчитывается и не публикуется.** Утверждённой CTR-модели по позициям
для Яндекса и Google не существует (`quality.py` `NO_CTR_MODEL`,
`allow_expected_ctr_claims=false`). Любое число «мы теряем N кликов» без
утверждённой кривой — выдумка.

## Трафик

### `metrika.visits` / `organic_visits`

| | |
|---|---|
| **Бизнес-смысл** | Визиты на сайт; визит объединяет действия с таймаутом 30 минут |
| **Источник** | Метрика Stat API v1, `ym:s:visits`, `accuracy=full` |
| **Охват** | Весь сайт; `organic_visits` — фильтр `ym:s:lastTrafficSource=='organic'`, все поисковые системы |
| **Период** | 14 дней, конец — вчера |
| **Ограничения** | Модель визита Метрики ≠ модель сессии GA4 |
| **Нельзя** | ❌ Сравнивать с кликами Вебмастера (часть и целое). ❌ Считать числом реальных людей |

### `ga4.sessions`

| | |
|---|---|
| **Источник** | GA4 Data API, `sessions` по `sessionDefaultChannelGroup` |
| **Ограничения** | ⚠ Канал `Organic Search` включает `metrika.yandex.ru` и `alice.yandex.ru` — собственные визиты владельца и голосовой ассистент (MKT-007). ⚠ Атрибуция каналов пересматривается GA4 задним числом |
| **Допустимое расхождение с Метрикой** | До ~10 % — разные модели сессии. Фактически 20 % по органике, и разница объясняется MKT-007, а не моделью |
| **Нельзя** | ❌ Считать `totalUsers` числом реальных людей: блокировщики, Safari/iOS ITP, отсутствие consent-режима |

### `ga4.Unassigned`

Сессии без определённого источника (9–11 из ~107). **Это не канал, а признак
проблемы сбора.** Рост доли `Unassigned` — сигнал деградации разметки, а не
появления нового трафика.

## Конверсии

### `metrika.goal_events` (`ym:s:sumGoalReachesAny`) ⚠

| | |
|---|---|
| **Что это на самом деле** | Сумма достижений **любых** целей счётчика, **без дедупликации по посетителю** |
| **Что это НЕ** | Не заявки, не лиды, не обращения |
| **Из чего состоит сегодня** | Только автоцели Метрики: отправка формы (**попытка**, не успех), заполнение и отправка контактных данных, поиск по сайту |
| **Ограничение** | MKT-001: ни одна из 23 целей сайта не заведена, поэтому реальные конверсии в этот показатель не входят |
| **Правило публикации** | `quality.py` `allow_lead_wording=false` — формулировка «заявка/лид» запрещена; используется «целевое событие» |
| **Нельзя** | ❌ Считать конверсию сайта как `goal_events / visits`. ❌ Сравнивать с key events GA4 — измеряют разное |

### `ga4.keyEvents` ⚠

| | |
|---|---|
| **Что это** | События, размеченные как ключевые: `form_submit`, `generate_lead` |
| **Что происходит на самом деле** | Сайт не отправляет ни одно из них. За всю историю сбора зафиксировано 2 key events, оба — из источника `metrika.yandex.ru`, то есть собственные визиты владельца (MKT-006, MKT-007) |
| **Граница сравнения** | 18.08.2026 — разметка изменена внутри периода (`measurement-limits.json` ANL-002). Сравнение конверсий через эту дату **запрещено** |
| **Нельзя** | ❌ Делать любой вывод об эффективности канала по этому показателю |

### `conversion_rate`

**Не определён и не публикуется** до закрытия MKT-001. После закрытия:

```
conversion_rate = визиты с достижением цели уровня lead / визиты
```

Обязательно с указанием `n` и маркером низкой выборки при `n < 5`
(`quality.py` `LOW_CONVERSION_SAMPLE`). Знаменатель — **визиты**, не показы и
не пользователи.

### `qualified_leads`, `deals`, `revenue`

**Не измеряются.** `measurement.py` фиксирует «CRM leads — источник не
подключён». В снимке лежат как `None`, а не `0` — это правильно и должно
таким остаться до подключения выгрузки Directus.

## Спрос

### `commercial_demand` — коммерческий спрос ⚠

| | |
|---|---|
| **Бизнес-смысл** | Сколько раз в месяц в Яндексе спрашивают то, что BIZSoft продаёт |
| **Источник** | Yandex Cloud Search API (Wordstat), `getTop`, широкое соответствие |
| **Формула** | `Σ wordstat_frequency` по фразам кластера с `intent == commercial` и `in_scope == true` |
| **Реализация** | `scripts/seo/wordstat/coverage.py::clusters_of` |
| **Значение на 21.08** | 490 638 запросов/мес по 150 кластерам |
| **Ограничение 1 (MKT-002)** | 51,6 % значения даёт кластер `google`, в котором 69 % — смартфоны Google Pixel и «google не работает» |
| **Ограничение 2 (MKT-003)** | Фильтр релевантности пропускает кроссовки Nike Air Zoom и отбрасывает `zoom купить` (7 960/мес) |
| **Ограничение 3 (MKT-012)** | Частотности Вордстата при широком соответствии вложены друг в друга; их сумма переучитывает спрос |
| **Свежесть** | Замер 21.08.2026; `quality.py` помечает устаревание (`MARKET_DEMAND_STALE`) и неполноту (`MARKET_DEMAND_PARTIAL`) |
| **Можно** | Сравнивать спрос **внутри одного кластера** между замерами |
| **Нельзя** | ❌ Считать объёмом рынка BIZSoft. ❌ Сравнивать с нашими показами: разные единицы, окна и соответствие (`DEMAND_NOT_COMPARABLE_TO_VISIBILITY`). ❌ Считать долю голоса. ❌ Принимать решения об ассортименте, пока `allow_assortment_decisions=false` |

### `наши показы по запросу`

**Это не спрос.** `opportunity.py` фиксирует правило прямо: показы сайта
рыночным спросом не называются ни при каких условиях, а формулировка «рыночный
спрос» разрешена только при наличии замера Вордстата. Правило соблюдается —
это одно из лучших мест системы.

### `coverage.levels` — покрытие спроса

| | |
|---|---|
| **Формула** | Для каждого уровня — доля суммарной частотности коммерческих фраз кластеров, удовлетворяющих условию |
| **Уровни** | `page` (есть страница) → `indexed` → `top10` → `clicks` → `conversion_measured` → `qualified_leads` |
| **Значения 21.08** | 0,773 / 0,0646 / 0,0087 / 0,0001 / **0,0** / `null` |
| **Ограничение 1** | Знаменатель загрязнён (см. `commercial_demand`); `page_coverage 77 %` завышен, потому что запросы про Pixel засчитаны как покрытые страницей `/vendors/google` |
| **Ограничение 2 (MKT-013)** | `conversion_measured: 0.0` — **ошибка типа**: конверсии не измеряются вовсе, значение обязано быть `null`, как соседний `qualified_leads` |
| **Нельзя** | ❌ Читать `conversion_measured = 0` как «спрос покрыт, но не конвертируется» |

## Приоритизация

### `opportunity_score` ⚠ — **сегодня две несовместимые формулы (MKT-011)**

**Каноническая (рекомендуется оставить)** — `scripts/seo/wordstat/opportunity.py`:

```
opportunity_score = normalized_demand × commercial_intent × coverage_gap
                    × trend_factor × confidence / estimated_effort
```

| Компонент | Диапазон | Смысл |
|---|---|---|
| `normalized_demand` | 0…1 | спрос кластера, нормированный на максимум |
| `commercial_intent` | 0…1 | `min(1, commercial_phrases/10)`, но ≥ 0,3 при ненулевом спросе |
| `coverage_gap` | 0,1…1,0 | 1,0 — страницы нет; 0,1 — есть, в топе, кликают |
| `trend_factor` | 0,5…1,3 | `declining` 0,5 · `unknown` 0,9 · `stable` 1,0 · `growing` 1,3 |
| `confidence` | 0,45…0,9 | по числу фраз и объёму спроса кластера |
| `estimated_effort` | 1,0…8,0 | GAP-D (заголовок) 1,0 … GAP-H (падающий спрос) 8,0 |

**Вторая формула** — `scripts/seo/opportunity.py`:

```
score = intent_weight × normalised_impressions × confidence_weight
        × band_impact / band_effort          (impact 0,4…0,9; effort 1…3)
```

Шкалы несопоставимы (знаменатель до 8 против до 3), состав компонентов разный,
имя одно. **Правило: до устранения дефекта числа из двух модулей нельзя
класть рядом и нельзя сортировать в один список.** Обе величины — только
способ упорядочить, а не основание решения; компоненты обязаны показываться
рядом с итогом.

### `priority_score`

Поле присутствует в `semantic-universe.jsonl`. **Определения в словаре нет** —
до его появления показатель в отчётах не используется.

## Здоровье данных

### `data_health` — `verified` / `limited` / `degraded`

| Значение | Условие | Что означает для читателя |
|---|---|---|
| `verified` | все источники доступны, охваты и периоды сопоставлены | числа описывают одно множество |
| `limited` | источники исправны, охваты различаются | числа верны, но описывают разные множества |
| `degraded` | сбор не прошёл или есть critical-находка | часть показателей не опирается на свежие данные |

Реализация — `measurement.py::data_health`. Текущее состояние: `limited`.

**Известный пробел:** `degraded` выставляется по отсутствию источника, но
`collect_gsc` при ошибке API записывает не `error`, а тело ошибки, поэтому
источник считается доступным с нулём показов (MKT-008). До исправления
`degraded` не гарантирует обнаружение сбоя GSC.

### `publication_rules`

Машиночитаемые запреты, выводимые из состояния данных:
`allow_green_overall_status`, `allow_sitewide_ctr_claims`,
`allow_expected_ctr_claims`, `allow_lead_wording`,
`allow_market_demand_wording`, `allow_assortment_decisions`.

**Предлагается добавить:** `allow_absolute_delta` (снимается при
`WINDOW_LENGTH_MISMATCH` или `SAMPLE_CHURN` — MKT-005) и
`allow_channel_conversion_claims` (снимается, пока внутренний трафик не
отфильтрован — MKT-007).

## Терминология: что нельзя называть чем

| Ошибочно | Правильно | Почему |
|---|---|---|
| «Заявка», «лид» о `goal_events` | «Целевое событие» | Автоцели уровня попытки, без дедупликации |
| «CTR сайта» о `sample_ctr` | «CTR выборки» | Охват — 100 запросов из 506 |
| «Рыночный спрос» о наших показах | «Наши показы по запросу» | Показы — свидетельство нашей видимости |
| «Источник» о поле `source` заявки | «Форма» / `form_source` | Значения `pricing`, `question`, `quote` — идентификаторы форм |
| «Конверсия канала» о `keyEvents` | — | Размечены события, которых сайт не шлёт |
| «Рост видимости» о разнице сумм Вебмастера | «Изменение накопленного окна» | Окна разной длины, состав выборки меняется |
| «Показов 0» при ошибке GSC | «Сбор не прошёл» | Ноль ≠ отсутствие данных |
