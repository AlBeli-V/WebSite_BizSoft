# SEO-мониторинг biz-soft.pro

Ежедневный автоматический мониторинг видимости biz-soft.pro в поиске с отчётом в 9:00 (Бишкек, UTC+6).

## Что отслеживается

- **Видимость в Google** по корзине ключевых запросов (`keywords.json`) — присутствие домена в топе выдачи и конкурентный ландшафт (кто занимает топ).
- **Динамика день к дню** — история замеров в `history.json`, сравнение с предыдущими днями.
- **Конкуренты** — появление/исчезновение игроков в топе по коммерческим запросам.

## Методология и ограничения среды

Замеры выполняются агентом Claude Code из облачной среды:

- Google-выдача снимается через поисковый инструмент с **US-локацией** — это аппроксимация: реальная выдача google.ru для пользователей РФ может отличаться. Тренд «не виден → виден → в топ-10» при этом отслеживается корректно.
- **Яндекс из среды недоступен** (сетевая политика блокирует yandex.ru), прямой запрос к biz-soft.pro также блокируется. Точные позиции в Яндексе и google.ru требуют подключения API Яндекс.Вебмастера / Google Search Console или стороннего сервиса (Topvisor, SE Ranking) — см. рекомендации в отчётах.
- Позиция фиксируется как: `top3` / `top10` (виден в результатах) / `null` (не найден в видимой части выдачи).

## Файлы

- `keywords.json` — корзина запросов (бренд / коммерческие / информационные). Редактируется вручную, агент подхватывает изменения.
- `history.json` — история замеров по датам.
- `YYYY-MM-DD.md` — ежедневные отчёты: замеры, динамика, комментарии, рекомендации.

## Реальные данные поисковых систем (GSC + Яндекс.Вебмастер)

Воркфлоу `.github/workflows/seo-data-collect.yml` (скрипт `scripts/seo/collect.py`) забирает из API Google Search Console и Яндекс.Вебмастера реальные данные: запросы с позициями/кликами/показами (GSC, задержка данных ~2–3 дня), список ресурсов, индексацию, ИКС и популярные запросы (Яндекс). Результат — `data/gsc-ГГГГ-ММ-ДД.json` и `data/yandex-ГГГГ-ММ-ДД.json`, коммитятся в ветку мониторинга. Секреты: `GSC_SERVICE_ACCOUNT_JSON`, `YANDEX_WEBMASTER_TOKEN`.

GitHub-schedule не срабатывает для не-main веток, поэтому агент сам запускает сборщик (workflow_dispatch, ref — ветка мониторинга) в начале утреннего прогона и ждёт его завершения перед чтением данных.

## Процедура ежедневного прогона (для агента)

0. Запустить воркфлоу `seo-data-collect.yml` (workflow_dispatch, ref `claude/biz-soft-rating-tracking-5rf03g`), дождаться завершения (~1 мин), сделать `git pull` — подтянуть свежие `data/*.json`; прочитать их (позиции/клики из GSC, индексация/ИКС/запросы из Яндекса) и использовать в отчёте как основной источник. Если данных нет или в них `error` — отметить это в отчёте.
1. Прочитать `keywords.json` и `history.json`.
2. Для каждого запроса выполнить поиск, зафиксировать: найден ли biz-soft.pro, топ-конкурентов (до 5 доменов).
3. Дописать замер в `history.json`.
4. Сравнить с предыдущим замером: новые/потерянные видимости, изменения в конкурентном топе.
5. Написать отчёт в двух форматах:
   - `YYYY-MM-DD.md` — рабочая версия для истории и чата (сводка, замеры, динамика, рекомендации);
   - `YYYY-MM-DD.html` — **письмо руководителю**: email-вёрстка (таблицы, инлайн-стили, ширина 640px, бренд-цвет #f2591d), язык — для бизнес-пользователя без маркетингового жаргона (термины объяснять по ходу). Обязательные блоки: 1) общая аналитика с ключевыми цифрами, 2) динамика «было → стало» с трендами ↑↓→ и пояснением, 3) тактические рекомендации (быстрые, без бюджета), 4) стратегические рекомендации (1–3 месяца), 5) «на что ещё обратить внимание» — важное по мнению аналитика. Образец: `2026-08-18.html`.
6. Закоммитить и запушить в ветку `claude/biz-soft-rating-tracking-5rf03g`, отправить отчёт пользователю.

## Доставка на почту

При пуше отчёта в ветку мониторинга воркфлоу `.github/workflows/seo-report-email.yml` автоматически отправляет последний отчёт на **avbelyaev@biz-soft.pro** с ящика hello@biz-soft.pro (SMTP reg.ru). Требуется repo-секрет `SMTP_PASS` — тот же, что использует `ops-mail.yml`. Агенту отдельно ничего отправлять не нужно; после пуша стоит убедиться, что воркфлоу завершился успешно.
