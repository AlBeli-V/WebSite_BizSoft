# BIZSoft Search Performance & Experiment Reporting (v2)

Ежедневная система отчётности по поисковой видимости biz-soft.pro. Два уровня:
**executive brief** для руководителя (≤900 слов) и **аналитическое приложение** для маркетинга,
SEO и разработки. Письмо уходит в 9:00 (Asia/Bishkek, UTC+6) на avbelyaev@biz-soft.pro.

Методика: `docs/seo/reporting-methodology.md` · переход с v1: `docs/seo/reporting-v2-migration.md` ·
аудит прежнего pipeline: `docs/seo/reporting-current-state.md`.

## Конвейер

| Шаг | Команда / файл | Результат |
|---|---|---|
| 1. Сбор | воркфлоу `seo-data-collect.yml` → `scripts/seo/collect.py` | `reports/seo/data/<источник>-<дата>.json` |
| 2. Канонический snapshot | `python3 scripts/seo/snapshot.py <дата>` | `intelligence/snapshots/<дата>.json` |
| 3. Качество данных | `python3 scripts/seo/quality.py <дата>` | `intelligence/data-quality/<дата>.json` |
| 4. Графики | `python3 scripts/seo/charts.py <дата>` | `intelligence/charts/<дата>-*.svg` |
| 5. Отчёт | `python3 scripts/seo/report_v2.py <дата>` | `intelligence/<дата>-executive.{md,html}`, `<дата>-appendix.md` |
| 6. Тесты | `python3 -m unittest discover -s scripts/seo/tests` | 40 проверок расчётов и формулировок |
| 7. Доставка | `seo-report-email.yml` (push executive-файла) | письмо + plain-text из `.md` |
| 8. Проверка сайта | `seo-site-check.yml` | title и FAQPage на живых страницах экспериментов |

## Правила, обязательные к соблюдению

1. Цифры только из snapshot — вручную в текст письма значения не вписываются.
2. Нет данных → «нет данных», не ноль.
3. ФАКТ / ИНТЕРПРЕТАЦИЯ / ГИПОТЕЗА / РЕШЕНИЕ / РИСК ДАННЫХ — каждое утверждение маркировано.
4. Критическая ошибка качества данных блокирует зависящие выводы и «зелёный» статус.
5. Показы — видимость сайта, не рыночный спрос. Цели Метрики — события, не заявки и не лиды.
6. «В топ-10» — строго средняя позиция ≤ 10; запросы и страницы не смешиваются.
7. В executive brief: ≤3 решения, без технических команд, промтов и путей к файлам в теле.
8. Технические задачи — тикетами в `reports/seo/tasks/`, исполнитель сам создаёт ветку и PR.
9. Деплой из отчётного контура не выполняется; изменения сайта — только через PR.

## Структура executive brief

Заголовок · свежесть данных по источникам · одно предложение общего статуса (выводится из статусов) ·
четыре статуса (видимость, захват трафика, конверсия, качество данных) · ≤5 KPI ·
«Что изменилось» (≤3 события с current/previous/абс./отн./доверием/интерпретацией) ·
результат для бизнеса · ≤3 решения (полный набор полей) · риски и качество данных ·
следующая контрольная точка.

## Ограничения среды мониторинга

Яндекс, biz-soft.pro и рекламные кабинеты недоступны напрямую из контейнера (egress) — сеть работает
через GitHub Actions. Контрольные замеры конкурентов через WebSearch (US-прокси) — вспомогательный
сигнал, не позиции.

## Ежедневная процедура (для агента)

0. `git pull`; `git fetch origin main`; синхронизировать `intelligence/seo-experiments.json` с main;
   статусы задач определять по main и по `seo-site-check`, не по прошлому отчёту.
1. Запустить `seo-data-collect.yml`, дождаться коммита данных, `git pull`.
2. `snapshot.py` → `quality.py` → `report_v2.py` (charts вызываются внутри) → `unittest`.
3. Проверить, что тесты зелёные и объём brief ≤900 слов.
4. Обновить реестры экспериментов; при изменении методики — `docs/seo/reporting-methodology.md`
   и раздел истории в приложении.
5. Коммит и push (перед push `git pull --rebase`) — письмо уходит автоматически.
6. Отправить пользователю executive.html и приложение.
