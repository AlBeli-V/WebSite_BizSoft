# Замена источников после блокировки NameBright/DropCatch

Дата: 08.09.2026. Приложение к `reports/seo/drop-domain-strategy.md` и
`reports/seo/drop-domain-pilot-plan.md` (ворота G1); постановка источника —
`reports/seo/tasks/DATA-003-backlink-source.md`.

Повод: NameBright (Legal Department) отказал в восстановлении аккаунта,
блокировка объявлена постоянной и не пересматриваемой, создание новых
аккаунтов NameBright и DropCatch — прямо или косвенно связанных с тем же
лицом — запрещено.

---

## 1. Что именно отключилось

NameBright, DropCatch, HugeDomains и Expire.com принадлежат одной компании —
TurnCommerce. Значит, отключился не один сервис, а весь контур этой группы,
и «завести аккаунт на другое лицо или компанию» вариантом не является: письмо
прямо описывает такой аккаунт как подлежащий блокировке без уведомления, то
есть домены, купленные через него, оказались бы в аккаунте, который могут
закрыть в любой момент вместе с оплаченными позициями.

Функции, которые группа выполняла для доменного направления:

| Функция | Кто выполнял | Класс |
|---|---|---|
| Списки освобождающихся и pending delete доменов gTLD | DropCatch | данные |
| Перехват освобождающегося домена (backorder) | DropCatch | приобретение |
| Аукцион перехваченных доменов | DropCatch | приобретение |
| Регистратор и хранение пойманного домена | NameBright | владение |
| Витрина премиальных имён | HugeDomains | приобретение |

Источником данных для модели оценки кандидата
(`reports/seo/drop-domain-evaluation-model.json`) эта группа не была ни в
одном факторе: ссылочного профиля, анкоров, истории индексации и архивной
структуры URL она не отдаёт.

## 2. Что теряет от блокировки текущая работа

**По репозиторию — ничего.** Пилот по дропам не запущен решением
руководителя 08.09.2026 (`drop-domain-strategy.md`, раздел 12), оба ворота
не сработали: источника ссылочных и архивных данных нет (G1), индексный блок
не снят — Google не обходит 67% известных ему страниц (G2). Ни один рабочий
контур (`seo-serp-watch`, `seo-daily-report`, `competitive-intelligence-daily`,
`seo-wordstat`) на сервисы TurnCommerce не завязан: проверено грепом по
`scripts/`, `competitive-intelligence/`, `.github/workflows/` — упоминаний нет.

Поэтому вопрос стоит не «чем закрыть потерю качества», а «чем закрывать G1,
когда до него дойдёт дело»: потери качества нет, потому что качество на этих
источниках и не строилось.

## 3. Домены в заблокированном аккаунте: их нет

Проверено руководителем 09.09.2026: доменов в аккаунте NameBright не
осталось. Значит, необратимой части у этой истории нет — потеряны канал
регистрации и канал перехвата, а не активы. Срочных работ по трансферу и
обращению в ICANN не требуется; регистратор-приёмник заводится не раньше
общих сроков раздела 6.

Регистратор `biz-soft.pro` в репозитории по-прежнему не записан. Выяснять
его вручную не нужно: первый прогон `ops-domain-watch` с ветки main назовёт
регистратора в отчёте, значение заносится в `expected_registrar` реестра
аккаунтов, и с этого момента сторож ловит смену регистратора сам.

## 4. Замена по функциям

| Функция | Замена | Качество против прежнего |
|---|---|---|
| Списки дропов gTLD, ручной просмотр | ExpiredDomains.net (бесплатно, свод по 676 TLD, включая аукционные площадки), WhoisFreaks (бесплатный ежедневный список), Instant Domain Search (раздел «dropping soon») | равно или выше: свод по многим площадкам вместо одной |
| Списки дропов, программно | DataForSEO Domain Analytics WHOIS API — фильтр по `expiration_datetime`, записи обогащены ссылочными и поисковыми метриками; при необходимости — зон-файлы ICANN CZDS и диффы по RDAP | выше: у DropCatch API отбора по качеству не было |
| Освобождающиеся `.ru` и `.рф` | cctld.ru (официальные списки), nic.ru, expired.ru (приём заявок для более чем десяти аккредитованных регистраторов) | новое покрытие: DropCatch зону `.ru` не обслуживал, а профиль донора BIZSoft — русскоязычный |
| Оценка кандидата по модели (ссылки, анкоры, доноры) | DataForSEO Backlinks API — тот же поставщик, аккаунт и секреты уже заведены (`DATAFORSEO_LOGIN/PASSWORD`, проба `ci-serp-probe`) | выше: сегодня не считается ни один фактор модели |
| Историческая структура URL, глубина архива | Wayback CDX API — бесплатно, без договора | выше: раньше не было |
| Присутствие в выдаче до дропа | xmlriver (Google) и Яндекс Search API — уже в контуре `seo-serp-watch` | равно |
| Глубокая ссылочная история (при нехватке первого источника) | Majestic: Trust Flow, Topical Trust Flow, исторический индекс, pay-as-you-go | выше по глубине, но это второй поставщик — против правила DATA-003 «один источник, один ряд» |
| Перехват gTLD | Dynadot, GoDaddy Auctions, SnapNames, NameJet, Pool, Sedo | ниже по вероятности перехвата конкурентных имён (у DropCatch была сеть из более чем тысячи аккредитаций); для нишевых имён профиля донора разница мала |
| Перехват `.ru` и `.рф` | expired.ru, Reg.ru, RU-CENTER | новое покрытие |
| Регистратор | Cloudflare Registrar, Porkbun, Namecheap, Dynadot; для `.ru` — Reg.ru, RU-CENTER, Timeweb | равно; оплата из РФ проще у российских |

## 5. Почему замена по данным получается сильнее прежнего

Обе половины ворот G1 — ссылочный индекс и архив — закрываются без нового
договора и без нового поставщика:

1. **DataForSEO уже подключён и оплачен.** Domain Analytics (WHOIS) и
   Backlinks — это те же учётные данные, что уже работают в
   Google-части конкурентной разведки. Один поставщик закрывает и ссылочные
   профили конкурентов из DATA-003, и историю доменов-кандидатов.
2. **Wayback CDX бесплатен** и закрывает архивную половину, которую DATA-003
   и разрешала брать отдельно.
3. **Отбор по качеству появляется до покупки.** У DropCatch поток был
   «имя + цена»; связка WHOIS-фильтра с ссылочными метриками даёт отбор по
   факторам модели ещё до аукциона.

Ограничение, которое нужно снять решением: у DataForSEO действует hard cap
**$20/мес** (`docs/competitive/decisions-2026-08-31.md`, раздел 3), и он
рассчитан под еженедельный съём Google-выдачи. Запросы Backlinks и WHOIS в
этот потолок не закладывались — либо потолок поднимается, либо заводится
отдельная строка бюджета с собственным счётчиком в журнале.

## 6. Решения руководителя 08.09.2026

1. **Ворота G1 закрываются существующим поставщиком:** DataForSEO (Domain
   Analytics WHOIS + Backlinks) плюс бесплатный Wayback CDX. Второй ссылочный
   сервис не заводится — правило DATA-003 «один источник, один ряд» в силе.
2. **Канал приобретения не восстанавливается сейчас:** перехват и регистратор
   заводятся не раньше, чем сработают оба ворота пилота.
3. **Бюджета хватает — расчёт ниже** (раздел 10). Потолок $20/мес
   заводился под съём Google-выдачи через DataForSEO, но Google снимается
   через xmlriver, и у DataForSEO остались только ручные пробы: потолок
   почти не расходуется. Нужен не новый бюджет, а счётчик расхода в журнале.
4. Домены в заблокированном аккаунте — их нет (раздел 3), вопрос закрыт.

## 7. Можно ли вернуть сами сервисы

Вопрос поставлен отдельно: не «чем заменить», а «нельзя ли вернуть те же два
источника через другие аккаунты этих же сервисов». Варианты, которые
существуют на самом деле, и то, чем каждый оплачивается.

| Вариант | Что это | Оценка |
|---|---|---|
| **Данные DropCatch без аккаунта** | аукционные списки DropCatch попадают в сводные агрегаторы (ExpiredDomains.net сводит площадки в один ряд); чтение публичных страниц аккаунта не требует | законно, ничего не нарушает, возвращает ровно ту половину, которая была данными |
| **Покупка на вторичном рынке** | домен, пойманный кем-то другим, покупается у продавца через брокера или площадку (Sedo, Afternic и подобные) | законно: мы покупатель, а не владелец аккаунта в группе TurnCommerce; дороже перехвата, но перехват и не был дешёвым |
| **Аккаунт юрлица с раскрытием связи** | компания открывает счёт на своё имя, письменно раскрывая прежнюю блокировку и запрашивая разрешение заранее | законно; вероятность отказа высокая — письмо распространяет запрет и на косвенно связанные аккаунты. Годится как запрос, не как план |
| **Новый аккаунт на другие данные, другое лицо, через прокси** | обход блокировки | **отклоняется**. Письмо описывает такой аккаунт как подлежащий блокировке без уведомления; исходная причина блокировки — несводимые регистрационные данные связанных аккаунтов, то есть повторение схемы даёт тот же результат, но уже с оплаченными доменами внутри аккаунта. Для SEO-актива это худший класс риска: потеря домена после вложений в контент |

Практический вывод: первая половина потерянного (данные) возвращается
бесплатно и без аккаунта — через агрегаторы, и она же перекрывается сильнее
связкой DataForSEO + Wayback. Вторая половина (перехват) через эти сервисы
не возвращается никак, кроме варианта с раскрытием, и до срабатывания ворот
пилота не нужна.

## 8. Переключатель источников в настройках

Отдельная беда этой истории не в самой блокировке, а в том, что поставщик
выбирался в переписке и нигде не был записан: замену пришлось искать заново
вместо того, чтобы переключить. Заведён реестр
`data/seo/domain-data-sources.json` — по образцу `data/seo/xmlriver.json`
(правка только через PR) и `ops/secrets/registry.json` (реестр без значений).

Устройство: восемь функций (ссылочный профиль, история домена, архив, списки
дропов gTLD, списки `.ru`, перехват gTLD, перехват `.ru`, регистратор), у
каждой — поле `active` (действующий источник) и `alternates` (запасные).
Переключение поставщика — правка одного поля, а не поиск заново. Заблокированные
площадки описаны в `blocked_groups` вместе с брендами группы, датой и политикой.

Тест `scripts/seo/tests/test_domain_sources.py` (в общем прогоне CI) держит
четыре инварианта:

| Инвариант | От чего страхует |
|---|---|
| `active` существует в `sources` и не принадлежит заблокированной группе | возврат на NameBright/DropCatch по невнимательности через полгода |
| У каждой функции есть хотя бы один живой запасной | единая точка отказа: поставщик отвалился — переключать не на что |
| Секреты источника заведены в `ops/secrets/registry.json` | источник, который «подключён», но нечем вызвать |
| Функция без источника обязана объяснить причину | молчаливый `null` неотличим от забытой строки |

## 9. Чем снижается риск повторения

Разбор по причине, а не по симптому. Формулировка письма — «несводимые
регистрационные данные в нескольких аккаунтах одного лица»; значит, риск
создаётся не работой с дропами, а устройством учёта.

| Мера | Что закрывает | Стоимость |
|---|---|---|
| Один поставщик — один аккаунт, данные совпадают с платёжным средством и документами; при смене данных аккаунт обновляется, а не заводится второй | прямую причину этой блокировки | ноль |
| Знать группу владельцев поставщика до подключения (в реестре — поле `group`) | «отвалился один сервис» вместо «отвалились четыре одной компании» | ноль, уже сделано |
| Домены не хранятся у площадки перехвата: регистратор отдельный, почта владельца — в собственном домене, не у поставщика | потерю актива вместе с аккаунтом сервиса | ноль |
| Критичные домены и экспериментальные — у разных регистраторов; продление с запасом и резервное платёжное средство | потерю основного домена из-за спора по побочному направлению | стоимость продления |
| Данные выгружаются в репозиторий, а не живут в кабинете (требование DATA-003 уже такое) | потерю истории при отключении поставщика: теряется будущий поток, не архив | ноль |
| Решения строятся на факторах модели, а не на фирменной метрике одного вендора | привязку к поставщику, из которой нельзя выйти | ноль, уже так |
| Реестр аккаунтов поставщиков без паролей: вендор, группа, владелец, платёжное средство, что упадёт при потере | «мы не знаем, что ещё завязано на этот аккаунт» | полчаса разово |
| Сторож сроков и статусов доменов по RDAP с предупреждением заранее | потерю домена по любой причине — бан, просрочка, сбой оплаты | один workflow |

Первые шесть строк — правила, они ничего не стоят и действуют с момента
записи. Последние две — работа, и они вынесены в вопрос руководителю.

## 10. Сколько стоит закрыть ворота G1

Цены DataForSEO — публичные, модель pay-as-you-go без абонентской платы:
Backlinks — $0,024 за запрос плюс $0,000036 за строку данных; Domain
Analytics WHOIS — $0,12 за запрос плюс $0,0012 за домен в ответе (до 1000
доменов на запрос). Wayback CDX бесплатен.

| Работа | Состав | Оценка |
|---|---|---|
| Базовый замер DATA-003: свой профиль и десять конкурентов Google | 11 доменов × 3 запроса (сводка, доноры, анкоры) ≈ 33 запроса и ≈ 20 тыс. строк | около $1,5 разово |
| Ежемесячная перепроверка тех же профилей | тот же объём раз в месяц | около $1,5 в месяц |
| Отбор дроп-кандидатов по WHOIS | один запрос с фильтром на 1000 доменов | около $1,3 за срез |

Даже при еженедельном срезе кандидатов расход укладывается примерно в
$5–8 в месяц — то есть в существующий потолок $20/мес, который сегодня
расходуется только ручными пробами (регулярный Google-сбор идёт через
xmlriver по 25 ₽ за 1000 вызовов). Поднимать потолок не нужно; нужно, чтобы
расход этих запросов попадал в тот же append-only журнал, что и Google-часть,
иначе потолок перестанет что-либо значить.

## 11. Модель подключения аккаунтов: ключ пользователя, а не общий аккаунт

Решение руководителя 09.09.2026 по будущему сервису анализа дроп-доменов:
регистратором и владельцем источника выступает сам пользователь сервиса —
он подключает собственный ключ доступа, и на его же балансе лежат средства.
Общего аккаунта, через который работают все, у сервиса нет.

Для риска блокировок это лучшая из возможных схем: блокировка одного
пользователя не останавливает сервис, а сервис не накапливает у поставщика
историю «одно лицо — много аккаунтов», из-за которой и возникла нынешняя
ситуация. Три требования, без которых схема даёт обратный эффект:

1. **Раздельный исходящий адрес.** Если сервис ходит к поставщику с одного
   IP от имени десятков ключей, поставщик связывает эти аккаунты между собой
   — ровно та связка, которую NameBright назвал причиной блокировки. Значит:
   запрос выполняется либо из браузера пользователя, либо через отдельный
   исходящий адрес на пользователя.
2. **Чужой ключ — это чужой секрет.** Хранение только в зашифрованном виде,
   отзыв по требованию владельца, доступ из кода — по одному ключу за раз,
   в журнале — факт использования, но не значение.
3. **Условия поставщика проверяются до подключения.** Часть сервисов
   разрешает вызовы от имени владельца ключа через стороннее приложение,
   часть запрещает; проверка — до того, как ключ принят, а не после жалобы.

Требования относятся к сервису дроп-доменов и не затрагивают контуры сайта:
там аккаунты остаются собственными и описаны в `ops/accounts/registry.json`.

Схема целиком — `docs/drop-service/byo-account-architecture.md`: два слоя
данных, три возможных исполнителя запроса, жизненный цикл ключа и приёмка.
