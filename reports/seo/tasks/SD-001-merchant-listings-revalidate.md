# SD-001 — Проверить в Search Console, сняты ли претензии по товарной разметке

**Приоритет:** P2 · **Статус:** queued · **Заведено:** 2026-09-15 · **Созревает:** 2026-09-29

## Повод

15.09.2026 Google прислал два письма по biz-soft.pro:

- «Данные о товарах продавца» — три незначительные проблемы: отсутствует
  `hasMerchantReturnPolicy` (в offers), отсутствует `shippingDetails` (в offers),
  поле `sku` дублируется;
- «Описания товара» — две незначительные: отсутствует `aggregateRating`,
  отсутствует `review`.

## Что установлено 15.09.2026

Проба прода (`ops-probe`, прогон #260, `/product/chatgpt-business`,
15.09.2026 15:53 МСК) — на живой странице:

| Что искали | Сколько нашли | Чтение |
|---|---|---|
| `hasMerchantReturnPolicy` | 2 | по разу в JSON-LD и microdata — поле есть |
| `shippingDetails` | 2 | по разу в JSON-LD и microdata — поле есть |
| `sku` | 2 | по разу в JSON-LD (`"sku":`) и microdata (`itemprop="sku"`) |
| `aggregateRating`, `review` | 0 | отзывов о товарах у проекта нет |

То есть два из трёх пунктов письма о товарах продавца на проде закрыты с
13.09.2026 (компонент `OfferLogisticsMicrodata`, разбор —
`docs/seo/structured-data-implementation.md` §10.1): письмо описывает
состояние индекса до выкатки. Третий пункт — дубль `sku` — на странице
возможен только как следствие двух сериализаций одного товара (JSON-LD для
Google, microdata для Яндекса), других источников артикула на странице нет.
Живой тест Google 08.09.2026 после снятия общего идентификатора узла показал
«2 элемента без ошибок», без дублей, — то есть претензия относится к тому же
доиндексному состоянию.

## Решения руководителя 15.09.2026

1. Разметку не трогать, дождаться переобхода. В Search Console по обоим
   отчётам нажать «ПРОВЕРИТЬ ИСПРАВЛЕНИЕ» (программного API для этого нет),
   контрольная точка — этот тикет.
2. `aggregateRating` и `review` не заводить: источника отзывов нет, фиктивные
   рейтинги запрещены правилом `docs/rules/structured-data.md`. Предупреждение
   остаётся ожидаемым (`docs/seo/structured-data-implementation.md` §6).
3. Прод сторожит недельный прогон `ops-schema-check` (понедельник, 06:41 и
   07:29 МСК) — чтобы о расхождении узнавать своей проверкой, а не письмом.

## Что сделать 29.09.2026

1. Открыть отчёт «Данные о товарах продавца» в Search Console и посмотреть
   состояние проверки исправления и дату последнего сканирования карточек.
2. Если дубль `sku` пережил переобход — снять `meta itemprop="sku"` из
   microdata-слоя карточки (`src/pages/product/[slug].astro`): артикул
   останется в JSON-LD и в видимых параметрах карточки, Яндексу `sku` в
   товарной микроразметке не нужен. Это вариант 2 решения 15.09, отложенный
   до подтверждения фактом.
3. Если претензии сняты — закрыть тикет записью о дате переобхода.

## Приёмка

В отчётах Search Console по карточкам товаров нет пунктов «Отсутствует поле
"hasMerchantReturnPolicy"», «Отсутствует поле "shippingDetails"» и «Поле "sku"
дублируется», либо по каждому оставшемуся есть решение руководителя.
