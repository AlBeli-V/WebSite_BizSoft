# SEM-001 — Подключение источников рыночного спроса (Wordstat API, Директ API)

**Приоритет:** P1 (после DATA-001) · **Статус:** proposed · **Владелец:** не назначен

## Проблема, которую закрываем
Все текущие источники (Яндекс.Вебмастер, GSC) измеряют **видимость наших страниц**, а не объём рынка.
Следствия, зафиксированные в отчёте 2026-08-19:
- решения об ассортименте принимаются по нашим показам — то есть только там, где мы уже ранжируемся;
- товары с рыночным спросом, по которым у нас нет страниц, структурно невидимы;
- в snapshot запрещены формулировки о спросе (`allow_market_demand_wording: false`);
- PPC-RES-001 заблокирован: нет прогноза CPC и кликов.

## Этап A. Wordstat API (делать первым)
1. Аккаунт Yandex Cloud + привязанный биллинг.
2. Заявка на доступ к Wordstat API, дождаться одобрения.
3. Ключ → секрет репозитория `WORDSTAT_API_KEY`.
4. До массового прогона зафиксировать тариф и лимиты (базовые ориентиры: 10 запросов/с, 1000/сутки) —
   от них зависит дизайн батчей и кэша.

## Этап B. Директ API (двумя шагами)
1. Песочница — включается в интерфейсе Директа без реальных кампаний, используется для отладки.
2. Полный доступ — требует созданной кампании в интерфейсе, принятия соглашения и заявки.
3. Токен → секрет `DIRECT_OAUTH_TOKEN`.
Полный доступ нужен для прогноза бюджета/ставок и последующей сверки PPC-запросов с SEO.

## Этап C. Инженерная часть
- `scripts/seo/collect_semantics.py`: Wordstat (частотность, связанные запросы) + прогноз Директа.
- Кэш и помесячное обновление частотности (не ежедневное) — экономия квоты и корректность сезонности.
- Новый блок snapshot `market_demand` с собственными периодами, регионом и типом соответствия.
- Проверки качества: обязательный регион; различение «показы Wordstat» и «показы нашего сайта»;
  запрет переноса частотности Яндекса на Google; маркер сезонности при сравнении месяцев.
- Артефакты: `reports/seo/semantics/core-<дата>.json`, `gap-analysis-<дата>.md`.

## Что появится в отчётности
1. **Расширение семантики по текущим товарам** — полное ядро на каждую vendor-страницу, gap-анализ
   «что ищут / чего нет на странице», приоритет по частотности × коммерческому интенту.
2. **Поиск новых товаров** — скан вендоров рынка по шаблонам «купить {X} на юрлицо», ранжирование по
   частотности; кандидаты на ассортимент с подтверждённым спросом.
3. **Доля голоса** — наши показы против рыночной частотности по кластеру: где мы близки к потолку,
   а где рынок в разы больше нашей видимости.
4. **Экономика канала** — прогноз CPC × частотность: сравнение стоимости трафика SEO и PPC по кластерам.

## Ограничения (фиксировать в методике)
- Wordstat отражает показы в поиске Яндекса, а не покупки и не выручку.
- Частотность зависит от региона, типа соответствия (широкое / «кавычки» / !точное) и сезона.
- Данные Яндекса не переносятся на Google.
- Квота суточных запросов ограничивает объём ядра — нужен приоритетный список кластеров.

## Критерий приёмки
В snapshot есть блок `market_demand` с регионом, типом соответствия и датой обновления; в приложении —
gap-анализ по 5 текущим кластерам и список кандидатов-товаров с частотностью; в методике описаны
ограничения; формулировки о спросе разрешены только со ссылкой на Wordstat.
