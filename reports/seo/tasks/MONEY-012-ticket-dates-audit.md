# MONEY-012 — Проставить даты созревания тикетам, у которых срок записан прозой

**Приоритет:** P2 · **Статус:** queued · **Заведено:** 2026-09-08 · **Созревает:** 2026-09-14

## Проблема

Слой созревания (`scripts/seo/tasks_due.py`) видит только тикеты с полем
`**Созревает:** ГГГГ-ММ-ДД`. Тикет, у которого момент запуска записан прозой,
для него не существует — и его судьба снова зависит от памяти людей, то есть от
того, ради чего слой и заводился.

## Что уже произошло: приём разошёлся сам

Первый замер 08.09.2026 нашёл **15 открытых тикетов без даты**, из них семь —
свежие `GIDX-*` соседнего контура с формулировками вроде «через 7 дней после
деплоя GIDX-000» и «применять сразу после мержа волны 1».

В течение часа после мержа поля `Созревает` соседний контур проставил даты всем
семи и перевёл статусы. Осталось **девять** тикетов без даты — и все они старые,
из тех, что заводились до появления поля:

| Тикет | П | Статус | С какого числа лежит |
|---|---|---|---|
| ANL-004 | P0 | open | 21.08 — цели в Метрике и GA4 не заведены, конверсия не измеряется вовсе |
| SEO-EXP-005 | P0 | running | 02.09 — партия snippets-10-expand |
| CONTENT-002 | P1 | running | 02.09 — шесть статей, вердикт 16.09 |
| CONTENT-004 | P1 | running | 03.09 — десять статей, вердикт 17.09 |
| CRO-EXP-002 | P1 | proposed | FAQ и коммерческие доказательства |
| INDEX-001 | P1 | in_progress | классификация исключённых URL |
| SEO-EXP-004 | P1 | running | 01.09 — сниппеты GAP-D, вердикт 16.09 |
| BRAND-001 | P2 | open | due diligence домена |
| DATA-002 | P2 | open | дневной ряд Вебмастера |

У четырёх идущих экспериментов дата вердикта известна и записана в реестре — им
нужна та же дата в поле `Созревает`, чтобы тикет всплыл в день, когда его пора
подводить. У `ANL-004` даты нет вовсе, и это P0, лежащий восемнадцатый день.

## Что сделать

Пройти `python3 scripts/seo/tasks_due.py --unmanaged` и по каждому тикету либо
проставить `**Созревает:**`, либо перевести статус в закрытый, если работа уже
не планируется. Для экспериментов дата берётся из `next_review` реестра — иначе
тикет и реестр разойдутся.

Чужие контуры — с их владельцем, а не правкой мимо него: `GIDX` показал, что
достаточно, чтобы приём был виден.

## Приёмка

`tasks_due.py --unmanaged` возвращает 1 (открытых тикетов без даты нет) либо
короткий список, по каждому пункту которого есть решение владельца.
