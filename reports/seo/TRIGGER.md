# Восстановление ежедневного триггера Growth Intelligence

Система запускается Routine-триггером Claude Code (среда CCR, сессия «BIZSoft Growth Intelligence»). Если триггер или сессия утеряны — создать заново из любой сессии Claude Code этого репозитория:

- **Расписание:** cron `3 3 * * *` UTC (09:03 Бишкек, ежедневно).
- **Текущий триггер:** `trig_013uQS6iK8LGVQETEaKDWFxY`, сессия `session_01JoQwrqUDpG5fpgeEWaNzKx`.
- **Промпт триггера** (актуальная редакция от 18.08.2026):

> Ежедневный прогон BIZSoft Search & Growth Intelligence (biz-soft.pro). Строго следуй процедуре и формату из reports/seo/README.md в репозитории WebSite_BizSoft, ветка claude/biz-soft-rating-tracking-5rf03g: 0) git pull; запусти воркфлоу seo-data-collect.yml (GitHub MCP actions_run_trigger, ref этой ветки), дождись коммита данных (poll git ls-remote), git pull; 1) запусти python3 scripts/seo/intelligence.py и прочитай reports/seo/intelligence/<сегодня>.json; сравни со вчерашним intelligence-JSON и score-history.json: дельта Growth Score, изменения окон, новые/потерянные запросы, движение позиций; также прочитай reports/seo/data/metrika-*.json и ga4-*.json за сегодня и вчера — визиты, органика, цели/keyEvents, их динамика и СОПОСТАВЛЕНИЕ двух счётчиков (расхождение >20% — в Risks); 2) WebSearch по корзине keywords.json — конкурентный контроль (US-прокси, только конкуренты, не позиции), допиши history.json; 3) напиши отчёт за сегодня в reports/seo/: YYYY-MM-DD.html (письмо руководителю, email-вёрстка по образцу 2026-08-18.html, бренд #f2591d) и YYYY-MM-DD.md. Формат — блоки из README, включая блок 3б «Поведение и конверсии (Метрика × GA4)» со связкой запрос→посадочная→визит→заявка, и PPC Radar (обязателен, даже если пусто). План действий (блок 12) — карточками из 6 полей на каждую проблему/точку роста: Обоснование (какие данные показывают проблему, что теряем без действия, почему это действие устраняет узкое место), Мини-вариант, Оптимальный, Макси-вариант, Охват (конкретные URL/карточки — перечислить — или весь каталог; сначала точечно, масштабировать после подтверждения), Как измеряем результат (до/после с контрольной группой нетронутых страниц, окно 7/14 дней, целевая метрика с ожидаемым значением) + Opportunity Score. Правила: FACT/HYPOTHESIS раздельно; нет данных — так и пиши; CPC/бюджеты без прогнозов не выдумывай; каждый блок — плашка «Резюме для руководителя» простым языком с ожидаемой реакцией; тон аналитик+growth-стратег+коммерческий директор; 4) обнови реестры экспериментов (активные эксперименты — проверять их метрики успеха по данным дня и двигать к вердикту); 5) git pull --rebase, коммит, push — seo-report-email отправит письмо на avbelyaev@biz-soft.pro (проверь статус run, упомяни); 6) отправь оба файла пользователю SendUserFile (html display render, status proactive, caption — Growth Score с дельтой и главное изменение). Понедельник — недельный отчёт (weekly/), 1-е число — месячный (monthly/). Ограничения среды: Яндекс/biz-soft.pro/рекламные кабинеты недоступны напрямую (egress blocked) — не обходить.

При изменении промпта триггера — обновлять и этот файл (единая точка восстановления).

## Зависимости системы (что должно быть живо)

- Секреты репозитория: `SMTP_PASS`, `GSC_SERVICE_ACCOUNT_JSON`, `YANDEX_WEBMASTER_TOKEN`, `YANDEX_METRIKA_TOKEN`, `YANDEX_METRIKA_COUNTER_ID`, `GA4_PROPERTY_ID`.
- Воркфлоу: `seo-data-collect.yml` (сбор), `seo-report-email.yml` (почта), `seo-site-check.yml` и `seo-ga4-admin.yml` (утилиты).
- Токен Яндекса живёт ~1 год — при истечении перевыпустить (oauth.yandex.ru, приложение с доступами Вебмастер+Метрика) и обновить секреты.
