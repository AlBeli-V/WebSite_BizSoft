## 1. Executive Summary

Проект в **лучшем состоянии, чем типичный сайт после десятков итераций**. Это надо
сказать прямо, потому что от этого зависит выбор стратегии: здесь **не нужен
рефакторинг**, здесь нужна **точечная починка**.

Что хорошо:

* строгий TypeScript, `astro check` — **0 ошибок, 0 предупреждений**;
* 79 юнит-тестов, все зелёные; ценовая логика вынесена в чистые функции и покрыта;
* **ни одного** маркера `TODO`/`FIXME`/`HACK` во всей кодовой базе;
* каждый вызов Directus обёрнут в `try/catch` — дисциплина соблюдена без исключений;
* цены КП пересчитываются на сервере из БД, клиентские значения не принимаются на веру;
* клиентский JS — **48 КБ** суммарно на 9 чанков, главная страница 37 КБ gzip;
* нет мёртвых модулей: все компоненты, библиотеки и data-модули имеют потребителей.

Что плохо — и это главное, что даёт этот аудит. Три дефекта работают **прямо
сейчас, молча, в продакшене**, и ни один из них не виден по логам или по
внешнему виду сайта:

1. **SEC-001 (P0).** Четыре файла `public/*-zagruzka.xlsx` раздаются по прямым
   URL и содержат колонки закупочной себестоимости в валюте и коэффициента
   наценки по **168 позициям**. `robots.txt` их не закрывает. Любой конкурент
   или клиент вычисляет вашу маржу за две минуты.
2. **ANL-001 (P1).** Из 10 мест вызова целей Яндекс.Метрики **5 вырезаны
   минификатором** из собранного бандла — и это ровно те, что считают
   конверсии: `lead_sent` (обе формы), `add_to_cart` (карточка и кнопка),
   `quote_pdf` (скачивание КП). Цели лендингов производителей (`view_vendor_landing`
   и клики) работают — у них есть зашитый фолбэк идентификатора. Итог: счётчик
   показывает трафик и поведение, но **ни одной заявки, ни одного КП** в отчётах
   по целям. Проверено на артефакте сборки и на отдаваемом HTML.
3. **REL-001 (P1).** При недоступности Directus страницы товаров отдают **404**,
   а не 503 — проверено экспериментально. Часовой сбой БД = сигнал поисковикам
   «этих страниц больше нет» по всему каталогу.

Плюс к этому: **29 известных уязвимостей в зависимостях** (12 high), отсутствие
любых лимитов на публичные формы, и невоспроизводимая сборка
(`--frozen-lockfile=false` и в Docker, и в CI).

**Общая оценка технического риска: средне-высокий, но локализованный.**
Архитектура здоровая. Проблемы — на стыках: приложение↔сборка,
приложение↔инфраструктура, приложение↔поисковики. Ровно там, где никто не
смотрит, потому что «сайт же работает».

**Рекомендуемая последовательность:** Phase 1 (P0/P1) закрывает ~90% реального
риска и занимает меньше дня. Всё остальное можно делать спокойно и по частям.

| Язык | TypeScript 5.9, `astro/tsconfigs/strict` |
| Пакетный менеджер | pnpm 9.15.9 (`packageManager` зафиксирован) |
| CMS / БД | Directus (REST API, тонкий самописный fetch-клиент, без SDK) |

| Шрифты | self-host Raleway (вариативный) + Prosto One, два woff2, `font-display: swap`, без preload |
| Почта | nodemailer (SMTP reg.ru) |
| PDF | pdfkit |
| OG-картинки | `@resvg/resvg-js` + DejaVu, рендер на лету |
| Тесты | vitest, 8 файлов / 79 тестов |
| Рантайм | Docker (node:22-alpine), nginx-реверс-прокси, SSH-деплой из GitHub Actions |

### 2.2. Фактический режим рендеринга

Заявлен «гибридный», и это соответствует действительности:

* **SSG (~40 страниц):** контентные и юридические страницы, блог, решения,
  сравнения, документы;
* **SSR (`prerender = false`, 21 маршрут):** главная, каталог, карточка товара,
  лендинги вендоров, корзина, `sitemap.xml`, OG-картинки, все `/api/*`.

**Важное следствие, которое не учтено в коде:** `BaseLayout` → `Header` вызывает
`getVendors()` и `getCategories()`, поэтому **статические страницы тоже ходят в
Directus во время сборки**. В прод-сборке (Docker build stage) Directus
недоступен — см. SEO-007.

несогласованность, при рестарте — холодный старт. Для одной реплики решение
адекватное.

## 4. Сильные стороны — что нельзя ломать

Эти решения работают и должны быть сохранены при любых изменениях:

1. **`lib/directus.ts` как единственная дверь в БД.** Именно поэтому фиксы
   таймаутов и кодов ответов будут точечными, а не размазанными.
2. **Чистая ценовая логика + тесты.** `effectivePrice`, `computePegRub`,
   `roundPrice`, `previewBulkChange` — не трогать без крайней нужды.
3. **Сервер пересчитывает цены КП из БД.** Подмена цен через localStorage или
   share-ссылку не влияет на финансовый результат. Проверено по коду.
4. **`escapeHtml` в рендере корзины.** Единственное место с `innerHTML` от
   пользовательских данных — экранирование на месте.
5. **`try/catch` вокруг каждого обращения к Directus.** Сбой БД не роняет
   страницу целиком. Проблема не в наличии обработки, а в выбранном
   HTTP-статусе (REL-001) — это правка одной ветки, а не переписывание.
6. **Дисциплина `noindex`.** Проверено вживую: `/cart`, `/consent`, `/docs`,
   `/compliance`, `/admin/prices` — `noindex` и вне sitemap; все 13 публичных
   страниц — индексируемы и в sitemap. Одно исключение — SEO-002.
7. **Нормализация URL.** `/about/` → 301 → `/about`, `trailingSlash: 'never'`
   соблюдается адаптером. Проверено.
8. **Крошечный клиентский бандл.** 48 КБ на 9 чанков. Не приносить фреймворки.
9. **Генерируемые артефакты синхронны с источниками.** Перегенерация
   `vendor-content.ts` из `scripts/content/*.json` дала бит-в-бит тот же файл;
   `pnpm build` не пачкает рабочее дерево.
10. **Комментарии объясняют «почему», а не «что»** — редкость, экономит часы
    при разборе.

## 5. Метод и доказательная база

Каждый вывод ниже подтверждён одним из способов, и способ указан явно:

* **[стенд]** — воспроизведено на локальном стенде: `pnpm install --frozen-lockfile`
  → `pnpm test` (79/79 ✅) → `pnpm typecheck` (0/0 ✅) → `pnpm build` (✅) →
  `node dist/server/entry.mjs` + HTTP-запросы. Directus на стенде недоступен —
  это дало **естественный эксперимент на отказ бэкенда**.
* **[артефакт]** — прочитан результат сборки в `dist/`.
* **[код]** — прочитан исходник, указаны файл и строки.
* **[тест]** — написан временный проверочный тест, зафиксирован результат,
  тест удалён (в репозиторий не попал).
* **[инструмент]** — `pnpm audit`, `pnpm outdated`.

Отдельно: **проверок на живом biz-soft.pro не проводилось** — прямой сетевой
доступ к прод-серверу из сессии закрыт (см. `CLAUDE.md`). Пункты, требующие
подтверждения на проде, помечены явно.

## 7. Security findings

### SEC-001 · P0 · Публичная выгрузка закупочных цен и наценки

| | |
|---|---|
| **Файлы** | `public/block1-design-zagruzka.xlsx`, `block2-games-zagruzka.xlsx`, `block3-video-zagruzka.xlsx`, `flagship-openai-figma-zagruzka.xlsx` |
| **Доказательство** | **[артефакт]** Файлы копируются в `dist/client/` и раздаются Node-адаптером по прямым URL. Разбор через `xlsx`: во всех четырёх присутствуют колонки `base_price_usd`, `base_price_eur`, `markup_coeff`; заполнены у **168 позиций из 189**. `public/robots.txt` закрывает только `/admin`, `/api`, `/cart`, `/checkout`, `/search`, `/consent` — эти файлы открыты и для индексации |
| **Последствия** | Конкурент получает закупочные цены и коэффициент наценки по всему каталогу. Клиент видит вашу маржу перед переговорами. Утрата переговорной позиции и ценовой политики целиком |
| **Вероятность** | Данные уже доступны. Достаточно одного любопытного посетителя или поискового бота |
| **Исправление** | Удалить файлы из `public/`; при необходимости хранить в приватном месте. Проверить кэш и индексы Яндекса/Google, при попадании — запросить удаление URL |
| **Риск исправления** | Минимальный: **[код]** ни один файл проекта на них не ссылается (проверено по `src`, `docs`, `.github`) |
| **Сложность** | Тривиальная |
| **Зависимости** | Нет |
| **Проверка** | `curl -I https://biz-soft.pro/block1-design-zagruzka.xlsx` → 404; проверка в Яндекс.Вебмастере через `ops-*` workflow |

> В отчёт намеренно не вынесены конкретные значения себестоимости и маржи —
> указаны только расположение и характер проблемы.

**Отдельно:** `public/shablon-zagruzki.xlsx` и `public/Шаблон загрузки.xlsx` —
байт-в-байт одинаковые файлы (33 579 б) под двумя именами. Это шаблон без

### SEC-002 · P1 · `/api/quote` — рассылка вложений на любой адрес от имени домена

| | |
|---|---|
| **Файл** | `src/pages/api/quote.ts:122-129` |

| **Риск исправления** | Средний: меняется клиентский сценарий «КП придёт на почту». Требует продуктового решения |
| **Сложность** | Средняя |
| **Зависимости** | Общий механизм лимитов — с SEC-003 |
| **Проверка** | Серия запросов с одного IP: после N-го — 429; журнал SMTP |

### SEC-005 · P1 · Незакреплённый GitHub Action в workflow с доступом к прод-серверу

| | |
|---|---|
| **Файл** | `.github/workflows/deploy.yml:37` |
| **Доказательство** | **[код]** `uses: easingthemes/ssh-deploy@main` — ссылка на **подвижную ветку**. Этому шагу передаётся `secrets.SSH_KEY` — приватный ключ от прод-сервера. Остальные 8 экшенов закреплены тегами |
| **Последствия** | Компрометация или недружественный коммит в апстрим `main` → выполнение произвольного кода в раннере, имеющем приватный SSH-ключ прод-сервера. Полный захват сервера |

### Что происходит с историей при включении целей

Вопрос закономерный, поэтому отвечаю отдельно: **обнуления нет ни в каком виде.**

| Данные | Что с ними станет |
|---|---|
| Визиты, источники, поведение, Вебвизор (счётчик `110206070`) | Не затрагиваются вообще. Счётчик не пересоздаётся, идентификатор не меняется |
| Цели лендингов производителей (`view_vendor_landing`, клики `data-ev`) | Пишутся сейчас и продолжат писаться. Провала в графике не будет |
| `lead_sent`, `add_to_cart`, `quote_pdf` | Терять нечего — не срабатывали ни разу. Ноль сменится реальными цифрами |

Единственный реальный эффект — **визуальный**: в отчёте «Конверсии» линия
пойдёт вверх от нуля, и при беглом взгляде это читается как всплеск. Лечится
примечанием в интерфейсе Метрики на дату правки.

**Если нужна содержательная непрерывность метрики, есть три способа получить
её без задержки исправления:**

1. **Восстановить фактическую историю из БД (рекомендуется).** Коллекции
   `leads` и `quotes` в Directus содержат `created_at` (`special: ['date-created']`)
   и `source` — **[код]** `scripts/directus-setup.mjs:192-213`. Этого достаточно,
   чтобы построить реальный ряд «заявки и КП по дням» за весь период работы сайта
   и использовать его как исторический базис рядом с данными Метрики. Данные уже
   есть, нужна только выгрузка через `ops-*` workflow. Это даёт непрерывность
   **бизнес-метрики**, которая и нужна для решений, — в отличие от Метрики, где
   разрез по источникам за прошлое восстановить нельзя.
2. **Проверить автоцели Метрики.** Метрика самостоятельно фиксирует отправку
   форм и клики по телефону/почте. Формы отправляются через `fetch` с
   `preventDefault`, но само событие `submit` при этом возникает, так что часть
   истории могла накапливаться помимо `reachGoal`. Проверяется в интерфейсе
   Метрики (раздел автоцелей) до внесения правок. То же стоит посмотреть в GA4
   (`G-V9BK2D1431`) — расширенная статистика умеет писать `form_submit`.
3. **Заложить возможность дозагрузки на будущее.** Офлайн-конверсии Метрики
   позволяют дописывать события задним числом, но требуют `ClientID`/`yclid`.
   **[код]** Сейчас он нигде не сохраняется — ни в `leads`, ни в `quotes`
   (поиск по `ClientID\|yclid\|_ym_uid` в `src` и `scripts` даёт 0 совпадений).
   Значит, за прошлое дозагрузка невозможна, но добавление одного поля
   `client_id` в `leads` позволит в дальнейшем связывать заявки со сделками и
   считать реальную окупаемость канала. Отдельная небольшая задача, не блокирует
   исправление.

Чего сделать нельзя ни одним способом — **восстановить прошлые конверсии в
разрезе источников трафика внутри Метрики.** Эти данные не потеряны при
исправлении: их никогда не существовало. Каждый день без правки — ещё один день
без них, поэтому откладывать исправление ради сохранности истории смысла нет.

данным. Переезд на другой фреймворк, другой рендеринг или другой слой данных
не даст выигрыша, соизмеримого с риском.

Целевое состояние — та же архитектура плюс четыре свойства, которых сейчас нет:

1. **Честные HTTP-коды.** Отказ бэкенда отдаёт 503, отсутствие записи — 404.
   Поисковик отличает аварию от удаления.
2. **Границы устойчивости.** Таймаут на каждом исходящем запросе; ни один
   внешний сервис не может подвесить рендер.
3. **Воспроизводимая сборка.** Один lock-файл → один и тот же артефакт в CI и
   на проде. Переменные окружения доезжают до того этапа, где они нужны.
4. **Ворота, проверяющие артефакт, а не только исходник.** Смотреть на то, что
   реально попало в `dist`, — единственный способ ловить дефекты класса ANL-001.

Разграничение прав доступа к Directus (SEC-007) — единственное изменение,
которое можно назвать архитектурным. Оно локализовано в `lib/directus.ts` и
конфигурации ролей.

## 20. Риски исправлений

| Что меняем | Что может сломаться | Как страхуемся |
|---|---|---|
| Коды ответов 404 → 503 | 503 там, где нужен честный 404 | Smoke: несуществующий slug при живой БД = 404 |
| Таймауты | Ложные ошибки на тяжёлом `limit: -1` | Начать с щедрого значения, снижать по метрикам |
| Удаление `public/*.xlsx` | Внешняя ссылка на файл | Проверено: ссылок в проекте нет; поиск по логам nginx |
| `--frozen-lockfile` | Сборка упадёт при рассинхроне | Уже проверено на стенде: проходит |
| Передача `PUBLIC_*` | Двойной счётчик | Проверка числа вхождений ID в HTML |
| Включение целей | Ничего: счётчик и его история не затрагиваются, цели лендингов пишутся без перерыва | Примечание в Метрике на дату правки, чтобы рост от нуля не читался как всплеск |
| Лимиты на `/api/` | Отсечка живых пользователей за NAT | Мягкие пороги, наблюдение за 429 |
| Удаление Tailwind | Незамеченная зависимость стилей | Побайтное сравнение CSS до/после + скриншоты |
| SVGO | Изменение внешнего вида иконок | `ops-screenshot` до/после, посписочная сверка |
| SEO-правки URL | Ухудшение индексации | Целевые URL не меняются — убирается только редирект |
| Разграничение токенов | Пустой каталог при ошибке в правах | Обкатка на стенде, готовый откат к одному токену |
| Обновление Astro | Что угодно | Отдельная ветка, полная регрессия, отдельное согласование |

**Общая страховка:** вся работа — в ветке `claude/biz-soft-technical-audit-iks9se`,
атомарными коммитами, любое изменение откатывается одним `git revert`.
Прод обновляется только push в `main`.

**После каждого коммита:** `pnpm test` · `pnpm typecheck` · `pnpm build` ·
smoke-набор из Phase 0.

динамика лидов в Directus, отчёты Вебмастера по исключённым страницам.
