# Ежедневный прогон конкурентной разведки (Routine)

Контур запускается Routine-триггером Claude Code. Если триггер или сессия
утеряны — создать заново из любой сессии этого репозитория по тексту ниже.

- **Текущий триггер:** `trig_01QVaQMBSrC3mgUj5z1GDM6o`, создан 31.08.2026.
- **Расписание:** cron `20 6 * * *` UTC = **09:20 МСК**, ежедневно.
  Время проекта — московское (правило CLAUDE.md); в cron пишется UTC.
- **Почему 09:20, а не 09:45.** Письмо должно быть у руководителя к 10:00.
  Прогон занимает около минуты, push в `competitive-data` запускает отправку
  немедленно — но само срабатывание Routine дрейфует: 31.08 базовый Routine
  с расписанием 09:00 отработал в 09:26. Запас в 40 минут делает так, что
  письмо приходит до 10:00 даже при дрейфе получаса.
- **Данные:** код в `main`, машинные данные — в orphan-ветке
  `competitive-data`; обмен только через
  `competitive-intelligence/storage/data_sync_ci.sh`.
- **Отправка:** push в `competitive-data` триггерит
  `competitive-intelligence-mail.yml`. Одно письмо на дату (маркер
  `reports/competitive/last-mailed.txt`), сторож в **10:40 МСК** шлёт
  уведомление, если письма за сегодня нет. Разрыв в 80 минут между
  Routine и сторожем взят под дрейф обоих расписаний: сторож,
  срабатывающий раньше конца прогона, слал бы ложную тревогу, и доверие к
  уведомлениям исчезло бы за неделю.

## Промпт триггера (копировать целиком)

```
Ежедневный прогон BIZSoft Competitive Intelligence. Код — в main, машинные данные — в orphan-ветке competitive-data; обмен только через competitive-intelligence/storage/data_sync_ci.sh. Отвечай по-русски.

ГРАНИЦЫ ПРОГОНА. Это операционный прогон, а не сессия разработки. Запрещено: коммитить в main; изменять .github/workflows/**; изменять CLAUDE.md, package.json, конфигурацию сборки и деплоя; изменять содержимое competitive-intelligence/**, scripts/** и src/**; коммитить в competitive-data что-либо вне data/competitive и reports/competitive; сливать pull request; менять настройки Routine, секреты, цены, домены, рекламные кабинеты; запускать платные закупки SERP сверх штатного прогона.

Если обнаружена проблема кода, workflow или инфраструктуры — НЕ чини её. Опиши в отчёте: симптом, доказательство, предлагаемое решение. Затем продолжи прогон. «Так будет быстрее» не основание отступать от границ.

1) Подготовка:
   git fetch origin main seo-data competitive-data
   git checkout main && git pull
   bash competitive-intelligence/storage/data_sync_ci.sh pull

2) Прогон (одна команда, всё детерминировано):
   python3 competitive-intelligence/run_daily.py
   Скрипт печатает покрытие, число доменов, Threat-лидера, число кандидатов в атаку и размер письма. Код возврата 1 означает, что данных нет или письмо не прошло лимит: в этом случае НЕ пушь результат — письмо не должно уйти. Опиши причину в отчёте.

3) Тесты обязаны быть зелёными, иначе не пушь:
   python3 -m unittest discover -s competitive-intelligence/tests -t competitive-intelligence/tests -p 'test_*.py'

4) Отправка (только если шаги 2 и 3 прошли):
   bash competitive-intelligence/storage/data_sync_ci.sh push "Прогон конкурентной разведки за <дата>"
   Push автоматически запускает workflow competitive-intelligence-mail.yml, который и отправляет письмо. Отдельных действий для отправки не требуется. Убедись, что push прошёл успешно (скрипт печатает «отправлено в competitive-data»).

5) Короткий отчёт в чат: вердикт, B2B Share, число кандидатов в атаку, главный сигнал, прошёл ли push. Если чего-то не хватило в данных — скажи прямо, не заполняй пробел догадкой.

ЧЕГО НЕ ДЕЛАТЬ В ОТЧЁТЕ: не называть причину изменения, если она не подтверждена данными; не выдавать прокси-величины за измеренные; не показывать NO DATA как ноль; не сравнивать позиции Яндекса и Google как равноточные (у Google нет геотаргетинга РФ, данные собираются через прокси-локацию).
```

## Что делает прогон

1. **Покрытие.** Читает срез выдачи Яндекса из ветки `seo-data` (read-only —
   эти снимки уже оплачены базовым контуром и повторно не покупаются).
2. **Discovery.** Строит реестр доменов с позициями, взвешенной видимостью и
   категорией; дописывает в append-only реестр и сохраняет снимок дня.
3. **Threat.** Считает угрозу конкурентов: уровень плюс динамика, где она
   доступна.
4. **Strike List.** Отбирает точки атаки: BIZSoft на 4–20 позиции, выше —
   конкурент из основного рейтинга, запрос коммерческий.
5. **Письмо.** Собирает пять блоков (вердикт, KPI, главный сигнал, что делать,
   за чем следим) в пределах 1000 видимых символов.

Прогон полностью детерминирован: LLM-шагов внутри нет, поэтому результат
воспроизводим и не зависит от формулировок.

## Ограничение сессий Routine

Сессии, запускаемые этим триггером, **не получают MCP-коннекторы** (в том
числе GitHub MCP): триггер создан из сессии, которая не могла их передать.
Поэтому промпт не полагается на них — отправка письма происходит по
push-триггеру workflow автоматически, а о проблемах прогон сообщает в отчёте,
а не заводит issue. Если понадобится, чтобы прогон сам работал с GitHub API,
триггер нужно пересоздать из интерфейса Routines на claude.ai.
