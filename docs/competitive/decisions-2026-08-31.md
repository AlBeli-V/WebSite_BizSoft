# Решения руководителя по контуру конкурентной разведки

Дата: 31.08.2026. Приняты после аудита `docs/competitive/audit-2026-08-30.md`
и трёх проб доступа к DataForSEO. Действуют во всех сессиях и ветках.

## 1. Провайдер Google SERP: DataForSEO

Выбран вместо предложенного в аудите Serper.dev. Секреты `DATAFORSEO_LOGIN`
и `DATAFORSEO_PASSWORD` заведены и проверены (`ci-serp-probe`, 31.08).
Баланс на момент подключения — $51.

## 2. Вес поисковых систем: Яндекс ежедневно, Google еженедельно

Основание — факты, а не предположение:

- **Яндекс** (срез 30.08, 150 запросов, Москва): biz-soft.pro в TOP-10 по
  94 запросам, в TOP-3 — по 28. Взвешенная видимость 5,4%.
- **Google** (проба 31.08, «купить figma»): biz-soft.pro **отсутствует в
  TOP-20**.

Поэтому Tier 1 ежедневно снимается только по Яндексу (через уже работающий
`seo-serp-watch`, read-only + докупка дельты). Google собирается **раз в
неделю** по узкому коммерческому ядру: этого достаточно, чтобы видеть, кто
там забирает наш спрос, и не тратить бюджет на ежедневную фиксацию нуля.
Отсутствие BIZSoft в Google — отдельный самостоятельный сигнал, который
письмо обязано показывать явно, а не прятать за прочерком.

## 3. Бюджет DataForSEO: hard cap $20/мес

Автосокращение объёма при 80% потолка, полная остановка закупок при 100% —
никогда молча, всегда со строкой-предупреждением в письме. Учёт — по
append-only журналу `data/competitive/ledger/google-<YYYY-MM>.jsonl`
(по образцу журнала `seo-serp-watch`).

Фактические цены, замеренные пробами (аудит содержал оценку $0,002 — она
уточнена): live/advanced — **$0,004** за запрос. Регулярный сбор идёт через
очередь **task_post/task_get (standard)**, live остаётся только для проб.

## 4. Гео Google для России: прокси-локация

**Локаций России в справочнике Google у DataForSEO — ноль** (Google удалил
геотаргетинг РФ). Доступны Беларусь (17 локаций), Казахстан (369),
Киргизия (76), США (62 864).

Решение: снимать Google через **ближайшую доступную русскоязычную локацию +
`language_code=ru`**. Проба через Беларусь дала корректную русскоязычную
выдачу с российскими сайтами (plati.market, ggsel.net, migsoft.ru,
kupikod.com, vc.ru, payment.mts.ru) — прокси работает.

**Обязательная методическая пометка:** региональной точности по РФ в Google
не существует ни у одного провайдера. В каждом отчёте и письме Google-данные
маркируются как «прокси-гео», выбранная локация фиксируется в конфиге
`competitive-intelligence/scoring/config.json`. Сравнивать Google-позиции с
Яндекс-позициями как равноточные запрещено.

## 5. DataForSEO Labs: сначала проба, потом решение

Labs (`competitors_domain`, `ranked_keywords`, `domain_intersection`) может
дать список конкурентов и их полный поисковый след одним вызовом — вместо
снятия тысяч SERP. Но Labs работает по собственной базе DataForSEO, и её
покрытие русскоязычного Google при отсутствующей локации РФ не гарантировано.

**Проба выполнена 31.08, вердикт: Labs не используется.** Факты
(`ci-labs-probe`, два прогона, потрачено $0,085):

- в справочнике Labs 94 локации; **России, Беларуси и Киргизии в нём нет**,
  из подходящих доступен только Казахстан (2398, с русским языком);
- контрольный вызов (`ranked_keywords` по figma.com, США/en) вернул
  **172 489 ключей** — метод рабочий, доступ есть, ответ читается верно;
- по biz-soft.pro и raketapay.ru в казахстанской базе — `total_count: null`,
  `items: null`; `competitors_domain` по нашему домену — `total_count: 0`.

Контроль отделил «база пуста» от «ошибка вызова»: метод работает, а данных по
русскоязычному рынку в базе нет. Причина та же, что и у live-выдачи, — у
Google нет локации РФ, и в казахстанскую базу российские домены не попадают.

**Следствие:** discovery конкурентов, Vendor/Product overlap и весь
конкурентный след строятся на **собственных SERP-снимках**, как и было
заложено в аудите. Labs в контуре не применяется; повторно проверять его
имеет смысл только если DataForSEO объявит о появлении локации РФ.

## 6. Deep report: защита токен-путём, без basic auth

Как у действующего SEO-отчёта: непубличный путь со случайным токеном,
`X-Robots-Tag: noindex, nofollow`, ссылок с сайта нет.
Секрет `CI_REPORT_PASSWORD` не заводится, basic auth не настраивается.

Адрес: **`https://biz-soft.pro/ci-c98370a0ebe87d97/latest.html`**, архив по
датам — `/ci-c98370a0ebe87d97/archive/<дата>.html`. Каталог на сервере
`/opt/bizsoft/ci-reports/` отдельный от `seo-reports`: конкурентная
аналитика чувствительнее обычной SEO-статистики. Выкладку делает
`ci-publish-report.yml` на каждый push отчёта.

Принятый риск: у знающего URL доступ есть без пароля. Ссылка передаётся
только в письме руководителю; при подозрении на утечку токен пути меняется
одним ops-запуском.

## Что это меняет в плане фаз

Фазы 1–5 из аудита сохраняются, с уточнениями:

- **Phase 1**: baseline Яндекса — полный; Google — узкое коммерческое ядро,
  еженедельно. Discovery — на собственных SERP-снимках (решение 5).
- **Phase 3**: пункт про basic auth снимается (решение 6); остаётся архив
  дат и токен-путь.
- **Phase 4**: verified Vendor/Product overlap закрывается собственным
  краулингом ≤15 доменов, как и планировалось; сокращения объёма за счёт
  Labs не будет.
