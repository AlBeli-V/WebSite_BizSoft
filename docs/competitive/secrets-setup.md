# Секреты для контура конкурентной разведки: как завести и где взять токены

Дата: 30.08.2026. Дополнение к `docs/competitive/audit-2026-08-30.md` (§3–§4).
Все секреты заводятся в одном месте:

> GitHub → репозиторий `AlBeli-V/WebSite_BizSoft` → **Settings → Secrets and
> variables → Actions → New repository secret** → имя строго как в таблице,
> значение — токен целиком, без кавычек и пробелов по краям.

Проверить, что секрет заведён, можно на той же странице (значение GitHub
никогда не показывает — только имя и дату). Изменить = завести заново с тем
же именем.

## Сводная таблица

| Секрет | Зачем | Статус | Срочность |
|---|---|---|---|
| `SERPER_API_KEY` **или** `XMLRIVER_USER`+`XMLRIVER_KEY` | Google SERP | ❌ нет | нужен для Google-части; без него Phase 1 стартует только по Яндексу |
| `YC_BILLING_SA_KEY` | факт расхода Yandex Cloud (SERP+Wordstat) | ❌ нет | желательно; без него бюджет живёт на расчётной оценке |

| `WORDSTAT_API_KEY`, `GSC_SERVICE_ACCOUNT_JSON`, `YANDEX_WEBMASTER_TOKEN`, `YANDEX_METRIKA_TOKEN`, `YANDEX_METRIKA_COUNTER_ID`, `GA4_PROPERTY_ID`, `SMTP_PASS`, `SSH_KEY/HOST/USER` | всё остальное | ✅ уже есть | трогать не надо |

## 1. Google SERP — два варианта, нужен один

### Вариант А: Serper.dev (дешевле, но оплата зарубежной картой)

1. Зайти на <https://serper.dev> → **Sign up** (почта или Google-аккаунт).
2. После регистрации даётся бесплатный стартовый пакет кредитов — его хватит
   на проверку интеграции и первые дни Tier 1.
3. Дашборд → **API Key** → скопировать ключ.
4. Оплата: Dashboard → Billing → купить пакет кредитов (ориентир на момент
   аудита: ~$1 за 1000 запросов, минимальный пакет $50 = 50 000 кредитов;
   при нашем hard cap 20 000/мес пакета хватает на ~2,5 месяца). **Нужна
   карта, работающая с зарубежными сервисами.**
5. Завести секрет **`SERPER_API_KEY`** = скопированный ключ.

### Вариант Б: XMLRiver (оплата в рублях)

Если зарубежной карты нет — российский агрегатор выдачи Google/Яндекс.

1. Зайти на <https://xmlriver.com> → регистрация.
2. Пополнить баланс (принимают рубли; тариф уточнить на сайте — порядок
   ~30–50 ₽ за 1000 запросов Google, т.е. при 14 500 зап/мес ≈ 450–750 ₽/мес).
3. В личном кабинете взять два значения: **user id** и **key** (они
   подставляются в URL запроса).
4. Завести два секрета: **`XMLRIVER_USER`** = user id, **`XMLRIVER_KEY`** = key.

В Phase 1 код будет поддерживать того провайдера, чьи секреты заведены;
если заведены оба — приоритет у Serper (стабильнее формат). Решение, какой
вариант выбран, достаточно сообщить в любой сессии.

## 2. `YC_BILLING_SA_KEY` — факт расхода Yandex Cloud

Даёт бюджетному контуру (`yc_billing.py`, уже внедрён в базовом контуре и
будет переиспользован CI) реальный остаток и тарифы вместо расчётной оценки.
Только чтение — менять платежи/реквизиты роль не позволяет.

1. Консоль Yandex Cloud (<https://console.yandex.cloud>) → каталог, где живёт
   ключ Wordstat → **Сервисные аккаунты** → выбрать существующий сервисный
   аккаунт (или создать отдельный, например `billing-reader`).
2. У аккаунта: **Создать новый ключ → Авторизованный ключ** (Authorized key,
   не API-ключ и не статический ключ!) → скачать JSON-файл.
3. Консоль → **Биллинг** → выбрать платёжный аккаунт → **Права доступа** →
   **Назначить роли** → добавить этот сервисный аккаунт → роль
   **`billing.accounts.viewer`**.
4. Завести секрет **`YC_BILLING_SA_KEY`** = содержимое скачанного JSON
   **целиком** (весь файл, со всеми фигурными скобками).
5. Проверка: запустить workflow `seo-serp-watch` вручную с ветки **main** —
   шаг биллинга перестанет тихо пропускаться, в `seo-data` появится
   `reports/seo/intelligence/cloud-billing.json`.

## 3. `CI_REPORT_PASSWORD` — basic auth для deep report

Deep report — конкурентная аналитика, токен-пути в URL недостаточно.

1. Придумать пароль (или сгенерировать: `openssl rand -base64 18` /
   любой генератор; ≥16 символов).
2. Завести секрет **`CI_REPORT_PASSWORD`** = пароль в открытом виде.
   Хэш `htpasswd` из него сделает ops-workflow прямо на сервере (openssl там
   есть) — руками ничего хэшировать не нужно. Логин будет фиксированный: `ci`.
3. Пароль сохранить у себя: он вводится один раз в браузере при открытии
   отчёта (браузер запомнит).

## 4. `YANDEX_OAUTH` — переобход в Вебмастере (проверить)

По журналу issue #22 от 18.08 секрета не было («токен НЕ НАЙДЕН»). Если с тех
пор не заведён — атаки CI нельзя будет быстро отправлять на переобход.

1. Зайти на <https://oauth.yandex.ru> под аккаунтом, которому принадлежит
   сайт в Вебмастере → **Создать приложение**.
2. Платформа: «Веб-сервисы», Redirect URI — подставить
   `https://oauth.yandex.ru/verification_code`.
3. Доступы: отметить **«Яндекс.Вебмастер»** (webmaster:verify / webmaster —
   как показано в списке).
4. После создания открыть в браузере:
   `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ID приложения>`
   → разрешить → скопировать токен со страницы.
5. Завести секрет **`YANDEX_OAUTH`** = токен.
6. Проверка: запустить `ops-yandex-recrawl` с main с одним URL — в issue #22
   должна появиться квота (150 URL/сутки), а не «токен НЕ НАЙДЕН».

## Проверка после заведения (всё — запуском workflow с ветки main)

| Секрет | Как проверить |
|---|---|
| Google SERP | проверочный workflow `ci-serp-probe` появится первым шагом Phase 1 (аналог `ops-serp-probe`: один запрос, результат в issue #22) |
| `YC_BILLING_SA_KEY` | ручной запуск `seo-serp-watch` → файл `cloud-billing.json` в `seo-data` |
| `CI_REPORT_PASSWORD` | используется в Phase 3 при настройке nginx |
| `YANDEX_OAUTH` | ручной запуск `ops-yandex-recrawl` → квота в issue #22 |

Напоминание: ручной запуск любого production-workflow — только с ветки
**main** (поле «Use workflow from»), это правило проекта.
