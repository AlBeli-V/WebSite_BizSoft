# Методика конкурентной разведки BIZSoft

Документ для внешнего аудита качества. Описывает, какие показатели
собираются и откуда, как они обрабатываются и вычисляются, как устроены оба
уровня представления информации, в каком порядке идёт погружение и по каким
правилам формируются управленческие решения.

Версия конфигурации: 1.0.0 · дата: 31.08.2026 · контур: отдельный от
базового SEO-конвейера.

---

## 1. Что это за система и чего она не делает

Система отвечает на пять вопросов ежедневно: усиливается ли BIZSoft в
коммерческой B2B-выдаче, кто забирает потенциальные сделки, на каких
запросах, где позиции конкурентов уязвимы и какие действия быстрее всего
перераспределят видимость в нашу пользу.

**Границы, заданные принципиально.** Система только наблюдает и
рекомендует: сайт не меняется автоматически, порядок работы —
наблюдение → анализ → рекомендация → проверка → измерение. Не используется
обход капчи, авторизации и антибот-защит; краулинг конкурентов ограничен
пятнадцатью доменами с соблюдением robots и задержек. Демпинг не
предлагается, причинно-следственные утверждения без данных не делаются.

**Ключевое ограничение достоверности.** Главный показатель — доля
взвешенной поисковой видимости. Это **не доля рынка, не доля трафика и не
доля выручки**. Он измеряет присутствие в контролируемом наборе
коммерческих запросов, взвешенное по вероятности клика.

## 2. Сбор данных: что, откуда, с какой периодичностью

### 2.1 Источники и их роли

| Источник | Что даёт | Как получаем | Периодичность |
|---|---|---|---|
| Яндекс, выдача TOP-20 | позиции всех доменов по коммерческим запросам | Yandex Cloud Search API (deferred-режим), собирает базовый SEO-контур | ежедневно, 01:37 МСК |
| Google, выдача | то же для Google | DataForSEO SERP API | еженедельно (не запущено) |
| Яндекс.Вебмастер | показы наших запросов — запасная мера спроса | API v4, собирает базовый контур | ежедневно |
| Яндекс.Wordstat | частотность запросов — основная мера спроса | Yandex Cloud API, собирает базовый контур | ежедневно |
| Directus | каталог: вендоры, товары, цены | REST через SSH | по требованию |
| Яндекс.Метрика, GA4 | калибровка выручки, проверка эффекта | API | не подключено (этап 5) |

### 2.2 Принцип неповторной закупки

Срезы выдачи Яндекса **читаются из хранилища базового SEO-контура только на
чтение** (`git show origin/seo-data:...`). Контур конкурентной разведки не
покупает те же снимки повторно и не пишет в чужое хранилище. Докупаются
только данные, которых там нет: Google и, при необходимости, дополнительные
регионы.

Экономический контроль: жёсткий месячный потолок 20 долларов на Google,
автоматическое сокращение объёма при достижении 80% и полная остановка
закупок при 100%, с обязательным предупреждением в письме. Учёт ведётся по
журналу дозаписи, повторный запуск в тот же день не удваивает расход.

### 2.3 Ограничение по географии Google

У Google **отсутствует геотаргетинг России** — локаций РФ нет ни в
live-выдаче, ни в базе провайдера (проверено контрольным вызовом 31.08:
метод работает, по российским доменам данных нет). Google снимается через
ближайшую доступную русскоязычную локацию. В каждом отчёте это помечается;
**сравнивать позиции Яндекса и Google как равноточные запрещено**.

### 2.4 Обращение с отсутствующими данными

Отсутствие данных никогда не превращается в ноль. Сбой источника
записывается как ошибка в отдельном поле и исключается из расчётов, а не
занижает чью-либо видимость. В интерфейсах пишется «нет данных» словами.

Практический случай: 31.08 сбор базового контура вернул ошибку по всем 502
запросам. Система не показала это как обвал видимости и не промолчала —
письмо ушло с вердиктом «недостаточно данных» и прямым указанием причины,
даты сбоя и того, за какое число показаны цифры.

## 3. Обработка и вычисления

### 3.1 Взвешенная видимость — базовая величина

Для каждого домена на каждой позиции берётся вес по зафиксированной кривой
CTR и суммируется по всем запросам среза:

```
видимость(домен) = Σ  CTR_вес(позиция) × коэффициент_SERP_элементов
                     × вес_спроса × коммерческий_интент × B2B_интент
```

Кривая CTR (доля кликов по позиции): 1-е место — 0,28; 2-е — 0,15;
3-е — 0,10; 5-е — 0,05; 10-е — 0,018; 20-е — 0,004; вне ТОП-20 — ноль.
Кривая вынесена в конфигурацию, а не зашита в код, и подлежит калибровке по
фактическим показам и кликам, когда накопится история.

Коэффициент SERP-элементов понижает органический CTR, когда выдачу занимают
крупные блоки: AI-ответ — 0,6; товарная галерея — 0,75; быстрый ответ — 0,8.
Берётся сильнейший из присутствующих, а не произведение — иначе получился бы
двойной счёт.

Множители спроса и интента по умолчанию нейтральны (равны единице), пока
разметка не подключена; текущий расчёт помечен как «базовый».

**Доля видимости** = видимость домена ÷ суммарная видимость поля.
При пустом поле возвращается «нет данных», а не ноль.

**Наш домен исключён из всех конкурентных срезов**: доли категорий
показывают, сколько держат конкуренты, наша доля стоит отдельной величиной.
Поэтому сумма долей категорий меньше 100%.

### 3.2 Классификация доменов

Восемь категорий: прямые B2B-реселлеры, малые B2B-реселлеры, крупные
интеграторы, профильные реселлеры, B2C и маркетплейсы, официальные сайты
вендоров, информационные площадки, платёжные посредники.

Категория «платёжные посредники» добавлена к исходному заданию по факту
наблюдения: по срезу 30.08 эта группа держит 31,9% взвешенной видимости —
больше, чем все B2B-реселлеры вместе, — и перехватывает тот же коммерческий
интент.

**В основной конкурентный рейтинг входят** первые четыре категории и
платёжные посредники. B2C, информационные площадки и официальные сайты
вендоров остаются в данных и в отчёте (они забирают клики), но не могут
стать «главным конкурентом»: с ними мы не конкурируем за сделку.

Домены официальных сайтов подтягиваются из реестра вендоров сайта, чтобы не
вести второй список. Неопознанные домены помечаются как «не
классифицировано» и в рейтинг молча не попадают — на срезе 30.08 таких 137
из 234.

### 3.3 B2B Confidence Score (0–100)

Оценка того, умеет ли конкурент продавать юридическим лицам. Сумма весов
сработавших сигналов на его страницах, ограниченная сотней: оплата по счёту
— 18, договор — 12, закрывающие документы — 12, НДС — 10, ЭДО — 10, реквизиты
— 8, запрос КП — 8, корпоративное лицензирование — 10, тарифы для команд — 8,
формулировки про юридических лиц — 14, безналичный расчёт — 8, персональный
менеджер — 4, тендеры — 6.

Порог основного пула — 60. Оценка объяснима: в карточке хранятся
сработавшие сигналы и адреса страниц-доказательств. Переоценка не реже
одного раза в 30 дней. **Сейчас не вычисляется**: требует обхода страниц
конкурентов, запланирован отдельным этапом; в интерфейсах стоит «нет
данных», а не ноль.

### 3.4 Threat Score (0–100) — насколько конкурент опасен сейчас

Складывается из уровня и динамики: доля видимости — до 40 баллов,
присутствие в ТОП-3 — до 20, в ТОП-10 — до 10, рост доли за сутки — до 30.
Насыщение по доле наступает на 15% (уровень безусловного лидера поля), по
росту — на 2 процентных пункта за сутки.

Пока истории меньше двух сравнимых дней, динамическая часть недоступна.
**Её вес не перераспределяется молча** на остальные слагаемые — вместо
этого уверенность оценки понижается до низкой, и это указывается в
интерфейсе вместе с причиной.

### 3.5 Разметка интента запроса (0–1)

Два независимых измерения.

**Коммерческий интент**: маркеры покупки (купить, оплата, цена, тариф,
подписка, лицензия, продление, счёт и другие). Один маркер даёт 0,7, два и
более — 1,0. Информационные маркеры («как», «что», «обзор», «аналоги»,
«бесплатно») понижают результат на 40%, но не обнуляют: «как купить figma
для компании» остаётся покупательским запросом.

**B2B-интент**: сильные маркеры (юридическое лицо, по счёту, безнал, НДС,
закрывающие, ЭДО, договор, тендер, корпоративный) дают полный вес; слабые
(business, team, enterprise, для компании) — половину, потому что «business»
чаще относится к названию тарифа, чем к покупателю.

Брендовые запросы BIZSoft исключаются из конкурентного поля.

### 3.6 Измерение спроса и две шкалы

Основной источник — частотность Wordstat. На срезе 30.08 она покрыла лишь
7 запросов из 150 (ядро мониторинга строится в том числе из запросов
Вебмастера, которых в базе Wordstat нет).

Поэтому подключён запасной источник — показы Яндекс.Вебмастера, покрывшие
143 запроса. **Шкалы нормируются раздельно**: насыщение по частотности
Wordstat — 1000, по показам Вебмастера — 200. Это принципиально: частотность
меряет весь рынок за месяц, показы — только ту его часть, где нас уже видно,
за две недели. Источник указывается в каждой строке; смешивать их молча
нельзя.

Отсутствие данных о спросе даёт нейтральное значение 0,5, а не ноль:
незнание и отсутствие спроса — разные вещи.

### 3.7 Business Opportunity Score (0–100)

Основной показатель выбора цели. Полный состав весов: выручка — 20%,
коммерческий интент — 15%, B2B-интент — 15%, близость позиции — 15%,
спрос — 10%, уязвимость конкурента — 10%, запас улучшения страницы — 10%,
приоритет вендора — 5%.

**Режим деградации действует сейчас и обязателен.** Уязвимость конкурента
требует обхода его страниц, которого ещё нет. Её вес перераспределён на
факторы, измеряемые достоверно: близость позиции получает 21%, запас
улучшения страницы — 14%. **Уверенность при этом не может быть выше
средней** — это защита от того, чтобы неполный расчёт выдавался за полный.

Близость позиции: 4-е место и выше — максимум; далее линейное убывание до
20-го; вне ТОП-20 — ноль (с такого разрыва одной правкой страницы не
доходят).

Запас улучшения страницы: страница есть и стоит ниже третьего места —
максимум (правка даёт эффект быстрее создания новой); страница в ТОП-3 —
0,2 (улучшать почти нечего); страницы нет — 0,5 (потенциал есть, но дороже).

Выручка считается **прокси-величиной** (спрос × коммерческий интент) и
всюду помечена как прокси. Калибровка по фактическим конверсиям Метрики и
GA4 — отдельный этап.

### 3.8 Отбор точек атаки

Кандидатом становится запрос, где одновременно: BIZSoft на позиции с 4-й по
20-ю, выше нас стоит конкурент **из основного рейтинга** в пределах ТОП-10,
запрос коммерческий и не брендовый.

Намеренно не кандидаты: запросы, где мы уже в ТОП-3 (отбирать нечего); где
выше только маркетплейсы и информационные площадки (мы не конкурируем с ними
за сделку); где нас нет в ТОП-20 вовсе (это работа по созданию страниц, а не
атака).

На срезе 30.08 из 150 запросов отобрано 59 кандидатов.

### 3.9 Пакеты работ — единица управленческого решения

Пятьдесят девять точек атаки невозможно поручить: это витрина, а не задача.
Поэтому они сводятся в пакеты по **странице**: одна доработка закрывает
несколько запросов сразу, и именно её можно поручить и принять.

Для каждого пакета вычисляется:

- охват: сколько запросов закрывает и каков их суммарный спрос;
- текущий диапазон позиций и список конкурентов выше нас;
- **ожидаемый прирост переходов**: Σ (вес_ТОП-3 − вес_текущей_позиции) ×
  спрос по каждому запросу группы. Это оценка потенциала при выходе в
  тройку, а не обещание — так и подписано;
- трудоёмкость: до трёх запросов — малая, до шести — средняя, далее большая;
- уверенность: берётся худшая из оценок группы;
- конкретное действие и чеклист приёмки.

Формулировки действий привязаны к типу страницы (страница вендора, карточка
товара, статья) и всегда конкретны. Формулировки вида «улучшить SEO» и
«усилить контент» запрещены и **проверяются автоматическим тестом**: их
нельзя поручить и нельзя принять.

Порядок пакетов — по убыванию ожидаемого прироста.

### 3.10 Фильтр значимости изменений

Чтобы шум не выдавался за сигнал: значимым считается вход или выход из
ТОП-3, вход или выход из ТОП-10, сдвиг на три позиции и более внутри ТОП-10,
сдвиг на пять и более в диапазоне 11–20. Сравниваются медианы трёх последних
измерений против трёх предыдущих. Изменение доли меньше 0,5 процентного
пункта считается шумом и не меняет вердикт.

## 4. Представление информации: два уровня

Разделение принципиальное: **письмо — это решение, отчёт — объяснение**.

### 4.1 Первый уровень: ежедневное письмо (10:00 МСК)

**Верхний экран — до 1000 видимых символов**, пять блоков в неизменном
порядке:

1. **Вердикт** одной строкой: усиливаемся · нейтрально · ухудшение ·
   недостаточно данных. При отсутствии сравнимого прошлого вердикт всегда
   «недостаточно данных» — система, объявляющая рост на второй день
   наблюдений, обесценивает собственный сигнал.
2. **Показатели**: доля видимости в Яндексе и Google, число запросов в ТОП-3
   и ТОП-10, дельты к сравнимому дню.
3. **Главный сигнал** — ровно один. Есть история — самое значимое изменение,
   прошедшее фильтр значимости; истории нет — структурный факт о поле (кто
   его держит), что в первые дни и есть самая ценная информация.
4. **Что делать** — одно поручение, сформулированное через пакет работ:
   какая страница, сколько запросов закроет, какой спрос, что даст, какая
   трудоёмкость. Высокая возможность с низкой уверенностью главным действием
   не становится.
5. **За чем следим** — одна угроза.

**Ниже верхнего экрана — детализация** (в лимит не входит, по решению
руководителя должна быть не беднее ежедневного SEO-письма):

- что поручить: три пакета работ с охватом, эффектом, трудоёмкостью и
  чеклистом приёмки;
- варианты действий: минимум, оптимум, полный охват — с объёмом и отдачей
  каждого, чтобы решение принималось из альтернатив;
- показатели с источником и оценкой достоверности;
- кто держит выдачу: доли категорий с визуальными полосами;
- кто давит сильнее всего: конкуренты с уровнем угрозы;
- где ближе всего рост: пять точек атаки;
- **что система пока не знает** — обязательный блок, чтобы цифры не
  читались шире, чем они есть.

Текстовая версия письма содержит то же самое: клиент без HTML не получает
обрубок.

Графика выполнена средствами HTML и CSS, а не изображениями: почтовые
клиенты блокируют внешние картинки, а вложения требуют сборки в прогоне.
Линейные графики динамики появятся, когда накопится история — рисовать
тренд по одному дню значило бы показать декорацию вместо данных.

Анти-повтор: сравниваются хэши главного сигнала и действия с предыдущим
днём. Повторение того же невыполненного поручения допустимо с указанием
срока, полный повтор письма без причины считается дефектом.

### 4.2 Второй уровень: deep report

Отдельная страница по непубличному адресу с запретом индексации, ссылок с
сайта нет. Ежедневные снимки сохраняются неизменяемыми в архиве по датам.

Порядок погружения — от общего к частному, шесть уровней:

1. **Итоги дня**: показатели с дельтами, число точек атаки, зрелость расчёта
   с явным перечнем ограничений; кто держит выдачу по категориям.
2. **Конкуренты по уровню угрозы**: полная таблица с долей, позициями,
   Threat и **основанием оценки** — почему именно такая уверенность.
3. **Карточки конкурентов**: по каждому — на каких запросах виден, какими
   страницами ранжируется, лучшая позиция, число появлений. Это материал для
   разбора: что у них на странице есть такого, чего нет у нас.
4. **План работ**: все пакеты с раскрытием — что и где, оценка эффекта с
   пояснением расчёта, чеклист приёмки, полный список закрываемых запросов.
5. **Точки атаки**: полная таблица всех кандидатов и разбор первых десяти в
   формате факт → расчёт → вероятно → что сделать.
6. **Исходные данные**: строки выдачи, на которых всё построено, и раздел
   методики с честным перечнем того, чего система не делает.

### 4.3 Маркировка утверждений

В отчёте каждое существенное утверждение помечено уровнем достоверности:
**факт** (наблюдение из данных), **расчёт** (вычисленная величина),
**вероятно** (обоснованное предположение), **гипотеза** (требует проверки),
**что сделать** (рекомендация). Причина изменения либо подтверждена
перечисленными запросами и страницами, либо не называется вовсе.

## 5. Как определяются управленческие воздействия

### 5.1 Последовательность решения

1. **Проверка покрытия данных.** Неполные данные → вердикт «недостаточно
   данных», письмо всё равно отправляется, сильные выводы не делаются.
2. **Пересчёт долей видимости** по всем доменам поля.
3. **Выделение значимых изменений** через фильтр волатильности.
4. **Пересчёт угрозы конкурентов** с учётом доступности динамики.
5. **Отбор точек атаки** по критериям 3.8.
6. **Сведение в пакеты работ** и расчёт ожидаемого эффекта.
7. **Выбор главного сигнала** — ровно одного.
8. **Выбор поручения**: пакет с наибольшим ожидаемым приростом при
   приемлемой уверенности.
9. **Формирование вариантов** действий с разной ценой и отдачей.
10. **Гейты качества** перед отправкой.

### 5.2 Правила, ограничивающие рекомендации

- Рекомендация с низкой уверенностью не становится главным действием, каким
  бы высоким ни был расчётный потенциал.
- Действие формулируется через страницу и конкретные пункты работ;
  обобщённые формулировки запрещены и проверяются тестом.
- Прирост подаётся как оценка потенциала при условии выхода в ТОП-3, а не
  как обещание результата.
- Действие не предлагается только потому, что так делает конкурент.
- Изменения сайта проходят обычный порядок: предложение → решение
  руководителя → правка через pull request → проверка → измерение.

### 5.3 Гейты качества перед отправкой

Письмо не уходит, если: превышен лимит верхнего экрана; главный сигнал не
ровно один; вердикт не проставлен; отсутствуют файлы письма. При
непройденном гейте отправляется уведомление о сбое, а не письмо с дефектом.
Дополнительно: тесты обязаны быть зелёными, иначе результат не публикуется.

### 5.4 Контроль исполнения

Прогон выполняется ежедневно в 09:20 МСК, письмо доставляется к 10:00.
Сторожевой механизм в 10:40 отправляет уведомление, если письма за сегодня
нет. Разрыв в 80 минут выбран по замеру реального дрейфа расписаний
(зафиксирован случай задержки на 26 минут): сторож, срабатывающий раньше
конца прогона, слал бы ложные тревоги, и доверие к уведомлениям исчезло бы.

Одно письмо на одну дату: повторный запуск не приводит к повторной отправке.

## 6. Проверяемость и текущая зрелость

### 6.1 Автоматические проверки

110 автоматических тестов, выполняются в непрерывной интеграции при каждом
изменении. Покрывают: монотонность кривой CTR; отсутствие данных как «нет
данных», а не ноль; изоляцию регионов; невозможность попадания нашего домена
в конкурентные срезы; невозможность для B2C и информационных площадок стать
главным конкурентом; понижение уверенности при неполном расчёте; лимит
символов; наличие ровно одного главного сигнала; запрет обобщённых
формулировок в поручениях; корректность расчёта прироста.

### 6.2 Что не реализовано и почему

| Не реализовано | Причина | Следствие для интерпретации |
|---|---|---|
| Уязвимость страниц конкурентов | требует их обхода | режим деградации, уверенность не выше средней |
| Выручка по запросам | нужна привязка к конверсиям | вместо денег показан прокси, помечен как прокси |
| Сбор Google | не запущен по решению | раздел показывает «нет данных» |
| Динамика и тренды | накоплен один день истории | вердикт «недостаточно данных», графики не строятся |
| B2B Confidence конкурентов | требует обхода страниц | в карточках «нет данных» |
| Память решений и эксперименты | следующий этап | нет отслеживания судьбы рекомендаций |

### 6.3 Известные допущения, требующие внимания аудитора

1. **Кривая CTR взята из усреднённых публичных исследований**, а не
   откалибрована по нашим данным. Это влияет на абсолютные значения долей,
   но слабо влияет на ранжирование конкурентов между собой.
2. **Показы Вебмастера используются как мера спроса** при отсутствии
   частотности. Это разные величины; нормировка разведена, источник
   указывается, но природа величин остаётся разной.
3. **Категория домена определяется по спискам и признакам URL.** Из 234
   доменов среза 137 остались неклассифицированными — они честно исключены
   из рейтинга, но это означает неполноту картины поля.
4. **Оценка прироста переходов линейна** по спросу и не учитывает
   сезонность, конкурентную реакцию и изменение самой выдачи.
5. **Один день истории.** Все текущие значения — базовая линия, а не тренд.
