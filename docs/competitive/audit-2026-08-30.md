## 4. SERP-провайдер: выбор, стоимость Tier-модели, hard cap

**Яндекс — Yandex Cloud Search API v2 (уже подключён).** Тарифы: бесплатно
1 000 запросов/мес; deferred в ночное окно 00:00–07:59 МСК ≈ **25,41 ₽/1000**
(≈0,025 ₽/запрос); синхронный дневной ≈ 488 ₽/1000. Сторонний провайдер для
Яндекса не нужен: официальный API дешевле DataForSEO/SerpApi и уже оплачен.

**Google — нужен сторонний легальный SERP API.** Рекомендация: **Serper.dev**
(~$1/1000, минимальный пакет $50 = 50 000 кредитов) — самый дешёвый вход;
альтернатива DataForSEO (~$0,6–2/1000, сложнее интеграция), SerpApi (~$8–15/1000
— дорого). Нужны: решение руководителя, регистрация, новый секрет
`SERPER_API_KEY`. До появления ключа Google-часть = NO DATA (письмо это честно
помечает), система полноценно работает по Яндексу.

**Расчёт месячного объёма (Tier-модель на 20-м топе, до оптимизации):**

| Ярус | Объём | Частота | Яндекс (213+225) | Google (РФ) |
|---|---|---|---|---|
| Baseline «неделя ноль» (разово) | все ярусы ~2 800 запросов | 1 раз | 300×2 + 1000 + 1500 = 3 100 | 2 800 |
| Tier 1 | 300 | ежедневно | 300×2×30 = 18 000 | 9 000 |
| Tier 2 | ~1 000 | еженедельно | 4 000 | 4 000 |
| Tier 3 | ~1 500 | ежемесячно | 1 500 | 1 500 |
| **Итого/мес** | | | **23 500** | **14 500** |

Стоимость без переиспользования: Яндекс 23 500 × 0,0254 ₽ ≈ **597 ₽/мес**;
Google 14 500 × $0,001 ≈ **$14,5 ≈ 1 450 ₽/мес**. С учётом read-only чтения
ядра serp-watch (до 500 запросов Мск/день уже снимаются) Яндекс-докупка CI
сжимается ориентировочно до 10–15 тыс./мес ≈ **300–400 ₽/мес**.

**Предлагаемый hard cap (нужно утверждение):**

- Яндекс (докупка CI): **15 000 запросов/мес**, дневной потолок 600 — отдельный
  append-only журнал по образцу serp-watch (никогда не превышать молча);
- Google: **20 000 кредитов/мес ≈ $20**, дневной потолок 800;
- итого бюджет контура ≈ **2 000–2 500 ₽/мес**;
- при достижении 80% любого cap — автоматическое сокращение Tier 1 (даунгрейд
  частоты до «через день», отбрасывание хвоста по Opportunity) + строка-
  предупреждение в письмо; при 100% — остановка закупок до конца месяца.

## 5. Архитектура: storage, discovery, скоринг, Decision Engine

### 5.1 Storage

По образцу базового контура — код отдельно, данные отдельно:

- **Код** (`main`): `competitive-intelligence/{discovery,serp,competitors,
  scoring,crawling,pricing,assortment,attack-engine,decision-engine,reports,
  mailer,experiments,storage}/` — Python 3 + stdlib/requests, как весь конвейер.
- **Данные**: orphan-ветка **`competitive-data`** (создаётся по образцу
  `seo-data`; свой `storage/data_sync_ci.sh`, в `.gitignore` main добавляются
  пути). Внутри: `data/competitive/{raw,processed,history,snapshots}/`,
  `reports/competitive/{,archive/}`. История append-only, никаких перезаписей,
  все timestamp с таймзоной (`Europe/Moscow` явно).
- **Журналы расхода API**: `data/competitive/ledger/{yandex,google}-<YYYY-MM>.jsonl`.

### 5.2 Competitor discovery

Ежедневно из всех накопленных SERP-срезов (свои + read-only serp-watch):
домен-кандидат = появление в TOP-20 по ≥N коммерческих запросов поля.
Категории A–H из задания; классификатор стартует от seed-списков
`serp_analysis.py`, но ведёт собственный реестр
`data/competitive/competitors/registry.jsonl` (домен, категория, B2B Confidence,
evidence-URL, last_verified, история переоценок ≥1 раз/30 дней).

Реальность по срезу 30.08 (150 запросов, Москва): фактические лидеры видимости —
НЕ из старого списка реселлеров: raketapay.ru (10,0%), platipomiru.com (6,8%),
pipl.io (6,0%), finteka.io (3,4%) — «платёжные посредники»; из классических
B2B — syssoft.ru (2,1%), migsoft.ru (1,6%), legasoft.ru; softline/allsoft/softkey
в топ-10 не встретились вовсе. Discovery обязан ловить именно такие сдвиги.

B2B Classifier (0–100): сигналы из главной/страниц «оплата»/«для юрлиц»
конкурента (счёт, договор, НДС, ЭДО, ИНН/ОГРН, КП, team/enterprise, безнал…),
вежливый однократный fetch 2–3 страниц с соблюдением robots. Основной пул ≥60,
карточка объяснима (Detected signals + Evidence URLs).

### 5.3 Формулы Score (с режимом деградации)

- **Weighted Visibility** = CTR-вес позиции × вес спроса × Commercial Intent ×
  B2B Intent × Revenue Weight (нормировки и CTR-кривая фиксируются в
  `competitive-intelligence/scoring/config.json`; для запросов с крупными
  SERP-features/AI-блоком — понижающий коэффициент; Share воспроизводим).
- **Competitive Relevance 0–100** — вход в пул: общие запросы, общие кластеры,
  позиционная близость, B2B Confidence.
- **Threat 0–100** — уровень+динамика: Share, рост 30д, скорость новых страниц,
  TOP-3/TOP-10, overlap с high-revenue, Vendor/Product overlap (stage 1 —
  inferred по SERP с Phase 1; stage 2 — verified по краулингу с Phase 4).
- **Vulnerability 0–100** — только для URL-кандидатов Attack Engine и winning
  pages топ-конкурентов (не для всех страниц всех доменов).
- **Opportunity 0–100** = 20% Revenue + 15% Commercial Intent + 15% B2B Intent +
  15% Proximity + 10% Demand + 10% Vulnerability + 10% Page Improvement +
  5% Strategic Vendor Priority; фильтры Effort/Cost/Risk.
- **Деградация до Phase 4:** вес Vulnerability перераспределяется на Proximity
  и Page Improvement, Confidence автоматически ≤ MEDIUM, письмо помечается
  «Scoring: базовый». Revenue Potential до калибровки Метрикой/GA4 (Phase 5) —
  прокси из цены SKU × спрос, с пометкой в конфиге.

### 5.4 Daily Decision Engine (до 09:30 МСК)

Конвейер: Data Coverage → пересчёт Share → значимые изменения (фильтр
волатильности: медиана 3 последних против 3 предыдущих) → Threat →
Vulnerability (в объёме фазы) → Opportunity → статусы прошлых рекомендаций →
MAIN SIGNAL → DO NEXT → письмо → snapshot deep report. Неполные критические
данные → вердикт ⚪ DATA INCOMPLETE, письмо всё равно уходит. NO DATA ≠ 0.
Quality-гейты перед отправкой (лимит 1000 символов, один MAIN SIGNAL, анти-повтор
по хэшу, работающая ссылка, Яндекс/Google не смешаны, B2C не в основном
рейтинге) — по образцу гейтов письма V4.

Исполнение: расчёт — отдельная CI-Routine-сессия (клон паттерна
`reports/seo/TRIGGER.md`) в 08:40 МСК; доставка — `competitive-intelligence-mail.yml`
по push-триггеру + сторож 10:10 (расписания Actions дрейфуют — привязка к
Routine обязательна).

## 8. Механизм статусов рекомендаций (Decision Memory)

Хранилище: `data/competitive/decisions/decisions.jsonl` (append-only; статусы
NEW → ACCEPTED → IN PROGRESS → DONE → MEASURED → SUCCESS/NEUTRAL/FAILED,
плюс REJECTED c причиной и пересмотром через 90 дней, DEFERRED). Канал
обратной связи — три равнозначных способа:

1. **Кнопки в deep report** (Accept / Reject / Done у каждой Attack Card) —
   ссылки на `github.com/AlBeli-V/WebSite_BizSoft/issues/new` с предзаполненными
   title (`CI-DECISION: ACCEPT ATT-001`) и label `ci-decision`; руководитель
   нажимает «Submit» — ночной прогон читает такие issues, обновляет статусы и
   закрывает их. Без бэкенда на сайте, работает с телефона.
2. **CLI**: `python competitive-intelligence/decision-engine/status.py ATT-001 accepted "причина"` —
   для сессий Claude по команде руководителя.
3. **Ответ на письмо** — руководитель может просто написать в чат сессии;
   статус проставляется способом 2.

Без подтверждения статус остаётся NEW: рекомендация показывается со счётчиком
«в бэклоге N дней», но не чаще 1 раза в неделю.

**Защита deep report.** Текущий SEO-отчёт защищён только токен-путём в URL.
Для CI этого мало (конкурентная аналитика): предлагается отдельный location
`/ci-<случайный токен>/` **плюс basic auth** (nginx `auth_basic`, htpasswd
кладётся ops-workflow'ом). Кнопка письма ведёт на
`/ci-<токен>/latest/`; ежедневные снимки `/ci-<токен>/2026-08-30/` неизменяемы.

## 10. Чего система делать не будет (зафиксировано)

Не generic-SEO-dashboard и не автогенератор правок: сайт не меняется
автоматически (OBSERVE → ANALYZE → RECOMMEND → TEST → MEASURE). Никакого обхода
CAPTCHA/антиботов, никакого агрессивного скрапинга (≤15 доменов, robots,
задержки, идентифицируемый User-Agent). Демпинг не предлагается; «причина —
цена» не утверждается без доказательств (только PRICE CORRELATION). B2C и
маркетплейсы — вне основного рейтинга. Бренд-запросы BIZSoft исключены из
конкурентного Share. Недоступный источник = NO DATA, не догадки.
