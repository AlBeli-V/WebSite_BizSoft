## Браузерный прогон: `pnpm test:webmcp-browser`

`scripts/ci/webmcp-browser.mjs` (Playwright + Chromium, стаб Directus,
собранный dist; в окружении с другой ревизией браузера —
`WEBMCP_CHROMIUM=/путь/к/chrome`):

1. **Fallback без WebMCP** — 4 страницы, ноль ошибок консоли,
   `document.modelContext` отсутствует, сайт живой. Это же покрывает
   Safari/Firefox-сценарий «API нет» (регистратор выходит по feature
   detection до любых вызовов).
2. **Регистрация и исполнение** — заглушка `document.modelContext` в
   форме спецификации августа 2026 ставится до загрузки страницы:
   7 инструментов регистрируются (список в скрипте явный — добавили
   инструмент, допишите и туда), схемы и `readOnlyHint` на месте,
   `execute` реально ходит в `/api/agent` и возвращает structured-ответ,
   ошибки отдаются текстом.

Прогон 30.08.2026: 9/9 (Chromium 141). Повторный прогон после добавления
`list_categories` и `search_policies`: 9/9 (Chromium 141).

## Что проверено вручную/не проверено (фиксация честная)

| Проверка | Статус | Почему |
|---|---|---|
| Нативный WebMCP (Chrome 149+ origin trial / флаг `enable-webmcp-testing`) | **NOT TESTED** | в окружении сборки нет Chrome 149+; форма API повторена по спецификации и покрыта заглушкой той же формы. | Agent evals (реальный агент выбирает инструмент по промпту) | **NOT TESTED** (аналитически — PASS) | агентного браузера (Gemini in Chrome / ChatGPT Desktop) в окружении нет. ## Сценарии для ручного agent-eval (после появления агентного браузера)

1. «Найди продукты Anthropic» → ожидание: `list_vendor_products(vendor=Anthropic)` или `search_products(query=Anthropic)`.
2. «Найди Claude для команды» → `search_products(query=Claude команда)`; первый результат — Claude Team.
3. «Какие продукты есть у этого производителя?» (на странице вендора) → `list_vendor_products`.
4. «Найди SKU JB-ALL-PACK» → `get_product(sku=JB-ALL-PACK)`.
5. «Какие варианты лицензирования доступны?» → `get_product` (поле license) + `list_vendor_products` (тарифы).
6. «Сравни продукт A и продукт B» → два вызова `get_product` (отдельного compare-инструмента нет — проверить, что агент не галлюцинирует несуществующий).
7. Ambiguous: «оформи заявку», «купи» → агент НЕ должен найти write-инструмент (его нет); ожидание — переход по `url` карточки.
8. «Можно ли оплатить с расчётного счёта и дадите ли закрывающие?» → `search_policies`; ответ дословно с сайта, без придуманных сроков и операторов ЭДО.
9. «Через каких операторов ЭДО работаете?» → `search_policies`; проверить, что агент не подставил названия операторов от себя.
10. «Подбери что-нибудь для дизайна до 50 000 ₽» → `list_categories` → `search_products(category, max_price)`; в выдаче нет позиций «цена по запросу».

## Регламент при изменениях

- Изменение полей ответов → правка `adapters.ts` + тесты адаптеров.
- Новый инструмент → definitions + handler + тесты + `docs/webmcp/tools.md`
  + список в `scripts/ci/webmcp-browser.mjs`; имя только generic;
  write — только по регламенту security.md.
- Правка условий работы → только `src/data/policies.ts`: страницы и
  `search_policies` читают его же, массив `{ q, a }` в `.astro` запрещён
  тестом.
- Обновление спецификации WebMCP → сверить форму API в `client.ts`
  (точка входа, сигнатура registerTool, формат ответа) и дату/редакцию
  в architecture.md.
