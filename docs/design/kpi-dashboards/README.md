# KPI-дашборды для отчётов: исследование и витрина макетов

Ветка `claude/kpi-dashboards-reports-pg21zn`. Задача руководителя: перестроить
визуальный слой отчётов (письма и HTML-страницы «подробных данных») — уйти от
текстовых таблиц к дашбордам с наборами KPI и углублением от общего к частному.

## Что есть сейчас

- **Страница отчёта** — `scripts/seo/webreport.py`: один самодостаточный HTML
  без JS, ~24 раздела таблиц; графики — те же три PNG, что и в письме,
  вшитые data-URI. Публикуется `seo-publish-web` (rsync на сервер, nginx
  `/r-…/latest.html`, noindex).
- **Письмо** — `scripts/seo/report_v4.py`: табличная вёрстка; графики —
  `charts_v4.py` (HTML/CSS-строки) → `render.mjs` (Playwright + Chromium) →
  PNG как `cid:`-вложения. Гейты `uxlint_v4.py`: ≤3 картинки, ≤220 px
  высоты, ≤1900 слов, шрифт ≥14 px, без горизонтальной прокрутки на 375 px.
- **Библиотек графиков нет** ни в Node, ни в Python (только stdlib).
  Фактический движок графики — «HTML → скриншот Chromium».

## Рекомендация по архитектуре

Не внедрять BI-платформу (Metabase/Superset/Redash) и не поднимать QuickChart:
в конвейере уже есть свой рендер HTML → PNG (`render.mjs`), а хостинг
страниц — статик за nginx. Оптимальный путь — **собственный набор
KPI-компонентов на inline SVG/CSS** (плитка, спарклайн, линия, воронка,
теплокарта, bullet, дерево), который:

1. на странице рендерится «живым» (hover, углубление по клику, сортировка);
2. в письмо уходит теми же компонентами через существующий `render.mjs` → PNG
   в пределах лимитов `uxlint_v4`;
3. хранится в одном модуле (шаблоны компонентов), а данные подаются JSON-ом
   из `reports/seo/intelligence/*` — без второй базы и без внешнего сервиса.

Правила визуализации — по методике dataviz: одна ось, тонкие марки, серия =
сущность (Яндекс — синий, Google — фирменный оранжевый), статусные цвета
отдельно от серий, легенда при ≥2 серий, таблица-двойник у каждого графика.
Палитра проверена валидатором (CVD ΔE ≥ 9, контраст ≥ 3:1 кроме aqua/yellow —
у них обязательны прямые подписи).

кнопками выбора (артефакт сессии сохраняет голоса в базу страницы):
