Настроено 29.08.2026 (ветка `claude/yandex-products-setup-70o2tf`).

## Рубильник: фиды закрыты до команды руководителя

Решение руководителя 29.08.2026: фиды готовы, но **никому не раздаются**.
По умолчанию все фид-URL отвечают 404 с заголовком `X-Feed-Status: disabled`.

Открытие — только по команде руководителя, переменной окружения на проде
(без пересборки кода):

```
YANDEX_FEEDS_ENABLED=all                              # открыть все
YANDEX_FEEDS_ENABLED=yandex-products,yandex-business  # только перечисленные
```

Ночная проверка `ops-yandex-feeds` показывает закрытый фид как
«⏸ подготовлен, но закрыт» — это штатное состояние, не ошибка.

Исполнение команды руководителя — workflow `ops-yandex-feeds-toggle`
(запуск строго с main): пишет значение в `/opt/bizsoft/astro.env`,
пересоздаёт контейнер astro и показывает фактический статус фидов.

Решение руководителя 29.08.2026 по итогам исследования: курс — органика +
Директ; открыт только фид Директа (`YANDEX_FEEDS_ENABLED=yandex-direct`),
Товары/Бизнес/Маркет остаются закрытыми (категория «электронные товары»
не принимается Яндекс Товарами; ждём ответа поддержки).

Фактическое состояние на 02.09.2026 (проверка `ops-probe`): открыты Директ,
**Бизнес** и 2ГИС (HTTP 200, **532 оффера**, генерация динамическая — фид
всегда актуален каталогу на момент забора площадкой); Товары и Маркет закрыты
(404). Канал Бизнес-каталога подтверждён лидом 28.08 (шрифт Monotype).

Число офферов плавает вслед за каталогом (снятие с публикации, «цена по
запросу», новые позиции): 535 на 01.09, 532 на 02.09. Сверять кабинет надо с
выдачей фида на день сверки, а не с однажды записанным числом.

## Что отдаёт сайт (после открытия)

| Фид | URL | Потребитель |
| --- | --- | --- |
| YML Яндекс Товаров | `https://biz-soft.pro/yandex-products.yml` | кабинет merchants.yandex.ru → «Товары» → «Источники данных» → «Фиды» |
| YML Яндекс Бизнеса | `https://biz-soft.pro/yandex-business.xml` | кабинет Яндекс Бизнеса → товары/услуги организации |
| YML Яндекс Директа | `https://biz-soft.pro/yandex-direct.yml` | кабинет Директа → «Библиотека» → «Фиды» (товарные кампании, смарт-баннеры) |
| YML Яндекс Маркета | `https://biz-soft.pro/yandex-market.yml` | кабинет продавца partner.market.yandex.ru (ассортимент) |
| YML 2ГИС | `https://biz-soft.pro/2gis-products.yml` | Личный кабинет 2ГИС → «Товары и цены» → прайс-лист по ссылке (автозабор раз в сутки) |

Особенности 2ГИС (`src/lib/feeds/dgis.ts`, по официальной инструкции
прайс-листа): id оффера — числовой id товара (цифры/латиница ≤ 20, sku с
дефисами не проходят); картинка — чистый знак продукта
`/img/product-icon/<slug>.png` без цены и надписей (og-карточка запрещена
правилами площадки), без знака оффер идёт без картинки; описание без
URL; без oldprice/sales_notes. Лимит позиций — env `TWOGIS_FEED_MAX`.

Оба фида генерируются **на лету** (SSR из Directus): цены в них всегда
совпадают с сайтом, включая ночную переоценку по курсу ЦБ и акции.
Площадки забирают файл по ссылке сами, несколько раз в сутки.

## Порядок офферов и картинка (аудит 02.09.2026)

**Порядок — две ступени.** Первая: измеренный спрос самой карточки
(`src/data/product-demand.json` — визиты органики Метрики и показы/клики
страницы в GSC; счёт = визиты×10 + клики×5 + показы, порог 3). Вторая: спрос
вендора в Вордстате (`src/data/vendor-demand.json`), внутри вендора — основные
позиции раньше дополнений, затем витринный `sort` и имя. Площадка показывает
первыми те позиции, что идут первыми в выгрузке, а спрос вендора — оценка
рынка, а не нашей витрины. Файл спроса карточек пересобирается
`node scripts/seo/build-product-demand.mjs` и коммитится в репозиторий.

**Картинка зависит от площадки.** Изображение оффера выбирает резолвер
(`src/lib/feeds/yml.ts`):

| Фид | Картинка | Почему |
|---|---|---|
| Яндекс Товары, Директ, Маркет | `/og/product/<slug>.png` | изображение работает как рекламный креатив; название, вендор и цена на нём уместны |
| Яндекс Бизнес | `/img/product-icon/<slug>.png` | Бизнес показывает картинку как **фотографию товара** в карточке организации — цены и названия магазина на ней быть не должно |
| 2ГИС | `/img/product-icon/<slug>.png` | прямой запрет площадки на цену и надписи |

Нет знака товара — Бизнес получает OG-карточку как запасной вариант, чтобы
оффер не остался без изображения вовсе (2ГИС в этом случае идёт без картинки:
там запрет строгий).

## Архитектура: `src/lib/feeds/*`

Механизм отделён от логики сайта и универсален:

- `types.ts` — словарь: нормализованный оффер, спецификация фида;
- `select.ts` — ядро: фильтр требований площадок → ранжирование → лимит;
- `yml.ts` — сериализатор YML (общий для всех яндекс-фидов);
- `registry.ts` — реестр фидов: id, путь, сериализатор, env-лимит;
- `endpoint.ts` — единственная стыковка с сайтом (HTTP-ответ, 503 при сбое БД).

Подключение нового сервиса (Google Merchant, VK и т.п.) — новая запись в
реестре и, при новом формате, свой сериализатор. Ядро и страницы не меняются.

## Какие товары попадают в фид

Отбор (`feedEligible`): опубликованные зарубежные товары каталога, у которых:

- есть название, slug и артикул;
- карточка индексируется — исключены `noindex`, плагины `JB-PLG-*`,
  личные лицензии `JB-*-IND`, карточки продления `*-RENEWAL`;
- цена больше нуля («цена по запросу» площадки не принимают; карточки
  «от N ₽» идут с этой минимальной ценой — она видна и на сайте).

Порядок офферов описан выше («Порядок офферов и картинка»): первая ступень —
измеренный спрос карточки (`src/data/product-demand.json`), вторая — спрос
Вордстата по вендору из `src/data/vendor-demand.json` (агрегат
`reports/seo/wordstat/semantic-universe.jsonl` без пиратских фраз;
пересборка: `node scripts/seo/build-vendor-demand.mjs`), внутри вендора —
основные продукты раньше дополнений, затем витринный `sort`.

## Лимиты количества

Жёсткого лимита у Яндекса нет, но на случай ограничений лимит каждого фида
задаётся переменной окружения на проде (пусто/0 — без лимита):

- `YANDEX_PRODUCTS_FEED_MAX` — Яндекс Товары;
- `YANDEX_BUSINESS_FEED_MAX` — Яндекс Бизнес;
- `YANDEX_DIRECT_FEED_MAX` — Яндекс Директ;
- `YANDEX_MARKET_FEED_MAX` — Яндекс Маркет.

Благодаря ранжированию под лимит первыми попадают самые востребованные.

## Ночной контроль: workflow `ops-yandex-feeds`

Каждую ночь в 03:30 МСК (00:30 UTC) проверяет оба фида: HTTP 200,
Content-Type из списка Яндекса, валидность XML, свежая дата `yml_catalog`,
ненулевое число офферов, топ-10 позиций. Отчёт — комментарием в issue #22;
при поломке job падает (видно в Actions).

## Что осталось сделать руками (кабинеты)

1. Зарегистрировать магазин на merchants.yandex.ru (тот же Яндекс ID, что и
   Вебмастер) и подтвердить права на сайт.
2. Добавить фид по ссылке `https://biz-soft.pro/yandex-products.yml`,
   регион продаж — Россия.
3. В Яндекс Бизнесе подключить фид `https://biz-soft.pro/yandex-business.xml`.
4. Подключить счётчик Метрики в настройках кабинета Товаров.
5. Спросить поддержку Яндекс Товаров про категорию «электронные товары»
   (ПО/лицензии в правилах от 27.03.2026 не принимаются к полноценному
   размещению): реалистичная цель — обогащённый сниппет в органике.
6. Директ: в кабинете Директа («Библиотека» → «Фиды») добавить фид по
   ссылке `https://biz-soft.pro/yandex-direct.yml`; дальше на его основе
   создаются товарная кампания или смарт-баннеры (бюджет — решение
   руководителя).
7. Маркет: выход на маркетплейс — отдельное бизнес-решение. Покупка
   происходит на Маркете, а не на сайте: нужен кабинет продавца
   (partner.market.yandex.ru), договор и комиссия Маркета, модель DBS
   для цифровых товаров (выдача ключа/доступа после оплаты, инструкция
   по активации, обработка заказов через API кабинета). Фид ассортимента
   готов (`/yandex-market.yml`), но подключать его имеет смысл только
   после решения о выходе и настройки обработки заказов.

## Пуш через API (не настроено)

API Яндекс Товаров (оперативная смена цен/скрытие позиций) требует
OAuth-токен кабинета — секрет `YANDEX_MARKET_TOKEN` пока не заведён.
Он не обязателен: фид по ссылке площадки забирают сами. Когда токен
появится, шаг пуша добавляется в `ops-yandex-feeds`.
