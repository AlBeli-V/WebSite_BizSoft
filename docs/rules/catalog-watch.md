# Изменения каталога — под сторожем, письмо руководителю

**Правило.** Появление, исчезновение, снятие с витрины и возврат карточки, а
также правка её цены, закупки, коэффициента, названия, слага, приписки к цене
или типа товара — событие, о котором руководитель узнаёт письмом на
avbelyaev@biz-soft.pro в тот же день. Единственное исключение — ежедневная
переоценка по курсу ЦБ: она штатная и молчит. Сторож — workflow
`ops-catalog-watch`, разбор — `scripts/ops/catalog_watch.py`.

## Откуда правило

Поручение руководителя 10.09.2026: «следи, чтобы продукты не добавлялись и не
убирались с сайта автоматически; если продукты исчезают, добавляются или с
ними аномалия, кроме пересчёта курса доллара и евро, — уведомление мне на
почту».

Повод конкретный. Карточку ChatGPT Business руководитель заводил сам, а на
витрине её не стало. Разбор 10.09.2026: карточка `OPENAI-BUSINESS` была
дублем, и миграция AI-каталога 17.08.2026 (прогон #4 `ai-catalog-migrate`,
успешный; список `REMOVALS` в `scripts/ai-catalog-data.py`) сняла её с
публикации, поставив 301 на каноническую `INT-AI-CHATGPT`. Вместе с ней тем же
прогоном ушли `OPENAI-PLUS`, `OPENAI-PRO`, `OPENAI-API`, `MJ-BASIC`,
`DSCRPT-HOBBYIST`, `RECRAFT-BASIC`, `ELEVEN-STARTER`, `HEYGEN-CREATOR`. Каждое
снятие было осознанным решением, но ни одно не было видно снаружи: карточка
просто переставала открываться.

Каталог правят пачками сразу несколько автоматов: `ops-import-vendors` и
`ops-import-ai-cards` (upsert по sku из реестров репозитория),
`ops-merge-product` (склейка дублей: `drop` уходит в `draft`),
`ops-recategorize`, `ops-rename-product`, `ops-patch-product`,
`ops-annual-reprice`, `ai-catalog-migrate` и ежедневная `ops-currency-refresh`.
Ни один из них по замыслу не «удаляет товары сам» — но результат прогона
виден только тому, кто в этот момент читал журнал.

## Что сторож считает событием

| Событие | Пример источника |
|---|---|
| Карточка появилась | импорт реестра с новой позицией |
| Карточка исчезла из базы | удаление руками в админке |
| Снята с витрины (`published` → `draft`) | склейка дублей, миграция |
| Вернулась на витрину | правка статуса в админке |
| Изменились закупка, коэффициент или валютная привязка | переоценка, правка прайса |
| Цена изменилась не по формуле курса | ручная правка, `price_locked` |
| Изменились название, слаг, приписка к цене, промо, тип товара | переименование, патч |

Событием **не** считается смена рублёвой цены, которая объясняется новым
курсом ЦБ: валютная привязка и закупка те же, коэффициент тот же, а новая цена
сходится с витринной формулой `закупка × курс × коэффициент` с точностью до
рубля. Это ровно то, что делает `ops-currency-refresh` каждый день по всему
каталогу; без этого исключения письмо приходило бы ежедневно на полторы тысячи
строк и его перестали бы открывать.

## Как устроено

Снимок каталога снимается на прод-сервере рядом с Directus (из сессии и с
раннера GitHub доступа к базе нет) под учёткой администратора: статический
токен витрины видит только опубликованные карточки, и снятая с витрины позиция
выглядела бы как удалённая. Состояние лежит в `/opt/bizsoft/ops/catalog`:
`latest.json` — база сравнения, `ГГГГ-ММ-ДД.json` — дневные снимки за
последние 60 дней, `last-run.json` — маркер дня.

Два слота в cron (09:00 и 12:00 МСК) — по правилу
`docs/rules/operational-runs.md`: планировщик GitHub задерживает утренние слоты
на 4–5 часов. Повторной работы второй слот не делает, его останавливает маркер
дня.

Тишина по умолчанию: нет расхождений — нет ни письма, ни записи в журнал.
Запись в issue #22 появляется, когда есть находки или когда прогон упал.

`--baseline` пересобирает базу сравнения без письма: нужен после осознанной
массовой правки, чтобы завтрашний прогон не пересказывал её заново.

## Чего сторож не делает

Он не запрещает автоматам менять каталог и не откатывает правки. Запрет
ломал бы штатные контуры импорта и склейки; задача сторожа — чтобы ни одна
такая правка не прошла незамеченной.
