# Знаки продуктов в карточках

Решение руководителя 13.09.2026 (механизм согласован кнопками: официальные
источники + Google API на остаток). Правило глобальное: все позиции
каталога, существующие и новые.

## Правило

У каждой позиции — свой знак продукта: квадратный знак, а не текстовое
написание и не связка знака с надписью. Если знак продукта есть в пакете
(`src/assets/product-icons`), берётся он. Если нет — подбирается по
алгоритму ниже и кладётся в пакет в едином формате; после этого он
используется везде: в заголовке карточки, в плитках, в подборке для КП,
в цвете и в монохроме.

Знак вендора вместо знака продукта допустим там, где продукт назван
именем вендора (Figma, Cursor, Kling AI): там знак вендора и есть знак
продукта. Семейство продукта (без редакции, объёма и срока) получает один
знак: ManageEngine OpManager Standard и Professional — один `opmanager`.

## Решение 13.09.2026: остаток — знак вендора, поиск закрыт

Первый прогон подбора показал цену поиска: Marketplace возвращает соседние
плагины, а этап Google требует аккаунта Google Cloud и ручного выбора из
кандидатов по 137 семействам. Руководитель решил:

- плагины JetBrains Marketplace (867 позиций) показывают знак JetBrains;
  отдельные знаки плагинов не ищутся. 14 знаков, поставленных до решения
  (`data/catalog/logo-choices.json`), остаются;
- остальные 137 семейств без знака продукта (ManageEngine 38, Zoom 8,
  Microsoft 6, Apple 4 и далее по 1–3) показывают знак вендора; аккаунт
  Google Custom Search не заводится (`ops/accounts/registry.json`:
  `google-cloud-cse` — `declined`), этап Google в `ops-logo-candidates`
  без секретов не запускается и остаётся на случай отмены решения;
- новый знак продукта появляется только по прямому решению руководителя
  или из официального файла вендора, который принёс оператор.

Заявки в `data/catalog/logo-requests.json` сохраняются как опись семейств
без своего знака; новых прогонов подбора по ним не делается.

## Алгоритм подбора

1. `scripts/catalog/logo-requests.ts` собирает заявки: позиции без знака
   и позиции под знаком вендора → семейства → `data/catalog/logo-requests.json`.
2. `ops-logo-candidates` (GitHub Actions; в сессии внешней сети нет)
   скачивает кандидатов: JetBrains Marketplace API для плагинов,
   официальные адреса из заявки, затем Google Custom Search по фразе
   «вендор + продукт + logo» — при наличии секретов `GOOGLE_CSE_KEY` и
   `GOOGLE_CSE_CX` (квота 100 запросов в сутки). Кандидаты и лист превью
   `contact.png` коммитятся в рабочую ветку `assets/incoming/logos/<id>/`.
3. Выбор — в сессии по листу превью: самый распространённый знак продукта
   в квадратной форме; не надпись, не связка знака с надписью, не скриншот.
   Сомнение — вопрос оператору.

   Итог первого прогона (13.09.2026, ветка `claude/logo-candidates`): у
   плагинов JetBrains поиск Marketplace по названию семейства возвращает
   соседние плагины (запрос «API Explorer» — «Joymutlu API Explorer»,
   «Gorm» — четыре разных «Gorm»), а часть иконок — надписи или пустой SVG.
   Совпадение заголовка плагина с названием семейства не доказывает
   тождество: у каталога нет идентификатора плагина Marketplace. Поэтому
   знак плагина выбирается только при известном `plugin id` (просьба к
   оператору) либо остаётся буквенный фолбэк; заявки без ключа Google
   получают статус `needs_key` и ждут секретов.
4. `scripts/catalog/build-product-icons.mjs` по `data/catalog/logo-choices.json`
   нормализует выбранное в формат пакета: 512×512, прозрачный фон, поля 6%,
   цвет и монохром; обновляет `src/data/product-icon-map.json` и манифест
   `docs/catalog-product-icons-manifest.json` (источник и права у каждого
   знака).

## При заведении вендора или товара

Новая позиция получает знак так: есть официальный файл вендора или знак
семейства в пакете — кладётся в пакет; нет — карточка выходит со знаком
вендора (решение 13.09.2026), и это не долг, а норма. Плагин JetBrains —
всегда знак JetBrains.
