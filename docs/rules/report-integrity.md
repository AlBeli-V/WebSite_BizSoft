# Достоверность отчётов: данные, не литералы

Установлено 03.09.2026 по аудиту `docs/ops/report-integrity-audit-2026-09-03.md`
(письмо GI две недели печатало зашитую фразу «ждёт токена Вебмастера»).
Действует во всех ветках.

- **Литералы без срока годности запрещены** в тексте отчётов, промптов и
  записей журнала: даты, обещания («появится после», «следующий шаг»,
  «подготовлю», «ждёт»), «ещё не собран», суммы, квоты. Проверка —
  `scripts/seo/tests/test_report_literals.py`; исключения только в
  `data/reports/literal-allowlist.json` с причиной и `valid_until`.
- **Недоступный блок письма — только через `scripts/seo/passport.py`**:
  код причины из перечня, текст из словаря, дата данных `as_of` и пометка
  `stale` при отставании. Правило одной строкой: код не различает причину —
  текст её не называет.
- **Инварианты двух уровней** (`scripts/seo/invariants.py`): ложь о дате или
  причине блокирует выпуск письма (`<дата>-v4-blocked.json`, код 2,
  уведомление о сбое с причинами), форма — мягкое нарушение в JSON.
- **Решение руководителя доходит до карточки, а пересказ решения сверяется.**
  Журнал `reports/seo/intelligence/experiment-decisions.jsonl` — источник
  истины о вердикте и выборе. Карточка эксперимента печатает строку «решение
  по эксперименту» из журнала, а не только стадию наблюдения из реестра.
  Вердикт чужого эксперимента, названный в свободном тексте реестра
  (гипотеза, состав правки, целевой показатель), сверяется с журналом по
  тикету и дате — инвариант S5. Разбор 09.09.2026: вердикт CONFIRMED по
  CONTENT-001 был записан 03.09.2026 с решением EXPAND, но в реестре у
  эксперимента остался `status: running`, и отчёт неделю печатал
  «наблюдаем — накоплено 31 показов из 100 минимальных». Гипотеза CONTENT-002
  при этом ссылалась на «вердикт CONFIRMED 02.09.2026: +70% показов, статья
  на 5-й позиции», а CONTENT-004 — на «03.09.2026: +62%, 6-я позиция»: одно
  решение, две даты и два эффекта, ни один из которых не сверялся ни с чем.
- **Порог печатается тот, по которому судят.** Строка «минимальная
  экспозиция» показывает действующий гейт эксперимента, а не настроенную
  константу: рядом с выводом «накоплено 31 показов из 100 минимальных»
  стояло обещание «7 дн. и 500 показов». Снижение гейта называется прямо.
- **Число из чужого дня не ставится рядом без подписи.** Срез страниц
  Вебмастера собирается своим шагом и отстаёт; его возраст печатается рядом
  с числом. Если «в поиске» по инвентарю больше, чем по сводке хоста, это
  разные дни сбора, и подпись говорит, что сравнивать их нельзя (09.09.2026:
  663 страницы инвентаря по срезу от 06.09 против 650 по сводке хоста).
- **Событие за окно не выдаётся за состояние дня.** Запись о снятых из
  поиска страницах называет окно выборки и текущее число исключённых по
  хосту (09.09.2026: «267 адресов, LOW_QUALITY: 327» за три месяца стояли в
  «Сбоях дня» рядом со сводкой, где исключённых числилось 53). У записи есть
  условие снятия.
- **Журнал со статусом**: запись в issue #22 из workflow — только через
  `.github/actions/journal-post` с `outcome` основного шага (✓/✗, красный
  прогон при неуспехе). `|| true` и `exit 0` после «не найден» вокруг
  основного скрипта запрещены: вывод в output, шаг завершается кодом
  скрипта. Храповик — `tests/workflows-lint.test.ts`, база
  `data/reports/workflow-lint-baseline.json` только убывает.
- **Реестр секретов** `ops/secrets/registry.json`: каждое `secrets.X`
  зарегистрировано с назначением (`tests/secrets-registry.test.ts`); второе
  имя одного токена — долг с `resolve_by`.
- **Срок годности одноразовых workflow**: `# expires:` в шапке, просроченный —
  в `.github/workflows-archive/` или продление через PR.
- **Обмен с seo-data не затирает чужие правки**: `pull` запоминает снятую
  версию хранилища (метка в `.git`), `push` отправляет только файлы, которые
  прогон действительно изменил или удалил; нетронутые остаются версии
  хранилища. Полная замена каталога стоила четырёх инцидентов за неделю —
  откат почтового маркера с повторным письмом (29.08), взаимное затирание
  трёх workflow (30.08), удаление свежего site-check (31.08), потеря реестра
  экспериментов через минуту после правки (04.09). Сценарии закреплены в
  `scripts/seo/tests/test_data_sync.py` на настоящих репозиториях.
- **Сравнение только по полным окнам**: недельные и периодные агрегаты не
  сравниваются, пока оба окна не покрыты данными целиком; источник без
  данных печатается «—», а не «0».
