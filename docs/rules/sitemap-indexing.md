# Регулярное правило: новые страницы → sitemap → индексация

После добавления новых страниц сайта (лендинги в разделе «Производители»
`/vendors/*` и продуктовые страницы `/product/*`) и после содержательной
правки существующих (описание, модули карточки, мета) обязательно:

1. **Sitemap.** Проверить, что новые URL попали в `/sitemap.xml`.
   Sitemap динамический (SSR из Directus, `src/pages/sitemap.xml.ts`):
   товары и вендоры из БД подхватываются автоматически, но новые
   **статические/bespoke-страницы** нужно вручную добавить в `STATIC_ROUTES`.
   Товары с `noindex` и sku из `productNoindex()` (плагины JetBrains
   Marketplace, личные планы `IND`) в sitemap не попадают — их не
   индексируем. Исключение из правила личных планов заводится вендором в
   `IND_INDEXABLE_VENDORS` (`src/lib/catalog.ts`) и только решением
   руководителя: TryHackMe — 15.09.2026, личные Premium и MAX там основной
   товар, а не младший вариант командного тарифа.
   `lastmod` карточки — `content_updated_at`: его ставят `ops-apply-content`
   и `ops-apply-descriptions`, поэтому после правки контента дата в карте
   сайта обновляется сама, руками ничего не делать. Робот Яндекса при
   очередном чтении карты видит новую дату и ставит страницу в очередь —
   это третий, фоновый канал, он не заменяет два ниже.
2. **IndexNow — основной канал переобхода.** Отправить изменённые URL через
   workflow `ops-indexnow` (вход `urls` — список полных URL через запятую;
   пусто — весь sitemap). Лимит протокола — 10 000 URL в сутки, принимают
   Яндекс и Bing; Google IndexNow не поддерживает. Яндекс отвечает 202,
   api.indexnow.org — 200; другой код — сбой прогона. Результат —
   комментарий в журнал-issue #22. Отправлять сразу после применения
   изменений в прод, партиями по волне или семейству.
3. **Переобход Вебмастера — для приоритетных страниц.** `ops-yandex-recrawl`
   (вход `urls`, квота 150 URL/сутки) — вторая очередь Яндекса, независимая
   от IndexNow: носители семейств, посадочные вендоров, страницы под
   экспериментами. Квота обновляется в 00:30 МСК, ночной сплошной переобход
   `seo-recrawl-sweep` стартует в 00:40 и забирает остаток, поэтому ручные
   партии ставятся в окно 00:30–00:40 МСК и не превышают 100 адресов за
   ночь. Отклонённые с HTTP 429 переносятся на следующую ночь.

Что не делается из сессии. «Обход по счётчикам» (Вебмастер → Индексирование
→ Обход по счётчикам, привязка счётчика Метрики) — настройка кабинета,
API её не имеет; включение — решение и действие руководителя. Включённый
обход по счётчикам не тратит квоту переобхода и подхватывает страницы по
визитам, но новые карточки без трафика он не увидит — IndexNow остаётся.
