# Плашки над заголовком карточки

Решение руководителя 13.09.2026. Правило глобальное: действует на все
карточки каталога — существующие и те, что появятся позже.

## Правило

Над заголовком карточки стоят ровно две плашки.

**Первая — вид позиции**, выделена цветом:

| Вид позиции | Плашка |
|---|---|
| Продукт, ПО, подписка, план | `Командный план` либо `Индивидуальный план` |
| Пополнение баланса, токены, номинал | `Универсальный продукт` |
| Плагин, аддон, дополнение к продукту | `Дополнение к продукту` |

**Вторая — одна основная категория.** Даже если позиция логически попадает
в несколько разделов, в плашке стоит одна. У пополнений и дополнений это
основная категория производителя (`catSeg` и `catLabel` в
`src/data/vendors.ts`): сама позиция — надстройка над его продуктом, и своя
категория у неё бывает служебной. Вендора нет в реестре — берётся категория
самой позиции.

## Откуда берётся вид позиции

Считает `cardComposition` (`src/lib/product-composition.ts`) по данным:
`product_type`, `parent_sku`, артикул. Пополнения и дополнения определяются
однозначно, и плашка у них выводится сама.

Тип плана подписки данными **не определяется**: поля в каталоге нет, а
эвристика по названию и описанию (`src/lib/plan-type.ts`) молчит на 277
позициях из 601. Догадка здесь запрещена — она уже дала «Командный план ·
VFX и моушн» на карточке Red Giant.

## Спорная карточка размечается оператором

Поле `marker` в контенте вендора (`VendorCardMeta`) старше эвристики:

```json
"cards": { "MAXON-REDGIANT-TEAMS": { "marker": "team" } }
```

Значения: `team`, `individual`, `universal`, `addon`.

**При заведении нового вендора или товара:** если не очевидно, к какому виду
относится позиция и в какую категорию её класть, — вопрос оператору до
записи в каталог, а не догадка. Карточка без разметки и без подтверждённого
типа плана показывает только плашку категории: отсутствие плашки честнее
неверной.
