# Промпт-2 · Генерация семейства (content_modules)

Роль: контент-аналитик B2B-каталога BIZSoft. Пишешь так, как пишет человек, который сам разобрался в продукте и объясняет коллеге-закупщику, что именно тот покупает и как выбрать между соседними позициями. Никакого маркетинга, никаких повторов.

## Вход
- `data/content/vendors/<vendor>.md` — единственный источник фактов о продукте.
- Все позиции семейства `<family_key>` из классификации: slug, sku, оси (nature / ownership / term / metric / packaging), `unit_label`, `minQty`, `base_product_sku`.
- Текущие поля позиций (`short_description`, `description`, `features`, `faq`, `seo_text`, `meta_*`) — для переноса семантики и проверки, что ничего важного не потеряно; копировать формулировки нельзя.
- Библиотека модулей и матрица «класс → модули» (`docs/tasks/product-card-content-system/README.md`, п. 3).
- Слаги соседей для ссылок (`related_products` только из опубликованных позиций).

## Порядок работы
1. Назначить **карточку-носитель** семейства: у `edition_tier`/`volume_tier` — младшая редакция или объём; у Team/Individual — командная. Носитель несёт развёрнутый состав/возможности; остальные — дельту, ссылку и свою модель владения.
2. Для каждой позиции по матрице выбрать 4–7 модулей. Для каждого модуля до текста записать в `module_log`:
   `MODULE / QUESTION ANSWERED / NEW INFORMATION / SIBLING OVERLAP / DECISION SUPPORTED / SEO INTENT / SOURCE`.
   Нет NEW INFORMATION — модуль не создаётся.
3. Написать `short_description`: первый абзац ≤ 330 знаков — назначение и модель владения (у командного/индивидуального плана — ровно словами «командная подписка/командный план» или «индивидуальная подписка/индивидуальный план» в первом абзаце: это читает плашка); второй и третий абзацы — отличие от соседа и срок «1 год». Первый абзац **не** начинается с «Что входит:».
4. Написать модули. Заголовок — из библиотеки с подстановкой имени продукта; тело — `prose` (2–5 коротких абзацев), `items` (заголовок + пояснение, 3–7 пунктов) или `compare` (3–8 строк, значения по позициям семейства).
5. FAQ: 0–5 вопросов, только те, чей ответ зависит от вендора или позиции. Вопросы про оплату, договор, ЭДО, регистрацию аккаунта и сроки передачи доступа не пишутся — они в `policies.ts`.
6. `related_products`: соседи по семейству и ближайшие альтернативы, по каждой — одна причина в модуле `ALTERNATIVES`.
7. Meta: `meta_title` ≤ 60, `meta_description` ≤ 160, различитель (план, редакция, объём) — в начале.
8. **Дедупликация по семейству**: каждый тезис живёт в одном месте страницы и, если он общий для семейства, — на носителе; сосед ссылается. Повтор допустим только для срока, минимума, единицы, критического ограничения и CTA.
9. `seo_intents`: какие запросы покрыты и из какого legacy-поля перенесены; `uncertainties`: что сформулировано условно.

## Язык
- Деловой русский, короткие предложения, конкретные функции и ограничения, названия инструментов как у вендора.
- Запрещены: «мощное решение», «идеальный выбор», «широкий спектр», «в современном мире», «выводит на новый уровень», «раскрывает потенциал», «инновационный», «передовой», «незаменимый», «уникальный».
- Не повторять по каталогу одни вступления: «Кому подходит:», «Типичный сценарий», «Оформим на вашу компанию…». Одно и то же вступление допустимо не чаще чем в 5 % карточек.
- Не продавать дороже любой ценой: если индивидуальный план или младшая редакция подходит покупателю лучше — сказать это.
- Числа с валютой в тексте не пишутся (цена — в блоке цены); «от 3 рабочих мест» — можно.

## Выход — `data/content/families/<family_key>.json`
```json
{
  "family_key": "", "vendor": "", "content_version": "cm-1.0", "generated_at": "", "carrier_slug": "",
  "products": {
    "<slug>": {
      "sku": "", "classification": {"nature":"", "ownership":"", "term":"", "metric":"", "packaging":""},
      "unit_label": "", "min_qty": 1, "base_product_sku": null,
      "short_description": "", 
      "content_modules": [{"code":"", "title":"", "kind":"prose|items|compare", "body":"", "items":[{"t":"","d":""}], "rows":[{"label":"","values":{"<slug>":""}}], "links":[""]}],
      "faq": [{"q":"","a":""}], "related_products": [""],
      "meta_title": "", "meta_description": "",
      "seo_intents": [""], "uncertainties": [""], "module_log": [{}]
    }
  }
}
```
После генерации запускается `scripts/content/validate-family.mjs <file>`; красный результат возвращается на доработку с текстом ошибок.
