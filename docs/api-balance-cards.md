# Пополнение баланса API (карточки номиналов)

Заведено 11.09.2026 по решению руководителя. Первый вендор — OpenAI; механизм
общий: любой сервис, где программный доступ продаётся не местами, а суммой на
балансе (Anthropic и далее), ложится в ту же модель без новой архитектуры.

## Модель

- **Родительская карточка** — `<PREFIX>-API-BALANCE` (слаг
  `openai-api-balance`), цена по запросу. Держит поисковый интент «пополнить
  баланс <вендор>» и закрывает суммы вне готового ряда.
- **Номиналы** — по карточке на сумму: `<PREFIX>-CREDITS-<номинал>`
  (`OPENAI-CREDITS-50` … `OPENAI-CREDITS-10000`). Обычные карточки с ценой:
  живут на витрине, в избранном, в КП и в выгрузках.
- **Защита от каннибализации** — артикул. Правило `productNoindex`
  (`CREDITS_PACK` в `src/lib/catalog.ts`) закрывает `-CREDITS-<число>` от
  индексации: одиннадцать почти одинаковых страниц не конкурируют ни между
  собой, ни со страницей вендора. Тот же артикул делает карточку дополнением
  (`productKind = addon`), поэтому она не попадает в «Цены от» лендинга.
  Назвать артикул иначе — значит тихо выключить обе защиты; на это стоит
  проверка `tests/api-balance-cards.test.ts`.

## Цена

```
себестоимость (USD) = номинал × 1,22        # НДС поставщика при закупке
цена на витрине (₽)  = себестоимость × 1,9 × курс USD ЦБ
```

Коэффициент 1,9 — тот же, что у остальных карточек AI-каталога; хранится в
`markup_coeff` каждой карточки, поэтому пополнения переоценивает штатный
ежедневный механизм (`ops-currency-refresh`), отдельной ветки расчёта нет.
Номинал 50 $ → себестоимость 61 $ → витрина = 61 × 1,9 × курс.

## Где что лежит

| Что | Файл |
|---|---|
| Реестр: вендоры, номиналы, коэффициенты, тексты | `scripts/api-balance.json` |
| Сборщик карточек | `scripts/build-api-balance-cards.mjs` |
| Сгенерированные карточки (руками не править) | `scripts/api-balance-cards.json` |
| Проверки формулы и защиты от каннибализации | `tests/api-balance-cards.test.ts` |
| Блок номиналов на лендинге вендора | `src/pages/vendors/openai.astro` |

## Как добавить вендора

1. Запись в `scripts/api-balance.json`: `vendor`, `prefix`, `category`,
   `api_name`, `parent_sku`, `parent_name`, `sort_base`, ряд `denominations`
   и три подстановки в `texts` (`models`, `where`, `intent`). Коэффициенты
   берутся из `defaults` — свои нужны только при другой ставке.
2. `node scripts/build-api-balance-cards.mjs` — пересобрать карточки.
   `--check` сверяет, что файл не разошёлся с реестром (то же делает тест).
3. `pnpm test` — формула, ряд номиналов и защита артикулов.
4. На лендинге вендора блок номиналов появляется сам: карточки-дополнения
   собираются из живых данных Directus (`productKind === 'addon'`).

## Заливка на прод

Все workflow запускаются только с `main` (`docs/rules/production-workflow-main-only.md`).

1. `ops-import-ai-cards` с входом `registry = scripts/api-balance-cards.json`
   и перечнем `skus`; сначала `apply=false` (dry-run), затем `apply=true`.
   Импорт — upsert по sku: существующая карточка обновляется и сохраняет слаг,
   новая заводится со слагом sku в нижнем регистре.
2. `ops-apply-descriptions` — если для карточек подготовлены meta_title и
   meta_description в `data/seo/product-descriptions.json`.
3. `ops-yandex-recrawl` — переобход родительской карточки и страницы вендора.
   Номиналы в переобход не отправляются: они закрыты от индексации.
