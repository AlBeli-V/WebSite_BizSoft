# Методика отчётности BIZSoft Search Performance (v3.0.0)

## Принципы

1. Единственный источник цифр — канонический snapshot `reports/seo/intelligence/snapshots/<дата>.json`.
   В шаблонах отчёта нет вручную вписанных значений.
2. Отсутствующее значение — `null` и «нет данных». Ноль означает измеренный ноль.
3. Каждое утверждение маркируется: **ФАКТ** (видно в данных), **ИНТЕРПРЕТАЦИЯ** (объяснение),
   **ГИПОТЕЗА** (требует проверки), **РЕШЕНИЕ**, **РИСК ДАННЫХ**.
4. Критическая ошибка качества данных запрещает общий «зелёный» статус и подавляет зависящие выводы.

## Определения метрик

| Метрика | Определение | Источник |
|---|---|---|
| Показы | сколько раз страницы сайта показаны в выдаче по запросам источника. **Не** объём рыночного спроса | Вебмастер (выборка топ-100 запросов), GSC |
| Клики | переходы из выдачи по тем же запросам | Вебмастер, GSC |
| CTR | клики / показы; рассчитывается только при показах > 0 | производная |
| Средняя позиция | среднее по показам; не фиксированное место в выдаче | Вебмастер, GSC |
| «В топ-10» | средняя позиция ≤ 10 строго | производная |
| Визит | `ym:s:visits` Яндекс.Метрики | Метрика |
| Сессия | сессия GA4; не равна визиту Метрики | GA4 |
| Целевое событие | срабатывание цели Метрики (`ym:s:sumGoalReachesAny`); **не** заявка и не лид | Метрика |
| Уникальное обращение | дедуплицированное обращение одного пользователя | нет данных до DATA-001 |
| Квалифицированный лид, сделка, выручка | подтверждённые в CRM | нет данных (CRM не подключена) |

## Периоды и сравнения

- Периоды каждого источника фиксируются в snapshot: начало, конец, число дней, дата сбора,
  последняя доступная дата события.
- Относительное изменение публикуется только при равной длине периодов и предыдущем значении > 0.
- Скользящие окна (Вебмастер) пересекаются между сборами — для них публикуется абсолютное изменение
  с пометкой о пересечении, проценты не публикуются.
- При пересборе источника внутри дня каноническим считается последний сбор; факт пересмотра
  фиксируется в `data_revisions` и в отчёте.

## Округление

CTR — два знака после запятой в процентах; средняя позиция — один-два знака; абсолютные значения —
целые. Проценты изменений — один знак.

## Brand / non-brand, query / page

- Брендовым считается запрос, содержащий маркеры бренда (`bizsoft`, `биз софт`, `бизсофт`, `biz-soft`).
- Показатели по запросам и по страницам не смешиваются: средняя позиция страницы усредняется по её
  запросам, средняя позиция запроса — по его показам. Любая сводка указывает scope.

## Низкая выборка и доверие

| Порог | Значение | Следствие |
|---|---|---|
| показы | < 50 | выводы о видимости помечаются как ранний сигнал |
| визиты | < 20 | выводы о конверсии не публикуются как факт |
| конверсии | < 5 | только предварительный сигнал, обязательно указывается n |

Пороги конфигурируются в `scripts/seo/snapshot.py` (`THRESHOLDS`).

## Проверки качества данных

Выполняются до генерации текста (`scripts/seo/quality.py`), результат — sidecar
`reports/seo/intelligence/data-quality/<дата>.json`. Коды: `ROLLING_WINDOW_OVERLAP`,
`YANDEX_SAMPLE_SCOPE`, `SOURCE_RECONCILIATION` (critical), `PERIOD_MISMATCH`, `MEASUREMENT_CHANGE`,
`INTRA_DAY_REVISION`, `BASELINE_REVISED`, `LOW_CONVERSION_SAMPLE`, `GOAL_UNIQUENESS_UNKNOWN`,
`SCOPE_QUERY_VS_PAGE`, `LOW_IMPRESSION_BASE_GOOGLE`, `NO_CTR_MODEL`, `NO_CRM`,
`INDEXATION_UNCLASSIFIED`.

## Статусы вместо общего балла

Четыре независимых статуса: **видимость**, **захват трафика**, **конверсия**, **качество данных**.
Каждый сопровождается фактическим основанием. Общее предложение статуса выводится из них
автоматически. Композитный Growth Score в v2 **не рассчитывается**: его компонент
`yandex_engagement` опирался на неутверждённую CTR-модель, а сложение Яндекса и Google выполнялось
без нормализации. Историю прежних значений см. `reports/seo/intelligence/score-history.json`.

## CTR-модель

Утверждённой кривой CTR по позициям нет, поэтому «ожидаемый CTR» и «потерянные клики» не
публикуются. Построение внутренней кривой возможно при накоплении истории в разрезе:
поисковая система × позиция × устройство × brand/non-brand.

## Правила формулировок

| Запрещено | Корректно |
|---|---|
| «Яндекс наращивает доверие» | «Число страниц в индексе — 169, изменение к канонической базе: 0» |
| «HeyGen ищут 96 раз» | «Страницы получили 96 показов по запросам кластера HeyGen» |
| «Статья конвертит 60%» | «3 целевых события при 5 визитах; выборка мала, уникальность не подтверждена» |
| «Уже в топ-5» | «3 показа, средняя позиция 4,3; ранний сигнал» |
| «Правка превратит рост в деньги» | «Гипотеза: более релевантный сниппет может повысить CTR; влияние на лиды не измеряется» |
| «лучший день», «стабильно», «гарантированно», «единственное узкое место», «заявка», «спрос» | формулировки с указанием базы, периода и ограничения |

## Правила экспериментов

- Один эксперимент — одно изменение. Метаданные и контентные блоки разделяются.
- Обязательны: baseline до внедрения, контрольная группа, дата деплоя, дата появления изменения
  в выдаче, primary metric, guardrails, минимальный объём наблюдений, дата оценки, владелец.
- Вывод: **успех** (достигнута primary metric при непострадавших guardrails и достаточном объёме) ·
  **недостаточно данных** (объём ниже минимального — публикуется описательный вывод) ·
  **отрицательный результат** (метрика не достигнута или guardrail ухудшился).
- Фиксированный срок «7 дней» основанием для вывода не является.

## Executive email V3 (с 2026-08-19)

### Структура и объём
Письмо — управленческий продукт, а не выгрузка. Порядок блоков фиксирован:
заголовок и дата · итог дня (не более двух предложений) · «от вас» · четыре показателя ·
«система уже делает» · «что изменилось» · риски · следующая проверка · кнопки.
Видимый объём — 450–650 слов; alt-тексты и подвал считаются отдельно и не дублируют данные.
Полная таблица свежести заменена строкой «Данные: Яндекс/Google по DD.MM; Метрика/GA4 по DD.MM».

### Зоны ответственности и автономность
| Зона | Кто выполняет | Появляется в письме как |
|---|---|---|
| GREEN | агент автономно | «Система уже делает» |
| YELLOW | агент, руководителя информируем | «Система уже делает» |
| RED | руководитель: бюджет, юридические обязательства, цены, домены, необратимые изменения | «Требуется ваше решение» |

Владельцы GREEN и YELLOW назначаются картой ролей `reports/seo/intelligence/actions.json`;
формулировка «ответственного назначает руководитель» для них запрещена. Если RED-действий,
ожидающих решения, нет — блок «От вас» показывает «действий не требуется».

### Составной статус
Вместо одной фразы о видимости публикуются три: Яндекс (стабильно / смешанная динамика),
Google (ранний сигнал на низкой базе / без выраженной динамики) и общий вывод.

### Правило нулевой дельты
Если изменение равно нулю, в соответствующем блоке запрещены слова «вырос», «рост»,
«увеличился», «снизился», «падение». Корректная форма: «Количество страниц в поиске не изменилось — 169».
Проверяется автоматически (семантический тест и UX lint).

### Совместные внедрения
Изменения, выкаченные одной правкой, оцениваются как один эксперимент. Ретроспективное разделение
на независимые эксперименты запрещено: вклад элементов неразделим по построению.

### Визуализация в письме
Inline SVG запрещён. Графики — PNG 2x, ширина отображения 610 px, встраиваются вложениями (CID),
у каждого обязателен alt и одно предложение текстового фолбэка. Максимум два изображения.
Сквозная воронка не показывается, пока не завершена сверка источников: вместо неё «Карта измерения»
с явным разрывом сопоставимости.

### Язык письма
Технические термины (`SOURCE_RECONCILIATION`, guardrails, snapshot, `ym:s:visits`, popular queries,
rollback, stop-condition, key events) в теле письма запрещены — их место в приложении и словаре.
Идентификаторы задач допускаются как вторичная метка со ссылкой на тикет.

### Проверки письма (UX lint)
`scripts/seo/uxlint.py`: объём, число карточек показателей / изменений / действий, число изображений,
отсутствие inline SVG, размер шрифта (тело ≥14 px, метаданные ≥12.5 px), alt у изображений,
абсолютные ссылки вместо локальных путей, запрещённые термины, противоречие нулевой дельты,
запрет воронки до сверки, запрет раздельной оценки совместного внедрения, автоназначение владельцев.
