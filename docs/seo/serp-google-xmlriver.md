# Google SERP для России через xmlriver

Подключён руководителем 03.09.2026. Сервис xmlriver.com отдаёт выдачу Google
по справочнику местоположений, в котором есть Россия и её города, — то, чего
нет у DataForSEO (Google удалил геотаргетинг РФ, см.
`docs/competitive/decisions-2026-08-31.md`, раздел 4). Тариф кабинета —
**25 ₽ за 1000 вызовов** (0,025 ₽/вызов). Страница выдачи — 10 позиций,
топ-20 снимается двумя страницами: два вызова на ключ, 0,05 ₽/ключ
(решение руководителя 03.09.2026).

## Учётные данные — только в секретах

| Секрет | Значение | Где взять |
|---|---|---|
| `XMLRIVER_USER` | `user_id` кабинета (у нас — 22510) | кабинет xmlriver → «URL для запросов» |
| `XMLRIVER_KEY` | ключ API | там же |

Заводятся: GitHub → репозиторий → Settings → Secrets and variables → Actions →
New repository secret. В репозитории, конфиге и переписке ключа быть не
должно. Ключ, присланный в чат при подключении, засвечен в переписке —
после заведения секрета его стоит перевыпустить в кабинете и обновить секрет.

## Что и где

| Часть | Файл | Назначение |
|---|---|---|
| Клиент | `scripts/seo/xmlriver.py` | запрос `search/xml`, разбор Яндекс.XML-ответа (органика топ-N, блоки рекламы/видео отдельно, код 15 = пустая выдача), баланс `api/get_balance`, повторы на 5xx и сеть |
| Сборщик | `scripts/seo/serp_google.py` | срез по ядру `serp_watchlist.py`, журнал вызовов, потолки, баланс |
| Настройки | `data/seo/xmlriver.json` | местоположение, устройство, число результатов, расписание, потолки, тариф |
| Ночной прогон | `.github/workflows/seo-serp-watch.yml`, шаг `Collect Google SERP (xmlriver)` | идёт после Яндекс-среза, без секретов тихо пропускается |
| Проба | `.github/workflows/ops-xmlriver-probe.yml` | баланс + ровно один платный запрос, результат в issue #22 |
| Тесты | `scripts/seo/tests/test_xmlriver.py`, `test_serp_google.py`, `competitive-intelligence/tests/test_serp_source.py` | разбор, параметры, расписание, бюджет, чтение среза разведкой |

Выход в ветке `seo-data`:

- `reports/seo/serp/<дата>-serp-google.jsonl` — строка на запрос:
  `date, query, engine=google, region/loc, found, top[{domain,url,title}],
  blocks` или `error`. Суффикс отличается от Яндекса (`-serp.jsonl`),
  чтобы `serp_analysis.py`, `loop_health.py` и `serp_source.py` не приняли
  Google за Яндекс.
- `reports/seo/serp/ledger/google-<месяц>.jsonl` — append-only журнал: одна
  строка на каждый вызов (по нему считаются потолки и расход).
- `reports/seo/serp/xmlriver-balance.json` — остаток кабинета после прогона и
  оценка запаса в днях сбора; при запасе меньше `balance_warn_days` шаг пишет
  `::warning` в лог прогона.

## Настройки запроса (передаются в GET явно)

По странице кабинета xmlriver («Настройки», прочитана 03.09.2026): API
основано на Yandex Search API, параметры из GET имеют приоритет над
настройками кабинета, потоков на пользователя — не больше 10. Всё, что
задано в `data/seo/xmlriver.json` → `query`, уходит в каждом запросе:

| Параметр | Значение у нас | Справочник xmlriver |
|---|---|---|
| `loc` | 2643 — Россия | `files/geo.csv` (ID местоположения; для города — его ID оттуда) |
| `country` | 2643 — Россия | `files/countries.xlsx` |
| `lr` | `RU` — русский (код, не ID) | `files/langs.xlsx` |
| `device` | `desktop` | desktop / tablet / mobile |
| `page` | 0 и 1 — первая и вторая страница | параметр Yandex Search API, на котором основано API xmlriver |
| `domain` | не передаём — действует кабинет (выставлен google.ru) | `files/domains.xlsx` |

**Топ-20 — две страницы, а не параметр.** `groupby` у сервиса принимает
только 10, список «ТОП» в кабинете содержит одно значение — 10 (проверено
03.09.2026: пробы с groupby=20 вернули 10 и 9 позиций). Платная галка
«Кол-во результатов» (+10 ₽/1000) число позиций не меняет — она покупает
точное «найдено N» (в пробе с ней «Найдено» стало 160 вместо 100); галка
снята. Сборщик (`serp_google.py`) запрашивает страницы 0 и 1 (`pages` в
конфиге), склеивает их в одну строку среза; вторая страница идёт только
после удачной первой, а её сбой не стирает первую (`partial_error`).

Блоки OneBox, дополнительные параметры выдачи (локальные результаты,
Related Questions, нулевая позиция, реклама и т.п.) и фильтры кабинета мы
не включаем: сборщик берёт только органику, остальные типы блоков
считает в `blocks`.

Значения параметров печатает проба `ops-xmlriver-probe` — по ней и
сверяется местоположение.

## Расписание и потолки

- `cadence: weekly`, `weekday: 1` — раз в неделю, в ночь на понедельник по
  МСК (решение руководителя 31.08.2026: Google еженедельно по коммерческому
  ядру, Яндекс ежедневно). `daily` — каждую ночь вместе с Яндексом.
- Ручной запуск `seo-serp-watch` с main: вход `google` = `force` снимает
  Google-срез сегодня независимо от расписания, `skip` — не снимает.
- Потолки: `daily_cap` 1 100 и `monthly_cap` 15 000 **вызовов** (страниц)
  по журналу; на ключ уходит два вызова. Ядро — до 500 ключей (`core_cap`),
  один регион. При еженедельном сборе ≈ 4 000 вызовов/мес ≈ 100 ₽; при
  ежедневном месячный потолок надо поднять (≈ 30 000 вызовов ≈ 750 ₽).
- Потолки и расписание меняются только правкой конфига через PR.

## Приёмка после заведения секретов

1. Смержить ветку в `main`.
2. Actions → `ops-xmlriver-probe` → Run workflow (branch: **main**), вход
   `page` = 0 или 1. В issue #22 появится баланс, параметры запроса и
   десять позиций страницы с позицией biz-soft.pro.
   Ошибка «code=…» в ответе — дословный вердикт сервиса по ключу, балансу
   или параметрам.
3. Первый срез: `seo-serp-watch` вручную с main, вход `google=force`, либо
   дождаться ночи понедельника. Файл `<дата>-serp-google.jsonl` — в
   `seo-data`.
