# Цели сайта: что измеряем и почему именно это

Реестр — `src/lib/analytics.ts`, константа `GOALS`. Это единственный список:
из него же скрипт `scripts/seo/goals_sync.py` заводит цели в кабинетах, а тест
`tests/analytics-goals.test.ts` следит, чтобы код и реестр не разошлись.

## Зачем нужен реестр, а не просто вызовы

Цель, которую сайт шлёт, но которой нет в кабинете, летит в пустоту: счётчик
вызов принимает, а в отчёте её нет. Ноль по такой цели читается как «обращений
не было» — и именно так была потеряна конверсионная статистика (ANL-001).
Поэтому список целей заводится не руками, а из кода.

## Воронка

| Шаг | Цель | Что означает | Конверсия |
|---|---|---|---|
| Смотрит | `view_product` | открыта карточка товара | |
| | `view_vendor_landing` | открыт лендинг производителя | |
| | `view_solution` | открыта страница назначения ПО | |
| Выбирает | `add_to_cart` | товар добавлен в подборку | |
| | `remove_from_cart` | товар убран | |
| | `view_cart` | открыта подборка | |
| Оформляет | `begin_checkout` | открыта форма КП | |
| | `form_start` | начато заполнение формы заявки | |
| Обращается | `lead_sent` | отправлена заявка | ✔ |
| | `quote_pdf` | скачано КП — назвали организацию и ИНН | ✔ |
| | `click_phone` | клик по телефону | ✔ |
| | `click_email` | клик по адресу почты | ✔ |
| | `click_messenger` | переход в мессенджер | ✔ |

Каждый шаг — знаменатель следующего. «Добавили в подборку три раза» само по
себе не значит ничего: три из пяти просмотров и три из пятисот — разные вещи.

## Отдельно: спрос, которого у нас нет

| Цель | Что означает |
|---|---|
| `search_used` | воспользовались поиском по каталогу |
| `search_no_results` | поиск не дал результатов |

Поиск — единственное место, где посетитель прямо называет, что ему нужно.
Пустая выдача дороже любого замера частотности: это спрос, который дошёл до
нас и ушёл ни с чем. Отчёты по `search_no_results` идут прямо в работу по
расширению каталога.

## Отдельно: тихие потери

| Цель | Что означает |
|---|---|
| `lead_error` | заявка не отправилась из-за ошибки |
| `quote_error` | КП не сформировалось из-за ошибки |

Без них сбой формы неотличим от того, что клиент передумал: в отчёте и то и
другое выглядит как незавершённое оформление.

## Симметрия Метрики и GA4

Событие в коде одно, имя в каждой системе своё. В Метрику уходит наше имя, в
GA4 — рекомендованное, если такое есть: под стандартные имена GA4 сам строит
отчёты по воронке покупки и поиску.

| Наше | GA4 |
|---|---|
| `lead_sent`, `quote_pdf` | `generate_lead` |
| `click_phone`, `click_email`, `click_messenger` | `contact` |
| `view_product` | `view_item` |
| `view_vendor_landing`, `view_solution` | `view_item_list` |
| `add_to_cart`, `remove_from_cart`, `view_cart`, `begin_checkout` | те же |
| `search_used` | `search` |
| `lead_error`, `quote_error` | `form_error` |

Несколько наших целей отображаются в одно имя GA4. Чтобы они не слились в одно
число, наше имя уходит параметром `bz_goal`: в GA4 заявка с формы и скачивание
КП различаются по нему.

## Как завести цели в кабинетах

Actions → **seo-goals-sync** → Run workflow.

- `apply = false` (по умолчанию) — показывает, чего не хватает, ничего не меняя.
- `apply = true` — заводит недостающее.

Ничего не удаляет: лишняя цель в кабинете безвредна, а снятая по ошибке
обнуляет историю. Результат — комментарий в журнал-issue #22.

Если доступа к кабинету нет, прогон завершается ошибкой и так и пишет — «не
проверено». Это не то же самое, что «всё заведено», и складывать их в одно
нельзя: молчаливый ноль здесь уже стоил месяца конверсий.

## Состояние на 21.08.2026: Метрика упирается в права токена

GA4 закрыт — ключевое событие `contact` заведено, всего их шесть.

В Метрике не заведено ни одной цели по событиям, и прогон с `apply` вернул
`403 access_denied` на все восемнадцать. Токен счётчик **читает** (список
целей приходит), но **редактировать** его не может.

Это не ошибка скрипта и не недоделанный код сайта: вызовы целей лежат в
клиентских чанках, идентификатор счётчика не схлопнут в `void 0`, и на живой
карточке товара чанк целей доезжает до браузера — всё это проверяется в CI и
смоуке на каждом прогоне.

Что нужно, чтобы разблокировать: у приложения, которым выпущен
`YANDEX_METRIKA_TOKEN`, должно быть право `metrika:write`, либо пользователю,
от чьего имени выпущен токен, нужен доступ на **редактирование** счётчика
(не «только просмотр»). После этого хватит одного запуска с `apply = true` —
руками в кабинете заводить ничего не надо.

Пока прав нет, ноль по этим целям в отчётах помечается как «не измерялось»
(запись ANL-001 в `reports/seo/measurement-limits.json`), а фактическая
история обращений берётся из воронки заявок и скачиваний КП.
