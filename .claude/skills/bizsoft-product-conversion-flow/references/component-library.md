# Блоки карточки

Визуальные правила композиции, маркеров, подачи цены и подвала — в
`design-system.md`; здесь — какие компоненты берутся и при каких условиях
блоки появляются.

## Композиция

```
крошки: Главная → Каталог → Иностранное ПО → Производитель → позиция
  ↓ первый экран: значок, H1, оффер одной фразой, цена, главный призыв
  ↓ что входит — состав подписки читают до маркетингового текста
  ↓ описание
  ↓ характеристики · для кого · какие задачи закрывает
  ↓ цена и расчёт количества (карточка покупки: справа на широком экране)
  ↓ как проходит сделка: Оплата · Поставка · Документы
  ↓ вопросы и ответы
  ↓ похожие товары · статьи · связанные разделы
  ↓ липкая полоса призыва (узкий экран)
```

## Условия появления

| Блок | Появляется |
|---|---|
| Первый экран с ценой | всегда, кроме подарочной карты — у неё свой селектор региона и номинала |
| Счётчик и «сколько выйдет на команду» | цена есть; ступени выше минимума заказа |
| Оговорка тарифа | заведена в `VendorCardMeta.check` |
| Сделка в три колонки | обычный товар; у подарочной карты свой порядок активации |
| Липкая полоса | узкий экран **и** призыв первого экрана ушёл из виду |
| Переключатель редакций | только при подтверждённой данными связи позиций — сегодня её нет |
| Конфигуратор | только при обязательных компонентах — таких позиций в каталоге нет |
| Блок сравнения с соседом | только при подтверждённом содержательном отличии; «потому что тип требует» — не причина |

## Липкая полоса

Появляется по уходу призыва первого экрана из поля зрения, а не «после
N-го блока»: пока первый призыв на экране, вторая такая же кнопка только
спорит с ним. Механика — `IntersectionObserver` на `[data-hero-cta]`,
`buyBar.hidden = e.isIntersecting`. Без поддержки наблюдателя полоса просто
не показывается.

На широком экране полосы нет: там призыв держит липкая карточка покупки
(`.product-aside { position: sticky }`). Один и тот же призыв двумя
способами на одном экране не показывается.

Контрольный размер — 390 × 844: название, цена и главный призыв доступны до
первой значимой прокрутки. «Совсем без прокрутки» не обещаем: разброс
устройств этого не даёт.

## Иерархия контента

```
Глобальное → Вендор → Линейка → Позиция
```

Нижний уровень **переопределяет** то, что отличается, а не копирует всё
целиком. Порядок источников уже реализован в мете карточки: состав и «кому
адресовано» берутся из `VendorCardMeta`, если заданы, иначе из каталога.

Оплата, ЭДО, договор, закрывающие документы — уровень **глобальный**, не
вендорский и не линейки: «счёт в рублях» не специфичен даже для
производителя. Их формулировки живут в `src/data/policies.ts`; на странице
они не сочиняются.

Перед тем как выносить текст страницы в переиспользуемый компонент, читать
`seo-impact.md`: компонент во фронтенде не равен дедупликации для поисковика.

## Что переиспользуется

| Нужно | Берём |
|---|---|
| Счётчик количества на карточке тарифа | `src/components/TariffQty.astro` |
| Перенос выбора в заявку, состав расчёта | `src/components/VendorQuotePath.astro` |
| Кнопка подборки | `src/components/AddToCartButton.astro` |
| Модальное окно заявки | `src/components/QuestionForm.astro` |
| Инлайн-форма, в том числе двухшаговая | `src/components/LeadForm.astro` |
| Цена с акцией | `src/components/PriceTag.astro` |
| Коммерческая модель, подписи призыва | `src/lib/product-commerce.ts` |
| Подборка нескольких позиций в одно КП | `src/lib/cart-client.ts`, `/cart` — см. `quote-collection.md` |

Своих счётчиков, своих форм и второй кнопки подборки не заводится: каждая
копия — вторая валидация, вторая защита от спама и вторая цель, которые
разойдутся с первыми.
