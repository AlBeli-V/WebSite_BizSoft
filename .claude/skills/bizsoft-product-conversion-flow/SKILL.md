# Карточка товара под конверсию

Методика Product Conversion Flow, приложенная к шаблону
`src/pages/product/[slug].astro`. Правится **шаблон**, а не страница: карточек
в каталоге около двух тысяч, и одна поправленная — это симптом, а не работа.

Карта кода — `docs/INDEX.md`, правила проекта — `CLAUDE.md` и `docs/rules/`.
Страница производителя — отдельный навык `vendor-page-rebuild`, он про
`/vendors/<slug>`; здесь только карточка товара.

## Принцип 0 — Data Before UI

Интерфейс не угадывает коммерческую модель товара по слагу, названию,
вендору или числу соседей. Конструкций вида `if (slug.includes('team'))` или
`if (vendor === 'maxon')` в реализации не бывает.

Не хватает структурированных данных для интерфейсного решения — **не
подставляй предположение**. Запиши это как DATA GAP: какого поля нет, какой у
него должен быть тип, что без него нельзя сделать, — и продолжай остальную
работу. Схему данных навык не меняет: расширение схемы каталога заводится
отдельным решением руководителя и отдельным прогоном (`ops-directus-schema`).

Молчаливое допущение хуже отсутствующего блока. «Минимум заказа не объявлен,
значит единица» — это допущение; оно уже стоило карточкам Anthropic и OpenAI
показа цены одного места там, где тариф продаётся от двух.

## Шесть принципов

1. **Conversion First.** Первый экран отвечает на «что это», «сколько стоит»,
   «что нажать». Остальное ниже.
2. **Product Complexity Adaptive.** Состав блоков задаёт сложность товара, а
   не шаблонная полнота: конфигуратор появляется там, где есть что
   конфигурировать.
3. **SEO Intent Preservation as Baseline.** Владение поисковым интентом между
   соседними карточками не перераспределяется походя.
4. **Transparent & Invariant Pricing.** Показанная цена — наименьшая сумма
   валидного заказа.
5. **Deterministic CTA.** Подпись призыва считается по таблице от модели цены
   и доступности, а не подбирается на слух.
6. **Data Before UI.** См. выше.

## Порядок работы

1. **Аудит.** Найти шаблон карточки, источник данных позиции и её фактические
   поля. По каждому полю из списка в `references/classification.md` отметить
   «есть» или «отсутствует». Смотреть в код и данные, не по памяти.
2. **DATA GAP.** Выписать то, чего в данных нет, до того как писать разметку.
3. **Классификация.** Три оси — роль позиции, модель цены, коммерческая
   доступность. Гипотеза проверяется по полям; не подтвердилась данными —
   становится DATA GAP, а не хардкодом. См. `references/classification.md`.
4. **Макет в вариантах.** Композиция показывается руководителю вариантами с
   визой по каждому (правило `docs/rules/decisions-buttons.md`) до правки
   кода. Решение записывается в тексте задачи и в комментарии к коду.
5. **UX SAFE patch.** Делается сразу после согласования композиции. Что в него
   входит и что в него не входит — `references/seo-impact.md`.
6. **SEO-STRUCTURAL IMPACT proposal.** Отдельным блоком и отдельным диффом,
   не применяется без решения руководителя.
7. **Результат без автокоммита.** Показать дифф обеих частей, прогон приёмки
   и список DATA GAP. Коммит — по команде.

## Когда что читать

| Ситуация | Файл |
|---|---|
| Классифицирую позицию, ищу связь редакций, веду список DATA GAP | `references/classification.md` |
| Трогаю цену, счётчик, минимум заказа, НДС, курс | `references/pricing.md` |
| Пишу подпись кнопки, меняю статус доступности | `references/cta-rules.md` |
| Решаю, безопасна ли правка, или она про поиск | `references/seo-impact.md` |
| Ставлю или правлю цели, считаю воронку карточки | `references/analytics.md` |
| Собираю блоки страницы, наследую контент, делаю переключатель редакций | `references/component-library.md` |

## Чек-лист завершения

- [ ] Ни одно интерфейсное решение не выведено из слага, названия или вендора.
- [ ] Показанная цена — сумма минимального валидного заказа; счётчик не
      опускается ниже минимума.
- [ ] Подпись призыва совпадает с таблицей `references/cta-rules.md` и
      пересчитывается при смене количества.
- [ ] Выбор количества уезжает в заявку полем `product_ref`, а не
      пересказывается покупателем.
- [ ] На 390 × 844 название, цена и главный призыв доступны до первой
      значимой прокрутки; второй такой же призыв не показывается, пока виден
      первый.
- [ ] Новых имён целей без решения руководителя не появилось; заведённые цели
      не задвоены.
- [ ] Поля с персональными данными несут `ym-disable-keys`.
- [ ] Canonical, H1, title, микроразметка, состав крошек и внутренние ссылки
      между соседними позициями — либо не тронуты, либо вынесены в отдельное
      предложение.
- [ ] Прогон: `pnpm test`, `pnpm typecheck`, `pnpm build`, `pnpm smoke`,
      `pnpm check:mobile`. Последняя в сессии запускается с
      `LAYOUT_CHROMIUM=/opt/pw-browsers/chromium-*/chrome-linux/chrome`, если
      пакет браузеров Playwright не совпал с версией пакета.
- [ ] DATA GAP выписаны отдельным списком и не закрыты догадкой.
