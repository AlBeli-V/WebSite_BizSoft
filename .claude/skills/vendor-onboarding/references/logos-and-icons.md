# Логотипы и иконки

Графика приходит из четырёх независимых каналов. Они не взаимозаменяемы: у каждого
свой путь, свой кэш и своё место в приоритете. Если «логотип не появился» — почти
всегда сработал более приоритетный канал, а не пропал файл.

---

## Четыре канала

| # | Канал | Где лежит | Кэш |
|---|---|---|---|
| 1 | Пакет иконок вендора | `src/assets/vendor-icons/{color,mono}/<pack-slug>.svg` | `/_astro`, хеш, год immutable |
| 2 | Брендовый файл-логотип | `public/brand-logos/<slug>.svg` | `max-age=0` |
| 3 | Пакет иконок товара | `src/assets/product-icons/…` | `/_astro`, хеш, год immutable |
| 4 | Изображение товара в Directus | поле `products.image` | через `/assets/` Directus |

Каналы 1 и 3 идут через ассет-пайплайн Vite и получают хешированные имена с годовым
кэшем. Канал 2 лежит в `public/` и отдаётся с `max-age=0`. **При прочих равных выбирай
канал 1 или 3.**

### Канал 1 — пакет иконок вендора

- Файлы: `src/assets/vendor-icons/color/<slug>.svg` и `.../mono/<slug>.svg`.
- Холст **512×512, прозрачный фон**.
- Реестр читается автоматически через `import.meta.glob` — ручного списка вести
  не нужно, достаточно положить пару файлов.
- **Пара обязана быть полной.** Есть только `color` или только `mono` —
  `vendorIcon()` вернёт `null`, и канал выпадет целиком.
- Слаг сайта не совпал со слагом пакета — алиас в `ALIAS` внутри
  `src/data/vendor-icons.ts`.
- Источник и права — строка в `docs/vendor-icons-manifest.json`.

### Канал 2 — `public/brand-logos/`

Генератор `scripts/build-logos.mjs`, выход `src/data/logos.ts`
(**автогенерируемый, руками не править**).

Три уровня внутри канала:

1. **Официальный файл правообладателя.** Кладёшь `public/brand-logos/<slug>.svg`
   (принимаются `.png`, `.webp`). Скрипт копирует его под SEO-именем
   `<slug>-logo.<ext>` и вносит слаг в `FILE_LOGOS`. Высший приоритет.
2. **Глиф simple-icons.** Своего файла нет — скрипт ищет иконку по названию вендора.
   Найденное попадает в `LOGOS` и выгружается файлом с фирменным цветом; слишком
   светлые знаки затемняются до `#1d1d1f`, иначе теряются на белой карточке.
3. **Монограмма.** Ни файла, ни глифа — генерируется скруглённый квадрат в фирменном
   цвете с белой литерой.

Файлы с суффиксом `-logo` в имени скрипт **игнорирует как исходники** — это его
собственный выход. Клади `acme.svg`, а не `acme-logo.svg`.

### Канал 3 — пакет иконок товара

- **Прямой по слагу:** `src/assets/product-icons/{color,mono}/<product-slug>.svg`.
- **Каталожный по идентификатору:**
  `src/assets/product-icons/catalog/{color,mono}/<icon_id>.svg` плюс строка
  `"<product-slug>": "<icon_id>"` в `src/data/product-icon-map.json`. Один комплект
  файлов намеренно переиспользуется несколькими карточками одного семейства.
- **Составные позиции** — `COMPOSITE` в `src/data/product-icons.ts`: один слаг
  рисует несколько значков в ряд (тариф «Фотография» = Lightroom + Photoshop).

Порядок разрешения: прямой пакет по слагу → `COMPOSITE` → каталожный пакет → пусто.

## Приоритеты рендера

`VendorLogo.astro`, сверху вниз, первый сработавший выигрывает:

1. `vendorIcon(slug)` — пакет, монохром с переходом в цвет при наведении
2. `hasFileLogo(slug)` — `/brand-logos/<slug>.svg`
3. `brandLogo(slug)` — встроенный глиф `<svg>` с `currentColor`
4. `logoFile(slug)` — `/brand-logos/<slug>-logo.svg`
5. буквенный знак

`ProductCard.astro`:

1. своя иконка товара — `ProductIcon` 34px
2. иначе иконка вендора — `VendorIcon` 34px
3. иначе изображение из Directus — 40px

## Где появится

| Поверхность | Что и какой размер |
|---|---|
| Шапка, меню «Производители» | цветная иконка пакета либо `logoFile` |
| Главная — витрина товаров | ProductIcon 30 → VendorIcon 30 |
| Главная — плитки брендов | VendorIcon 64, сразу цветные |
| `/catalog` — бейдж бренда | VendorLogo 24 |
| `/vendors` — плитка | VendorIcon 56 |
| `/vendors/<slug>` шаблонный | VendorLogo 44, ProductIcon 38 в карточках |
| `/vendors/<slug>` базовый | VendorIcon 44 |
| Карточка товара, заголовок | ProductIcon 44, цветная |
| Любая плитка товара | 34 или 40 |

Проверять надо все затронутые поверхности, а не одну.

## Порядок при заведении вендора

1. Слаг зафиксирован (после этого имена файлов не меняются).
2. Пара иконок пакета 512×512 либо `public/brand-logos/<slug>.svg`.
3. Алиас, если слаг пакета иной.
4. `node scripts/build-logos.mjs` — запускать всегда, даже если положил только
   пакетную иконку: скрипт заведёт запасную монограмму.
5. Строка в `docs/vendor-icons-manifest.json`.
6. Проверки и скриншот.

## Порядок при заведении товара

1. Слаг товара финализирован. **Переименование задним числом рвёт связь
   в `product-icon-map.json` без единого предупреждения.**
2. Своей иконки нет — **ничего не делать**: карточка возьмёт иконку вендора.
   Это штатное состояние, а не пробел.
3. Иконка нужна — файл в прямой или каталожный пакет, при каталожном ещё строка
   в карте.
4. Строка в манифесте иконок товаров.

## Грабли

- **Логотип не появился, ошибок нет.** Сверь `products.vendor` с `VENDORS[].vendor`
  побуквенно.
- **Иконка есть, но цвет не включается.** Не хватает одной половины пары.
- **Положил файл, рендерится старое.** Сработал более приоритетный канал.
- **Файл в `brand-logos` игнорируется.** В имени суффикс `-logo`.
- **Подрезанная иконка.** Лечится разметкой, а не файлом: оба слоя абсолютные внутри
  `.vi` с явным размером на контейнере. Глобальное `img { height: auto }` и дробный
  масштаб экрана иначе подрезают один из слоёв.
- **Знак не читается на белом.** Генератор затемняет только глифы simple-icons; свой
  светлый SVG нужно готовить самому.
- **Только текстовое начертание** без графической марки плохо смотрится в квадратной
  плитке 512×512 — такой знак нужно перерисовывать, а не масштабировать.
