# Выкатка, импорт, приёмка, откат

Всё, что происходит после того, как партия собрана в репозитории. Здесь начинаются
необратимые действия, поэтому порядок важнее скорости.

---

## Порядок и почему он такой

```
merge в main → автодеплой витрины → импорт в Directus → проверки → индексация
```

**Витрина раньше данных.** Воркфлоу `ops-import-vendors` собирает xlsx из
`scripts/catalog/*.json` **своего checkout'а**. Пакета нет в `main` — импортировать
нечего. Плюс к моменту появления товаров страница вендора уже должна быть полной,
иначе покупатель попадёт на пустой лендинг.

Перед запуском убедись, что запуск production-workflow с произвольной ветки не
запрещён: такое ограничение в репозиторий вводили, и обходной путь через `ref=<branch>`
мог закрыться.

---

## Деплой

`deploy.yml` срабатывает на push в `main` и по ручному запуску. Пуш в рабочую ветку
деплой не запускает.

1. Коммит: что сделано и **почему**, а не перечень файлов.
2. `git push -u origin <branch>` — при сетевой ошибке повтор с задержкой 2, 4, 8, 16 с.
3. PR → дождаться CI → squash-merge.
4. Проверить, что `deploy` для нового коммита `main` завершился успехом.

---

## Импорт в Directus

Воркфлоу `ops-import-vendors`, upsert по `sku`, **ничего не удаляет**.

**Шаг 1 — `apply=false`.** Читай в отчёте:

- `rows` — сколько строк собрано из пакетов;
- `create` / `update` — что изменится;
- **`errors`** — любой ненулевой останавливает работу.

Самая частая причина ошибок: категории нет в Directus. Резолвер ищет раздел по слагу
или названию, не нашёл — строка не применяется.

Сверь несколько рублёвых цен из dry-run с ожиданием:
`base_price_usd × курс ЦБ × markup_coeff`. Расхождение — разбираться, а не применять.

**Шаг 2 — `apply=true`.** Проверь `created / updated / failed`. Импорт сам обновляет
курс ЦБ перед применением, поэтому цены считаются сразу.

## Приёмка на проде

Прямого доступа к сайту из сессии нет. Проверка — воркфлоу `ops-probe`
(вход: URL и шаблон для `grep -oE`), результат комментарием в журнал-issue #22.

| Проверка | Ожидание |
|---|---|
| `/vendors/<slug>` | 200, логотип на месте, плитки товаров есть |
| `/product/<slug>` | 200, рублёвая цена есть |
| `/vendors` | вендор в списке |
| `/catalog` | счётчик раздела вырос |
| `ops-vendors-audit` | вендора нет в списке «без логотипа» |

**В шаблоне grep не используй кириллические диапазоны** `[а-я]`: у раннера C-локаль,
и такой шаблон падает с `Invalid collation character`. Перечисляй альтернативы
через `|`.

Полезные шаблоны:

- логотип из пакета: `_astro/<slug>[a-zA-Z0-9._-]*\.svg`
- запасной брендовый файл: `brand-logos/<slug>-logo\.svg`
- редирект: `HTTP|location`

## Индексация

1. Вендоры и товары попадают в `/sitemap.xml` из базы автоматически — проверь, что
   попали. Товары со статусом `draft` и позиции, помеченные `noindex`, туда не идут
   и переобхода не требуют.
2. `ops-yandex-recrawl` — новые URL через запятую, полные `https`. Квота 150 URL/сутки,
   результат в issue #22.
3. Bespoke-страницы, если создавались, — вручную в `STATIC_ROUTES`
   (`src/pages/sitemap.xml.ts`).

## Откат

Порядок обратный выкатке. Сначала данные, потом витрина — иначе на сайте останутся
страницы, ссылающиеся на снятые позиции.

| Что откатывать | Как |
|---|---|
| Карточки товаров | архивные стабы `{sku, archive: true}` через штатный импорт: позиции уходят в `archived`, ничего не удаляется |
| Категория, заведённая под партию | смена статуса на `archived` через `ops-categories`; товары предварительно перенести |
| Витрина и код | `git revert` коммита слияния → автодеплой |
| Цены | правка `base_price_usd` в пакете и повторный импорт; переоценка пересчитает рубли сама |

Позиции, опубликованные до партии, откат трогать не должен — их адреса уже
проиндексированы, и 404 на них дороже, чем незавершённый откат.

## Отчёт

`reports/vendors/<партия>-<дата>.md` плюс короткая сводка в чат:

- изменённые файлы и новые записи `VENDORS`;
- заведённые SKU с ценами, источниками и датами проверки;
- **что поправил владелец** — было → стало по каждой правке;
- **принятые решения по спорным вопросам** с датой;
- отклонённые позиции с причинами;
- результаты тестов, импорта и проверок на проде;
- что осталось человеку.

Отчёт нужен не для отчётности. Через месяц при пересмотре цен единственный способ
понять, почему у позиции стоит именно эта цифра, — прочитать, откуда она взялась
и кто её подтвердил.
